  <action>
    Create `.planning/phases/13-overlay-shell/13-MANUAL-VERIFICATION.md` as an ordered, one-sitting
    checklist. Structure it as one section per roadmap success criterion, each with numbered steps,
    the exact expected observation, and a result line the author fills in (`PASS` / `FAIL` + notes):

    1. **Success criterion 1 — visible on top of the game.** Set PoE2 to windowed-fullscreen; enter a
       town or map so the game holds focus; launch `ff` from the repo root; confirm the stripe is
       drawn over the game, opaque, with the game visible around it. Include the note that exclusive
       fullscreen will not work and is not detected (D-21, `PITFALLS.md` §2) — if the stripe is
       invisible, check the display mode first.
    2. **Success criterion 2 — hotkey toggles while the game holds focus.** With the character
       standing in a safe spot and the game focused, press `Shift+Z` to hide, `Shift+Z` to summon,
       and again — at least three summons, because a single summon would miss the winit
       `MARKER_ACTIVATE` defect (RESEARCH Pitfall 1). Between summons, press a movement key and
       confirm the character still responds (D-05). Then click into the stripe, confirm it takes
       focus, click back onto the game, and confirm the stripe hides (D-06). Note D-09's accepted
       trade: `Shift+Z` is captured system-wide, so it will also fire from the game's chat box.
    3. **Success criterion 3 — opaque, non-passthrough, sub-screen.** Confirm the stripe's background
       is fully opaque; click inside it and confirm the click does **not** reach the game underneath;
       confirm the stripe is visibly smaller than the screen on all four sides.
    4. **Success criterion 4 — the game is unaffected.** Hide the stripe, play normally for a minute,
       tray → Quit, and confirm the game continues unaffected. Record that the overlay reads no game
       memory, injects no input and installs no global input hook (D-22) — the only OS calls it makes
       are on its own window plus one `RegisterHotKey`. Per `PITFALLS.md` §3 no disclaimer goes into
       the product; this line lives in the verification record.
    5. **Success criterion 5 — no binary named `overlay`.** `ls target/debug/*.exe` and the
       `Cargo.toml` `[[bin]]` table both show `ff`, `ff-cli`, `ferrisfilter`, `seed_prices` and no
       `overlay` (egui #5512).

    Add a short "If something fails" section: which plan owns each behavior (13-01 window shape,
    13-02 tray/hotkey delivery, 13-03 focus mechanism, 13-04 content/theme), so a failure routes to
    the right code without re-diagnosing from scratch.

    Update `CLAUDE.md`: add the overlay to the repository-layout table (`ff` opens the stripe;
    `dynamic.json` is what it displays read-only this milestone) and add a short "Overlay" note
    stating the game must run in **windowed or windowed-fullscreen** — exclusive fullscreen prevents
    any overlay from drawing and the tool does not detect it (D-21) — plus the `Shift+Z` toggle and
    that the tray's Quit is the only exit while `✕` merely hides (D-14, D-17). Keep it to the file's
    existing terse table-and-note style; do not restructure the document.

    Update `CHANGELOG.md`'s `[Unreleased]` section with the overlay shell entries (new `ff` GUI
    binary and `ff-cli` console binary, tray icon, `Shift+Z` toggle, read-only rule list).
