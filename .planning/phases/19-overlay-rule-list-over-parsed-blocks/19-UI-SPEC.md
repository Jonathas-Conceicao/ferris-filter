# Phase 19 — UI Design Contract

> Visual and interaction contract for the overlay rule list over parsed blocks. Native Rust eframe/egui 0.36 stripe, not a web app. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> Autonomous run: every item marked "Decided on user's behalf" was chosen without user input, consistent with 19-CONTEXT.md and the v0.4 overlay code. Phases 13/14/15 produced no UI-SPEC files, so tokens are taken from `src/overlay/theme.rs`, `widgets.rs`, `rule_editor.rs`, `apply.rs` and `app.rs`.
>
> **Correction to the brief:** the overlay chrome uses the PoE2-style warm-grey palette in `theme.rs` (D-24/D-25), NOT the Dracula palette. Dracula belongs to generated filter output and is kept separate on purpose. This spec reuses the `theme.rs` constants only.

## Design System

| Property | Value |
|----------|-------|
| Tool | none (egui immediate-mode; `theme::poe2_visuals()` applies the palette) |
| Preset | not applicable |
| Component library | egui 0.36 built-ins + `src/overlay/widgets.rs` (`header_plate`, `zebra_row`, `circular_toggle`, `arrow_button`) |
| Icon library | none; plain-English text labels. Arrows and the toggle are painted shapes in `widgets.rs` |
| Font | Cinzel (`theme::DISPLAY_FONT`) for the header plate and section headers; egui default proportional for body, values and controls |
| Window | fixed `STRIPE_WIDTH` 460px, docked right, `EDGE_MARGIN` 12px; must never resize horizontally (v0.4 D-01) |

## Spacing Scale

The stripe is dense. Values are multiples of 4, as used in v0.4 code.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Gap between row flag badges, gap between status lines |
| sm | 8px | Gap between controls inside an expanded row (v0.4 `add_space(8.0)`), search box vertical margin |
| md | 16px | Gap between the list and the footer block |
| lg | 24px | not used in this phase |
| xl | 32px | not used in this phase |
| 2xl | 48px | not used in this phase |
| 3xl | 64px | not used in this phase |

Exceptions: row height is `ui.spacing().interact_size.y` (egui default, about 18-20px) for the collapsed header row. This is required for `show_rows` virtualization, which needs a fixed row height. Existing v0.4 inset `add_space(10.0)` on status text is retained as is (inherited, not new).

**Virtualization contract (Decided on user's behalf):**
- Collapsed rows have one fixed height (`row_h = interact_size.y + 4`), so `ScrollArea::show_rows` can be used.
- At most ONE row is expanded at a time (accordion, as in v0.4).
- The expanded row has variable height and breaks `show_rows` arithmetic. Implement the list as `show_viewport` with a cached cumulative-offset table: collapsed rows use `row_h`, the single expanded row uses its measured height from the previous frame. Only rows intersecting the viewport are laid out.
- Row summaries (derived label, condition summary, search haystack) are cached per rule when the parsed filter loads or a rule mutates, never computed per frame.
- Target: smooth scrolling at about 460 rules (EDIT-07), with per-frame work proportional to visible rows, not total rows.

## Typography

Only existing v0.4 sizes. No new sizes introduced.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body (values, buttons, search input, status text) | 14px | Regular | egui default (about 1.4) |
| Label (field captions such as NAME/STYLE, `.small()`) | 11px (egui `.small()`) | Regular, LABEL_TAN | egui default |
| Row summary (derived label, flag text) | 13px (`ROW_SUMMARY_SIZE`) | Regular, TAB_ACTIVE | egui default |
| Heading (Cinzel header plate, section header `FILTER`) | 17-18px | Cinzel (single face) | egui default |

Weights: exactly two. Regular for everything, plus the Cinzel face as the heading weight. No bold/italic is introduced. Emphasis comes from colour and the flag text, not weight.

## Color

Palette is the existing `theme.rs` table. Nothing new is added except the "warning" role, which reuses `WARM_ACCENT`.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `PANEL_GROUND` #141414, `ROW_BASE` #0D0D0D / `ROW_ALT` #121212 | Panel ground, zebra rows |
| Secondary (30%) | `HEADER_PLATE` #3B3326, `INPUT_FILL` #090909, `LABEL_TAN` #E3CD97, `SECTION_CREAM` #F1E4C2, `TAB_ACTIVE` #B3AF93, `CONTROL_GLYPH` #C4C4A8, `BUTTON_TEXT` #DEDEDE, `VALUE_TEXT` #FEFEFE | Header plate, search input, captions, summaries, control glyphs |
| Accent (10%) | `WARM_ACCENT` #A36C3C | See reserved list |
| Destructive | `WARM_ACCENT` #A36C3C | Delete confirm button, Remove-economy confirm. Same colour as the accent, as in v0.4 (one warm red-bronze for "attention or destructive") |
| Disabled | `DISABLED_TEXT` #88856E | Disabled rule rows (text of header), invalid-can't-enable reason |

Accent reserved for (explicit list):
1. Delete / Remove confirm buttons (rule delete, economy section Remove).
2. Row flag text for error states: "grammar error", "invalid, can't enable".
3. The Continue-crossing warning indicator after a reorder.
4. Failure lines in the status block (Apply refused: changed on disk, damaged markers, invalid enabled block).
Not used for: normal buttons, selected tabs, the style-wins note, ordinary status text.

**Show/Hide/Minimal selector colouring (Decided on user's behalf):** no per-disposition colours. The selected option is `SECTION_CREAM` text on `HEADER_PLATE` fill; unselected is `LABEL_TAN` on `ROW_BASE`. Do not mimic the Dracula tier colours in the chrome.

**State encoding must survive monochrome**: every colour signal has a text twin (flag words below), per the v0.4 `indicator` convention.

## Layout

Top to bottom inside the stripe (all within existing scaffolding in `app.rs`):

1. Header plate `FERRISFILTER` with close (hide) control. Unchanged.
2. Status block (root, filter path, filter state, stale indicator, last Apply outcome). Unchanged structure. The stale "Rule editing returns in the next update" notice line is REMOVED in this phase.
3. Section header `FILTER` (Cinzel) with the rule count on the same line, right-aligned, e.g. `142 rules`; when searching, `7 of 142 rules`.
4. Search box (full width, hint `Search rules, classes, base types…`) plus a `Clear` small button visible only when the box is non-empty. Esc while focused clears.
5. Scrolling rule list (virtualized, flat). Takes all remaining height above the footer.
6. Economy footer row, pinned directly under the list (outside the scroll area, so it never scrolls away).
7. Action row: `+ ADD RULE` (left), then `REVERT`, `APPLY`, plus the existing `RELOAD` / `SYNC ECONOMY` / `ADD ECONOMY SECTION` buttons per `apply::footer_actions`.

**Search behaviour (Decided on user's behalf):**
- Case-insensitive substring match, over `#ff:name`, derived label, and each Class / BaseType value. Foreign header text is not searched.
- Filtering is applied to the visible list only; rule indices shown in labels remain the real positions in the file.
- While a filter is active, reorder arrows are disabled (an index-shifting move inside a filtered view is ambiguous). Tooltip on disabled arrows: `Clear the search to reorder`. Other row actions (toggle, expand, delete, duplicate) stay live.
- Add rule while searching clears nothing; the new rule appends at the end of the real list and the list scrolls to it only if it matches (otherwise a status line says `Rule added at position N (hidden by the current search)`).
- Zero matches: empty state below.

## Rule row anatomy

Collapsed row (one line, fixed height, zebra background via `zebra_row`):

`[toggle]  [label ..................]  [flags]  [up] [down]`

| Element | Contract |
|---------|----------|
| Enable toggle | `widgets::circular_toggle`. Filled = enabled. Tooltip: `Enabled` / `Disabled`. |
| Label | Named rule: `<index>  <Disposition> - <name>` (v0.4 `<index>  <style> - <name>` shape). Unnamed: derived label `<index>  <Disposition> · <Class summary> · BaseType ×N` e.g. `12  Show · Currency · BaseType ×14`. Use middle dot separators; omit parts that do not exist. A rule with no conditions at all: `<index>  <Disposition> · matches everything`. Single line, truncated with ellipsis (`Label::truncate`), full text in hover tooltip. Class summary: first class name, then `+N more` if several (`Rings +2 more`). |
| Label colour | Enabled: `TAB_ACTIVE` (row summary rule). Disabled: `DISABLED_TEXT`. Expanded row header: `SECTION_CREAM`. |
| Flags | Short text badges, right of the label, `ROW_SUMMARY_SIZE`, separated by 4px. Order fixed: `Continue`, `style wins`, `grammar error`, `can't enable`. Only those that apply. Colours below. |
| Arrows | `widgets::arrow_button` up/down. Up disabled on first rule, down disabled on the last rule (never moves into or past the economy section). |

Expansion: click the label area to expand or collapse in place (accordion, one at a time, as v0.4). Toggle and arrows do not expand.

**Flags (Decided on user's behalf):**

| Flag text | Shown when | Colour | Tooltip |
|-----------|-----------|--------|---------|
| `Continue` | block has Continue | `LABEL_TAN` | `Matching goes on to the rules below` |
| `style wins` | rule carries a style tag, so its action is set by the style on Apply (Phase 17) | `LABEL_TAN` | `Style "<tag>" sets this rule's Show/Hide on Apply` |
| `grammar error` | enabled block with a Phase 16 grammar error | `WARM_ACCENT` | the parser message, e.g. `Line 3: unknown condition "Clas"` |
| `can't enable` | disabled block whose commented lines are not valid grammar | `WARM_ACCENT` | `These lines are not valid filter grammar, so this rule cannot be turned on. You can still move or delete it.` |

Disabled rule rows additionally render the label in `DISABLED_TEXT`. A disabled rule shows no `Continue`/`style wins` flags unless valid (flags only describe parsed validity; a disabled invalid rule shows only `can't enable`).

**Style-action-wins indicator in the expanded body:** next to the Show/Hide/Minimal selector, when the rule has a style tag, the selector is shown but disabled-looking (`DISABLED_TEXT`) with the inline note below it (13px, `TAB_ACTIVE`): `Style "S" decides Show or Hide when you press Apply. Remove the style tag to choose here.` The selector is still clickable-free in this state (consistent with Phase 17: the style's action wins). Decided on user's behalf: because the action cannot be overridden, the selector is read-only when a style tag is present, rather than editable-but-ignored.

## Expanded row body

Phase 20 reworks the body. This phase ships a minimal body (all inside the 460px width, `add_space(8.0)` between groups, caption in `.small()` `LABEL_TAN` above each control, as in v0.4):

1. `NAME` : v0.4 circular toggle + text field (Phase 15 pattern), retargeted to the `#ff:name` line. Toggle off removes the `#ff:name` line; typing writes/updates it. Foreign header text is not shown as the name or as a placeholder.
2. `ACTION` : three-way selector `Show` | `Hide` | `Minimal` (segmented buttons, single choice) plus a `Continue` checkbox labelled `Continue to later rules`. Read-only when a style tag exists (see above). Decided on user's behalf: `Minimal` is offered even though PoE2 rarely honours it, since EDIT-03 requires it.
3. `CONDITIONS` : read-only plain-English summary lines (e.g. `Class: Rings, Amulets`, `BaseType: 14 items`), with the note `Editing conditions arrives in a later update.` Decided on user's behalf: v0.4 per-condition controls are NOT re-mounted here; Phase 20 owns them, and mixing half-wired condition editing over a lossless parse would risk the byte-exact guarantee.
4. Row actions, in one line: `Duplicate` (small button), `Delete` (small button).

**Delete:** inline confirm, v0.4 pattern. `Delete` is replaced in place by `Delete this rule?` followed by `Yes, delete` (WARM_ACCENT) and `Keep` buttons. No modal.

**Duplicate:** inserts the copy directly after the source, collapsed, enabled state copied, `#ff:name` copied with ` (copy)` appended if a name exists, fresh identity. Foreign comments are copied verbatim. The list scrolls to the copy and expands it.

**Add rule:** `+ ADD RULE` (full-size button) appends an empty valid unnamed rule (`Show`, no conditions) before the economy section, scrolls to it, and expands it. Note the label `<n>  Show · matches everything` is intentionally a visible no-op.

## Reorder

- Up/down arrows swap the rule with its neighbour in the real file order, deferred via `RowAction` after the render loop (Established Pattern). The moved row keeps focus, stays expanded if it was, and the list scrolls to keep it in view.
- **Continue-crossing warning (Decided on user's behalf):** when a move would pass the rule over a neighbour whose block has `Continue`, or the moved rule itself has `Continue`, the move still happens, and the moved row shows a warning flag `moved across Continue` in `WARM_ACCENT` with tooltip `This move changes which rules still apply after a Continue. Check the order.` The flag stays until the next Apply or Revert, or until that rule is moved again with no crossing. Not blocking, no dialog.
- The economy section is not part of the list. A rule can never be moved below it (the down arrow on the last rule is disabled).

## Economy footer row

Pinned under the list, separate band using `HEADER_PLATE` fill, 8px padding, a single line plus button:

| State | Content |
|-------|---------|
| Section present | `+ N locked rule blocks (economy)` in `LABEL_TAN`, right side `Remove` small button |
| Section absent (file loads, no markers) | `No economy section` in `DISABLED_TEXT`, right side `Add economy section` button |
| Markers damaged | `Economy markers are damaged` in `WARM_ACCENT`; no Add/Remove (only `RELOAD`, per `footer_actions`) |

- N is the count of economy blocks inside the markers (parsed, not hardcoded). Singular: `+ 1 locked rule block (economy)`.
- Rows are never listed or expandable. Tooltip: `Generated from prices.json by SYNC ECONOMY and APPLY. Not editable here.`
- `Remove` inline confirm in place: `Remove the economy section?` + `Yes, remove` (WARM_ACCENT) + `Keep`. Takes effect in memory and is written on Apply (same single-writer rule). Copy under it: `Your own rules are kept. Add the section back any time.`
- `Add economy section` takes effect in memory, shows the footer row as present, and is written on Apply. Replaces the existing `ADD ECONOMY SECTION` footer button from Phase 18 (one affordance, not two; the action-row button is removed in this phase).

## Apply and Revert

- `APPLY` and `REVERT` keep v0.4's model: edits are in-memory, Apply is the sole writer, Revert re-parses the last applied text.
- `REVERT` is enabled only when there are unapplied edits. It restores immediately, no confirm (v0.4: visible deliberate discard). Status line after: `Reverted to the last applied filter.`
- Stale indicator (existing `apply::indicator` copy, keep): `Filter out of date — press Apply, then reload in-game` / `Filter matches saved rules`.
- After success, keep `Wrote <path>. Reload it in-game: Options > Game > Item Filter > Refresh`.
- `APPLY` is disabled (greyed, `DISABLED_TEXT`) with a tooltip while an enabled block has a grammar error: `Fix or disable the rules marked "grammar error" first.`

**Apply safety outcomes surfaced in the status block (all `WARM_ACCENT`, wrapped, below the stale indicator):**

| Outcome | Copy | Recovery affordance |
|---------|------|---------------------|
| Changed on disk | `The filter changed on disk since it was loaded, so nothing was written. RELOAD to pick up the new file. Your unapplied edits are discarded by RELOAD.` | `RELOAD` button (existing). Apply disabled until reload. |
| Damaged markers | `The economy section markers are damaged. Fix them by hand, then RELOAD.` | `RELOAD` (existing copy retained from `filter_state_message`) |
| Invalid enabled block | `Apply refused: N enabled rules have grammar errors (first: rule 12, line 3). Fix them or turn them off.` | Clicking the message jumps to and expands the first offending rule |
| Success | per above | none |
| Unchanged | `<path> is already up to date; nothing was written` (existing) | none |

Decided on user's behalf: the three refusals are non-modal status lines, never popups, matching the stripe's existing pattern.

## Copywriting Contract

Plain English, no symbol-only controls. Casing follows v0.4: ALL CAPS for primary footer buttons and captions; sentence case for in-row actions and status.

| Element | Copy |
|---------|------|
| Primary CTA | `+ ADD RULE` (list); `APPLY` (footer) |
| Search hint | `Search rules, classes, base types…` |
| Empty state heading (no rules in file) | `No rules in this filter yet` |
| Empty state body | `Press + ADD RULE to write your first one. Blocks you add are saved with the filter when you press APPLY.` |
| No search matches | `No rules match "<query>"` with body `Check the spelling, or press Clear to see every rule.` |
| Error state (filter failed to load) | `The filter could not be loaded.` plus the existing parser/IO message, then `Fix the file and press RELOAD.` |
| Error state (row grammar error) | Flag `grammar error`; tooltip is the parser message with the line number |
| Disabled invalid reason | `can't enable` flag; expanded body shows `These lines are not valid filter grammar, so this rule cannot be turned on. You can still move or delete it.` |
| Destructive confirmation (rule) | `Delete this rule?` / `Yes, delete` / `Keep` |
| Destructive confirmation (economy) | `Remove the economy section?` / `Yes, remove` / `Keep`; body `Your own rules are kept. Add the section back any time.` |
| Continue crossing warning | flag `moved across Continue`; tooltip `This move changes which rules still apply after a Continue. Check the order.` |
| Enable refused (tooltip on toggle of invalid disabled rule) | `Can't enable: the commented lines are not valid filter grammar.` |
| Foot status after add (hidden by search) | `Rule added at position N (hidden by the current search)` |

Destructive actions in this phase: delete rule, remove economy section. Revert is destructive-to-edits but deliberately unconfirmed (v0.4 trade-off). No other destructive actions.

## Interaction summary

| Action | Result | Dirty (stale) |
|--------|--------|---------------|
| Toggle enable | comments/uncomments block in memory. Refused with tooltip for invalid disabled rule | yes |
| Up/Down | swap in real order | yes |
| Action selector / Continue | updates header keyword / Continue line | yes |
| Name edit | writes or updates `#ff:name` | yes |
| Duplicate / Add / Delete | as above | yes |
| Add/Remove economy | in-memory marker change | yes |
| Search typing | filter view only | no |
| Expand/collapse | UI state only | no |
| Revert | re-parse last applied text | clears |
| Apply | single writer, safety checks | clears on success |

All mutations are recorded as a `RowAction` during render and applied once after the loop. Quit stays deferred until after render. Rule identity: a stable `RuleId` per parsed block (session-only, assigned at parse and on duplicate), used for egui ids, expansion state and scroll-to targets so state survives reorders and search filtering.
