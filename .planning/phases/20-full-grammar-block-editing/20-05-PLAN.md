<objective>
Extend the egui-free working model (`overlay::rules::WorkingFilter`) with the per-line vocabulary
the data-driven body needs: a typed view of one block's body lines, and RowActions that edit,
add and remove one line through the 20-01 line-patch API, guarded against stale line indexes.

Purpose: EDIT-01 / EDIT-02 (every condition and action viewable and editable, none read-only);
20-RESEARCH Pattern 1 (optimistic line addressing), Pitfall 4 (stale indexes in one frame),
Pitfall 6 (never emit an empty keyword: emptying a list is a RemoveLine, decided in the view).
Decision (performance, Claude's discretion): `body_view` is computed on demand for the single
expanded row each frame (one block, a few lines), not cached; `RuleRow` is not widened.
Output: extended `src/overlay/rules.rs`, new tests in `tests/overlay_rules.rs`.
</objective>

src/overlay/rules.rs
- `#[derive(Debug, Clone, Copy, PartialEq, Eq, Hash)] pub enum LineKind { Condition, Action }`
- `#[derive(Debug, Clone, Copy, PartialEq, Eq)] pub enum EntryKind { Condition, Action, Modifier, Opaque }`
- `#[derive(Debug, Clone, PartialEq, Eq)] pub struct BodyEntry { pub line: usize /*doc line index*/, pub kind: EntryKind, pub keyword: Option<&'static Keyword>, pub op: Option<Operator>, pub values: Vec<String> /*raw value tokens as written, quotes kept*/, pub text: String /*full raw line text*/, pub ordinal: usize /*0-based occurrence of this keyword (case-insensitive) within the block; Opaque entries count among themselves*/ }`
- `impl WorkingFilter { pub fn body_view(&self, id: BlockId) -> Vec<BodyEntry>; pub fn body_editable(&self, id: BlockId) -> bool }` — `body_editable` is false for an Invalid disabled block (decision Q2: its lines render as read-only raw rows with the existing can't-enable explanation; accepted exception to "no read-only condition", since the lines are commented prose the parser cannot structure). Opaque (unknown-keyword / unparsable) lines of an editable block ARE editable: `EditLine` with `LinePatch::Whole` and `RemoveLine` both apply to them.
- `RowAction` gains: `EditLine { id: BlockId, line: usize, expect: String, patch: LinePatch }`, `AddLine { id: BlockId, kind: LineKind, text: String }`, `RemoveLine { id: BlockId, line: usize, expect: String }`.
- `ActionOutcome` gains `pub line: Option<usize>` (the doc line index of a line AddLine created; None otherwise). Default stays derivable.
- `pub fn coalesce_edits(actions: Vec<RowAction>) -> Vec<RowAction>` — for EditLine actions with the same `(id, line, patch variant)` keep only the LAST one (at the position of the last), every other action untouched and in order.
- Status copy (exact strings): `pub const STALE_LINE_STATUS: &str = "That line changed before the edit landed; nothing was changed.";` `pub const NOT_EDITABLE_STATUS: &str = "This rule's lines can't be edited here.";`
