<objective>
Make styles.json the single source of truth (D-03): remove the `styles` section from config.json and
dynamic_base.json, have every load path (CLI generate, CLI apply / overlay Apply via
compile::load_inputs, and the overlay's startup store::load) read styles.json, add the load-time
rule-reference check (D-07 / STYLE-02), and reject a leftover inline `styles` section with a clear
error naming the file (OD-1, which also settles D-05 for ssf_* configs). Output stays byte-identical
(STYLE-04).

Orchestrator decision OD-1 (recorded on the user's behalf): a config/store file with an inline
`styles` section is NOT silently ignored; it fails at load naming the file and saying the section
moved to styles.json. Implementation chosen: keep a raw `legacy_styles` field (serde rename
"styles", never serialized) so serde still parses the file, and reject in `loader::load_config` when
it is present. Consequence to surface in the SUMMARY: the user's own git-ignored dynamic.json (which
has an inline styles section including `craftable`) will stop loading until its styles section is
removed (or `apply --reset`), and `craftable` must be added to styles.json if a rule uses it. Do NOT
edit the user's dynamic.json or any ssf_* file.

Decision numbering is defined in 17-01-PLAN.md. Implements D-03, D-05, D-07 (rule check), OD-1,
OD-4 (dynamic_base.json loses styles), and the `with_styles` half of OD-2.
