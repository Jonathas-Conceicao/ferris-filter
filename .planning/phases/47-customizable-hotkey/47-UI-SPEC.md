# Phase 47 - UI Design Contract

> Visual and interaction contract. Generated by gsd-ui-researcher (autonomous run, no user questions), verified by gsd-ui-checker. The target is a Rust egui overlay with the PoE2 game skin, not a web UI. Web-template fields (px scales, font weights, hex palettes) are adapted: the "design system" is `src/skin/` (palette, Fontin fonts, `ff_*` widgets). Sizes are egui points (pt). This phase adds one CONFIG section with one row, one new skin widget (the game's keybind button) and two extracted textures.

Sources: 47-CONTEXT.md (binding author decisions), REQUIREMENTS.md KEY-01..04 and ART-04, `src/overlay/config_view.rs`, `src/skin/widgets.rs`, `src/skin/palette.rs`, `src/overlay/hotkey.rs`, `src/overlay/tray.rs`, `src/overlay/mod.rs`, `src/settings.rs`, reference art `.planning/research/ui-refs/options-input-tab.png` and `options-keybind-rows.png`, and the orchestrator's ff-art findings.

## Layout Contract

CONFIG tab order becomes **Filter, Overlay, Styles** (CONTEXT.md). `show_sections` gains one call between `show_filter` and `show_styles`:

```
section_title(ui, ctx, "Filter");  show_filter(...);
ui.add_space(16.0);
section_title(ui, ctx, "Overlay"); show_overlay(...);   // new, own fn
ui.add_space(16.0);
show_styles(...);
```

Keep the change contained to a new `show_overlay` function and its call (Phase 44 edits `show_styles` in parallel; do not touch it).

`show_overlay`: an `egui::Frame` with `fill(pal::ROW_EVEN)`, `inner_margin(8)`, full width (same as Filter), holding one `ff_row(ui, 0, "Show / hide overlay", ...)`. `ff_row` (not `ff_field_row`) because its label column is free width: `Show / hide overlay` would be cut by `ff_field_row`'s 128pt column. The control column (252pt, right-aligned at `ROW_PAD`) holds, left to right: the keybind button (208 x 30pt), a 10pt gap, the reset button (`ff_reload_button`, 34pt). The reset button's right edge lines up with the Filter row's refresh button above it.

### Keybind button widget

`skin::widgets::ff_keybind_button(ui, skin, caption: &str, caption_color: Color32, width: f32, lit: bool, enabled: bool) -> Response` (exact signature is the planner's call; this is the contract):

1. Allocates `width x 30pt` with `Sense::click()` (hover only when disabled), accessible name `Show / hide overlay: <chord>` set by the caller via `widget_info`.
2. Paints `keybind_plate` as a nine-slice (`slice::paint_nine`, `draw_center = true`) over the full rect, margins = the measured corner extent, scale = `30 / texture_height`. The height is not stretched, so the radial glow near the bottom stretches horizontally into the gold line along the bottom seen in the reference.
3. Paints `keybind_border` as a nine-slice over the same rect, same margins and scale, `draw_center = false`, tint white.
4. Plate tint: `pal::GOLD` at rest; the lit tint when hovered, focused, pressed or `lit` (capturing); `GOLD` at alpha 90 when disabled.
5. Caption: Fontin SmallCaps 17, centred, cut with `…` if wider than `width - 24pt` (never in practice), moved down 1pt while pressed (as `ff_button_ex`).
6. Both textures are trimmed, so the visible art fills the rect exactly: no margin offset is applied (ART-04 for the new art).

## Interaction Contract

### States of the row

| State | Button caption | Caption colour | Plate | Reset button |
|---|---|---|---|---|
| Rest | pending chord, e.g. `Ctrl+Shift+Z` (the applied chord when nothing is pending) | `VALUE` | rest | enabled when the pending chord is not `Ctrl+Shift+Z`, greyed otherwise |
| Hover / focus | same | `VALUE` | lit | unchanged |
| Capturing, no modifier held | `Press a key…` | `HEADING` | lit | unchanged |
| Capturing, modifiers held | `Ctrl+Shift+…` (held modifiers in Ctrl, Shift, Alt order, then `+…`) | `HEADING` | lit | unchanged |
| Capturing, last press rejected | `Add Ctrl, Shift or Alt` | `WARN` | lit | unchanged |

There is no edited / pending tag on the button (house rule: no new/edited tags); the pending state shows through the CONFIG tab ` *` and the unapplied indicator.

### Capture

1. **Start.** A click on the keybind button (or Space / Enter while it has keyboard focus) starts capture. Only one capture at a time.
2. **Live modifiers.** Each frame while capturing, the caption follows the held modifiers (`Ctrl`, `Shift`, `Alt`). Releasing all of them returns it to `Press a key…`. Modifier-only presses never commit.
3. **Commit.** The first press of a non-modifier key ends capture with the chord = held modifiers + that key:
   - accepted when at least one of Ctrl / Shift / Alt is held, or the key is F1-F24 (bare or with modifiers);
   - rejected (capture continues, caption `Add Ctrl, Shift or Alt` in `WARN` until the next key or modifier change) for any other key with no modifier;
   - rejected the same way, caption `Windows key not allowed`, when the Windows key is detected in the chord (if egui does not report it on Windows, the chord cannot contain it anyway; the planner confirms which);
   - a key with no entry in the egui-`Key`-to-`Code` table is rejected with caption `Key not supported`.
4. **Escape** (with or without modifiers) cancels capture and is never bindable.
5. **Cancel also on:** a pointer press anywhere outside the button, a second click on the button, a tab switch, the window being hidden (close control, hotkey, tray), the window losing focus, any popup opening. Cancel restores the rest caption and makes no edit.
6. **Key ownership.** While capturing, the capture consumes every key event, so no other widget or shortcut reacts (no text-field undo, no dropdown or popup Escape, no scroll keys).
7. **The live hotkey while capturing (CONTEXT: pause / ignore).** The applied chord stays registered, but its events are not a toggle while capturing: a press of the registered id during capture is taken as capturing the applied chord itself (its keys never reach egui, since the OS delivers them to the hotkey). The window does not hide.
8. **Edit.** An accepted chord equal to the pending chord makes no edit. Otherwise it becomes the pending chord: one CONFIG edit (tab ` *`, unapplied indicator, counted in the Revert prompt and the Unapplied changes popup). Capturing the applied chord while a different one is pending clears that edit.
9. A chord already registered by another application is swallowed by that application before ff sees it; the capture keeps waiting. No special UI.

### Reset

`ff_reload_button(ui, skin, "Reset hotkey", enabled)`, tooltip `Reset to Ctrl+Shift+Z` (also as the disabled tooltip). A click sets the pending chord to `Ctrl+Shift+Z` (a pending edit like any capture; no popup, since Revert undoes it). Greyed when the pending chord already is `Ctrl+Shift+Z`. A click during capture cancels the capture first (it is a click outside the keybind button), then resets.

### Revert, Apply, Quit

- **Revert** (Config, behind **Discard config changes?**) discards the pending chord with the other config edits.
- **Apply** (the one shared Apply): when a chord edit is pending, Apply validates everything as today, then registers the new chord **before writing anything**, keeping the old one registered.
  - Registration fails: Apply is refused, nothing is written (no `styles.json`, `tiers.json`, filter or `ff-settings.json`), the old binding stays, the chord stays pending, status (error) as in the copy table.
  - `ff-settings.json` exists but could not be used (it is never rewritten then): Apply is refused with the copy-table message; nothing written; the new registration is released.
  - Any write fails: the new registration is released, the old one kept.
  - All writes succeed: the old chord is unregistered, the new id becomes the live one, `hotkey` is saved in `ff-settings.json`, the tray tooltip and the header close tooltip switch to the new chord, and the Apply outcome names the new chord. No restart.
  - The in-game reload follows the existing Apply rules unchanged (no special case for a hotkey-only Apply).
- **Quit:** Unapplied changes popup counts the pending chord. Apply & quit follows the rules above (a refused registration refuses the Apply, so the app does not quit).

### Start-up

- `hotkey` absent: `Ctrl+Shift+Z`.
- `hotkey` present but not a valid chord (unparsable, no modifier and not F1-F24, Windows key, wrong type): use `Ctrl+Shift+Z` and add the settings warning from the copy table (shown in the status line like the other `ff-settings.json` key warnings).
- Valid but registration fails: try `Ctrl+Shift+Z`; if that registers, use it and show the in-use warning. If `Ctrl+Shift+Z` fails too, today's tray failure tooltip and disabled menu line, naming the chord that was tried last.
- The button always shows the live chord at start-up (the fallback, not the unusable saved value), and nothing is written at start-up.

### Live chord everywhere (KEY-04)

| Place | Text |
|---|---|
| Tray tooltip, registered | `FerrisFilter — <chord> to toggle` (updated by `TrayIcon::set_tooltip` after a successful Apply) |
| Tray tooltip + disabled menu line, failed | `FerrisFilter — <chord> unavailable: <reason>`; the disabled menu line is removed once a later Apply registers a chord |
| Header close control tooltip (`app.rs`) | `Hide (<chord>)` |
| Second-launch message box (`instance.rs`) | stops naming the chord: `… Use its tray icon or its show / hide hotkey instead.` (the second process cannot know the running one's live chord) |
| Code comments and CLAUDE.md | say "the show / hide hotkey (default `Ctrl+Shift+Z`)" instead of a hardcoded chord |

Debug builds keep their separate instance name; the foreground-only rule is unchanged.

## Settings Contract

- Key: `hotkey` in `ff-settings.json`, a string in the chord format above (e.g. `"hotkey": "Ctrl+Alt+K"`). Absent means `Ctrl+Shift+Z`. Parsed by FerrisFilter's own table, not `global-hotkey`'s `FromStr` text, so the file reads the same as the UI.
- Written only by Apply (only that key; unknown keys preserved, like the other per-key saves), and only when a chord edit is pending. A reset applied writes `"Ctrl+Shift+Z"` explicitly.
- Read by the overlay only. `ff-cli` ignores it.

## Judgement calls

Decided without asking, per the autonomous run.

1. **Keybind art found, fallback unused.** `optionsbuttonborder.dds` + `optionsbutton.dds` are the game's own keybind button; the generic `ff_button` art is not used. Flagged for the author's review in the summary.
2. **Border interior cleared in the manifest** (`clear`), not only skipped with `draw_center = false`: the white interior also reaches into the edge pieces of a nine-slice, so only a cleared PNG gives a frame-only draw.
3. **30pt button height** at 0.5pt per texel: the art is 60px, so it is pixel-exact at 200% DPI and close to the game's slim button inside a taller row.
4. **`ff_row`, not `ff_field_row`.** The label would be cut in the 128pt label column; `ff_row` is the skin's Options-style row (label left, fixed 252pt control column right), which is what the reference shows. The reset button lines up with the Filter refresh button above.
5. **Reset button margins left to ART-04.** The new keybind textures are trimmed, so they need no offset. `ff_reload_button` is used unchanged; its transparent right/bottom margin is ART-04 (Phase 48), which fixes the widget itself and so moves this reset button and the Filter refresh together. Adding a local offset here would double-compensate after Phase 48.
6. **Ignore, not unregister, during capture.** Unregistering for the capture could lose the chord to another app; keeping it registered and reading its own event as "capture the applied chord" both stops the window hiding and still lets the applied chord be captured.
7. **A refused registration refuses the whole Apply.** Registration is tried after validation and before any write, so it fits the existing all-or-none rule ("a refusal writes nothing"); the chord stays pending and can be changed or reset. Skipping only the chord would make Apply & quit silently drop it.
8. **Escape is never bindable** (it cancels capture); F1-F24 may be bare; Ctrl / Shift / Alt are the only modifiers.
9. **Rejected presses keep the capture open** with a short amber caption on the button itself instead of a status-line message, so the feedback stays where the user is looking and the status line is not overwritten.
10. **Second-launch message stops naming the chord**: that process cannot know the running instance's live chord, and KEY-04 allows "stop naming it".
11. **Settings key `hotkey`, human chord text** (`Ctrl+Shift+Z`), written explicitly when a reset is applied; absent means the default.
12. **Hotkey-only Apply keeps the normal in-game reload.** Apply stays one uniform action; no special case.
13. **Screenshot flags `--hotkey` and `--capture-hotkey`** so the planner and the UI auditor can verify the capture, pending and fallback looks without a real hotkey.
14. **CLAUDE.md task required** (planner): the overlay note ("Press `Ctrl+Shift+Z` (system-wide, hardcoded)") becomes the configurable hotkey with its default; the `ff-settings.json` row gains `hotkey`; the Config tab note gains the Overlay section; the `ff` row gains the two screenshot flags; the tray Quit/hotkey wording drops "hardcoded".
