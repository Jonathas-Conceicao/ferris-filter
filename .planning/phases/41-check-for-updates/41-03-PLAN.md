- Decision 2: a partial download on quit is deleted; a verified installer left when the user
  quits normally (not via Install) is deleted at shutdown.
- Decision 3: no generic worker refactor; `EconomySync` (`src/overlay/economy.rs`) and
  `LeagueList` (`src/overlay/leagues.rs`, from 39-03) stay untouched; this is a third copy that
  carries a Downloading stage message then Done.
- Decision 4: the install click re-checks the installer and sets an install-on-quit intent;
  Cancel or a refused Apply clears it (the button stays Ready).
- Planner discretion: the click-time re-check also re-hashes the installer against the verified
  SHA-256 (cheap, closes most of the verify-to-spawn window); a mismatch uses the existing
  `Mismatch` message and deletes the folder.

<feature>
  <name>Update job model (src/overlay/update_job.rs)</name>
  <files>src/overlay/update_job.rs, src/overlay/mod.rs</files>
  <behavior>
    - Fresh UpdateJob: state Idle, caption "Check for updates", enabled, tooltip "Look for a newer version on GitHub."
    - Checking: caption "Checking…", disabled, tooltip "Asking GitHub."; Downloading { "0.8.0" }: "Downloading…", disabled, "Downloading and checking the installer."; Ready("0.8.0"): "Install 0.8.0 and quit", enabled, "Closes FerrisFilter and starts the installer."
    - start(work) from Idle -> state Checking, returns true; start while Checking, Downloading or Ready is a no-op returning false and the closure never runs
    - a work closure that calls progress.downloading("0.8.0") then returns Ready -> successive polls yield ("Downloading 0.8.0…", Info) then ("0.8.0 available, released <date>", Info) with state Downloading then Ready (when both messages arrive in one poll, the state ends Ready and the last message is returned)
    - a closure returning UpToDate -> state Idle, message "Up to date (...)" Ok; returning Failed(Offline) -> Idle, Warning text
    - a closure that panics (sender dropped before Done) -> state Idle, message ("Could not read the latest version from GitHub.", Error)
    - inject(Ready(..)) sets the state without a worker; poll then returns None
    - begin_install when not Ready -> InstallClick::NotReady, intent stays false
    - begin_install with Ready whose installer file was deleted -> InstallClick::Failed(("The installer for 0.8.0 is no longer there. Check for updates again.", Error)), state Idle, intent false
    - begin_install with Ready whose installer bytes changed -> Failed with the Mismatch message, state Idle, folder deleted
    - begin_install with a valid Ready -> InstallClick::Proceed, install_intended() true, state still Ready; cancel_install() -> install_intended() false, state still Ready
    - shutdown() with intent and Ready -> Some(installer path) and the folder still exists; shutdown() without intent while Ready -> None and the folder is deleted; shutdown() while Downloading with a published partial folder -> None and that folder is deleted; shutdown() while Idle -> None
  </behavior>
  <implementation>See tasks.</implementation>
</feature>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| %TEMP% work folder -> click/shutdown | the installer path is re-validated before it is handed to the spawn |
| worker thread -> UI thread | messages over an mpsc channel |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-41-13 | Tampering | installer between verify and spawn (TOCTOU) | mitigate | `begin_install` re-checks existence and re-hashes against the verified SHA-256; mismatch deletes the folder; a same-user attacker able to race this is out of scope |
| T-41-14 | Elevation of Privilege | spawning on the wrong quit | mitigate | `shutdown()` returns a path only when `install_on_quit` is set by a successful click and state is Ready; `cancel_install` clears it; tests cover plain quit and cancel |
| T-41-15 | Tampering | `abandon` deleting the wrong folder | mitigate | deletes only the slot path or the installer's parent, and only when the last path component starts with `FerrisFilter-update-` |
| T-41-16 | Denial of Service | stuck button after a worker panic | mitigate | `Disconnected` before Done returns to Idle with the generic error |
</threat_model>
