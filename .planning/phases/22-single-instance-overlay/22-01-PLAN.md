<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| other local process (same logon session) -> named kernel objects | Any same-user process can open the `Local\` mutex/event names |
| second ff process -> first ff process | Cross-process signal carries no payload, only "show" |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-22-01 | Spoofing | `-show` event | accept | A same-user process can SetEvent the show event; the only effect is a reveal of the stripe (no data, no focus steal via `SW_SHOWNOACTIVATE`). Same-user code already has full control. |
| T-22-02 | Denial of Service | mutex name | accept | A same-user process could pre-create the mutex name and prevent `ff` from starting a stripe; it then shows the not-responding message. Same-user only (`Local\`, default DACL via null SECURITY_ATTRIBUTES); GUID in the name avoids accidental collisions. |
| T-22-03 | Elevation of Privilege | `Global\` namespace | mitigate | Names are built only from `Local\` (pure tests assert the prefix); null SECURITY_ATTRIBUTES gives the default same-user DACL. |
| T-22-04 | Tampering | `unsafe` Win32 calls | mitigate | Handles come only from Create* in this module, are null-checked before use, closed exactly once in `Drop`/`signal_running`; names are NUL-terminated UTF-16 owned Vecs alive across the call; every block has a SAFETY comment. |
| T-22-05 | Denial of Service | tests vs a running ff | mitigate | Windows tests use `Local\FerrisFilter-test-<pid>-<label>` names only, never production names (Pitfall 6). |
| T-22-SC | Tampering | dependency installs | accept | No new crate; only features of the already-locked windows-sys 0.61.2. No package-legitimacy gate needed. |
</threat_model>
