## Pattern Assignments

### `src/filter/section.rs` + `src/filter/meta.rs` (banner recognition, economy begin-only)

**Analog:** current `section.rs`. Every marker is read through `Line::ff_marker()` (key-based, never substring), which wraps `meta::parse_ff_line`.

**Marker reader** (`src/filter/lines.rs` 40-42, `src/filter/meta.rs` 41-60):
```rust
pub fn ff_marker(&self) -> Option<(&str, Option<&str>)> { super::meta::parse_ff_line(&self.text) }
pub(crate) fn parse_ff_line(text: &str) -> Option<(&str, Option<&str>)> {
    let (_, _, rest) = strip_prefix(text)?;   // accepts "# ff:" and legacy "#ff:", leading ws
    ...  // key = [A-Za-z0-9_-]+, value = rest trimmed
}
```
A banner is `rule / # ff:section <name> / rule`. Recognise it as three consecutive lines: line i-1 and i+1 are only `#` (>= 3, lenient; write exactly 80) and line i has key `section` or `economy-begin`. Anything else (NeverSink `#====`) stays a comment. A `# ff:section` line without both rules is ordinary comment (UI-SPEC: damaged banner is not a section). Writer helper next to `ff_line` (meta.rs 19-24), e.g. `banner_lines(key, value) -> [String; 3]` with `"#".repeat(80)`.

**Constants to replace** (`section.rs` 19-22): `BEGIN_KEY`, `END_KEY`, `BEGIN_LINE`, `END_LINE`. New: `BEGIN_KEY` stays `economy-begin`; add `SECTION_KEY = "section"`; `BEGIN_LINE` becomes `# ff:economy-begin Economy (generated by FerrisFilter, do not edit)`; delete `END_KEY`/`END_LINE` and `SectionError::{EndWithoutBegin,BeginWithoutEnd,EndBeforeBegin,DuplicateEnd}` (lines 36-74). Keep `DuplicateBegin`, `MarkerInsideBlock`, `NoSection`, `AlreadyPresent`, `BodyContainsMarker`, `Parse`.

**SectionSpan** (lines 29-34) is `{begin, end}` as marker line indices. New semantics: `begin` = the economy banner's first rule line (or the `economy-begin` line; pick one and be consistent), `end` = exclusive end = next section banner start or `lines.len()`. Every user of `span.begin/span.end` (`structure.rs` 513 `in_economy`, `rules.rs` 513, `dynamic.rs` 334-370 `blocking_errors`) uses `h > s.begin && h < s.end`; re-check each comparison when `end` becomes exclusive.

**refresh/add/remove pattern** (lines 162-245): build `out` by `push_line(&mut out, l.text(), l.eol())`, preserve BOM and `Eol`, finish with `require_one_span`. Copy this shape:
```rust
pub fn refresh(text: &str, body: &str) -> Result<String, SectionError> {
    let body = body_lines(body)?;
    let doc = parse_doc(text)?;
    let span = find(&doc)?.ok_or(SectionError::NoSection)?;
    let lines = doc.lines();
    let eol = lines[span.begin].eol();
    let mut out = String::new();
    if doc.has_bom() { out.push('\u{feff}'); }
    for l in &lines[..=span.begin] { push_line(&mut out, l.text(), l.eol()); }
    ...
```
Changes: `refresh` keeps lines up to and including the banner's third line, writes `"", body..., ` then keeps `lines[span.end..]` (the next section banner, if any; economy is always last so usually EOF). `add` pushes banner (3 lines) instead of `BEGIN_LINE`, no END line. `remove` deletes banner through `span.end` plus the one blank line above (existing logic lines 230-233). `body_lines` must now reject a body line that is an `economy-begin` or `section` marker (line 142).

**v0.4 migration** (`is_v04`, `migrate_v04`, `V04_*` consts, lines 24-28, 247-340, tests 679-769): CONTEXT says no migration and old markers unrecognised. Planner decision needed: delete `migrate_v04`/`is_v04` and their callers (`src/dynamic.rs:151`, `LoadedFilter.migrated`, overlay "will be converted on next Apply" notice, `tests/filter_structure.rs:203`) or keep it re-targeted. CONTEXT line 32 says old one-line markers not recognised; v0.4 conversion wraps with those markers, so it must go or emit the new banner. Flag for plan.

**`body_lines` dedupe rule** — the generated economy body must never contain `# ff:section` (it does not today).

### `src/filter/parse.rs` (lead_start and marker-as-trivia)

**Analog:** itself, lines 66-91.
```rust
fn is_economy_marker(line: &Line) -> bool {
    matches!(line.ff_marker().map(|(k, _)| k),
        Some(super::section::BEGIN_KEY | super::section::END_KEY))
}
fn lead_start(ls: &[Line], floor: usize, header: usize) -> usize {
    let mut j = header;
    while j > floor && is_comment_line(ls[j - 1].text()) && !is_economy_marker(&ls[j - 1]) { j -= 1; }
    j
}
```
Required change: a banner (rule line, `# ff:section|economy-begin`, rule line) must never be pulled into the leading comments of the block below it. Walking upward from the header, the 80-`#` line directly above the block is a bare comment that would otherwise be absorbed, so stop at the *third* banner line (a pure-`#` rule line whose predecessor-but-one is a banner key). Implement `fn banner_end_at(ls, j) -> bool` and stop `lead_start` when `ls[j-1]` is the closing rule of a banner, or when the line is itself a banner key. Also check `disabled::detect` (`# Show` detection) does not eat banner rule lines (80 `#` is a comment run). Test that a disabled block directly under a banner keeps its banner out of `lead_start`.

Same predicate exists in `structure.rs` lines 39-44 (`is_marker`); consolidate into one `pub(crate) fn is_banner_line(ls, i)` in `section.rs` and use it in both places plus `edit.rs:697` (`d.line_at(j).ff_marker().is_some()` region) and `group.rs` 254/357/457 (these read `ff_marker` for `group` key only; check they ignore the new keys).

Swapping a unit with a banner between them already works ("leave whatever lies between them where it is, which makes a move its own inverse", module doc).

### `src/filter/group.rs`, `src/filter/edit.rs`
