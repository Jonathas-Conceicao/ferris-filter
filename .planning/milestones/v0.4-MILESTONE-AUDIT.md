## The one blocker that remains

**`ff` cannot be launched by double-clicking the built exe.** Reproduced by the author 2026-09-17:

```
Cannot read `C:\...\target\release\dynamic_base.json`:
The system cannot find the file specified. (os error 2)
```

`store.rs:81-84` resolves every overlay path from `std::env::current_dir()`. `ff` is a Windows
GUI-subsystem binary, so started from Explorer the CWD is the exe's own folder. Compounded by
WARNING-1: nothing in `src/overlay/` calls `reset_store`, so there is no way back from inside the
GUI.

**Deferred to v0.5 by the author**, and the deferral is sound: the fix is not a patch but a decision
about where the overlay anchors its root — exe-relative lookup, walking up for `dynamic_base.json`,
or a remembered location — plus an in-GUI recovery path. It does not affect the author's own
workflow, which launches from the repo root.

It is recorded as blocker-severity tech debt rather than a milestone gap because no v0.4
requirement states that `ff` must launch from a shortcut. That is a technicality, and it is flagged
here precisely so the technicality does not bury it: for any user who is not the author, this is
the first thing they would hit.
