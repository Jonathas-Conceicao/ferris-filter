item, and implement `sync metadata` to build/refresh it from the RePoE-fork PoE2 JSON exports.

```json
{
  "version": 1,
  "overviewTypes": [
    { "type": "Currency", "category": "Currency", "class": "Stackable Currency", "baseTypeIsName": true },
    { "type": "Breach",   "category": "Breach",   "class": "Stackable Currency", "baseTypeIsName": true },

}
```

RePoE-fork exports (lenient parse — only these fields):
- https://repoe-fork.github.io/poe2/base_items.json — JSON object keyed by metadata path; each value
  has `"name"` (e.g. "Divine Orb") and `"item_class"` (PascalCase e.g. "StackableCurrency").
- https://repoe-fork.github.io/poe2/uniques.json — JSON keyed by numeric id; each value has `"name"`
  + `"item_class"` (e.g. "Amulet", "Belt"). No base_type (poe.ninja supplies unique baseType at
  prices time).

Normalization (RePoE item_class → filter Class==): insert a space before each interior uppercase
letter ("StackableCurrency" → "Stackable Currency", "BodyArmour" → "Body Armour"), with a small
override table for known irregulars confirmed against CLAUDE.md's class list.

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-06 | Tampering | RePoE response → mapping.json | mitigate | validate non-empty + parses; assemble fully in memory; tempfile `persist` atomic rename (Pattern 4) |
| T-04-07 | Denial of service | malformed/huge RePoE JSON | mitigate | lenient serde into a flat HashMap of only `name`+`item_class`; 30s client timeout (plan 01); no recursion |
| T-04-08 | Tampering | TLS to repoe-fork.github.io | mitigate | reqwest rustls-tls; hardcoded HTTPS URLs; `.error_for_status()` |
| T-04-09 | Spoofing / SSRF | request target | mitigate | RePoE URLs are compile-time constants; no user-controlled host/path |
| T-04-10 | Repudiation | silent partial map | accept | mapping.json is committed to git; diffs are reviewable; not security-sensitive |
</threat_model>
