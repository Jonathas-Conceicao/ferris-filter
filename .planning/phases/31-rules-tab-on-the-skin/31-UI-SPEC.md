# Phase 31 — UI Design Contract

> Visual and interaction contract for the RULES tab (rule list + expanded rule editor) on the `src/skin` look. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> Rust egui/eframe overlay, not a web app: "px" means egui logical points (pt), the design system is the in-repo `src/skin/`. This spec EXTENDS `30-UI-SPEC.md` (palette, Fontin size set 14/15/17/21, spacing tokens, icons, status line, popups, 535pt usable content width); where it is silent, Phase 30 applies. Target look: `.planning/quick/261016-1de-.../ff-proto-rules.png`. Sources: 31-CONTEXT.md (locked), CLAUDE.md overlay notes (every v0.5 RULES capability must survive, RULES-02), 30-UI-REVIEW.md findings, `ff-proto.rs`, `skin/{widgets,editor,icons}.rs`. Items marked "(Claude's discretion)" were decided here without user input.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none (in-repo `src/skin/`) |
| Preset | not applicable |
| Component library | `skin::widgets` (`ff_check`, `ff_arrow`, `ff_text_field`, `ff_button`, `ff_dropdown`, `ff_slider`, `ff_row`, `ff_scroll_area`, `row_background`), `skin::editor` (`ff_segmented`, `ff_card`, `ff_icon_button`, `caption`), `skin::icons` (`flag_icon`, `FLAG_ICON_SIZE` 18) |
| Icon library | painted vector shapes in `skin::icons`; no new art files |
| Font | Fontin SmallCaps (`fontin-sc`: row header, labels, chips, buttons) and Fontin Regular (`fontin`: summary, values, tooltips); sizes stay exactly 14, 15, 17, 21 |

Legacy wrappers (`widgets::themed_slider`, `circular_toggle`, `slide_switch`, `toggle_chip`, dropdown/combo helpers, text-field helpers) become THIN DELEGATES to the skin widgets (same signatures, same call sites in `body.rs`), so every editor path migrates at once. Per Phase 30 item 4: `circular_toggle` -> `ff_check`; `themed_slider` -> `ff_slider` (slider + exact-number field, see Editor); dropdowns -> `ff_dropdown`; text fields -> `ff_text_field`; `slide_switch` -> `ff_segmented` where a Yes/No or Show/Hide pair is shown. No egui-default-looking widget may remain in the RULES tab except the colour picker (below).

---

## Scope and Boundaries

- IN: toolbar, collapsed rows, expanded editor (all of it), add-rule behaviour, RULES scrollbar swap to the game scrollbar.
- OUT: Dividers/sections (Phase 32; no `+ Add section`, no section header rows; the add-rule insertion point is simply "top of file, before any divider"); skinned colour picker (Phase 33). Colour ACTIONS (Text/Border/Background colour, alpha) keep the current picker; a mixed look inside those three action cards is accepted. Surrounding label/row/card chrome for them is still skinned.
- Nothing from v0.5 is removed. The capability checklist is in "Capability Preservation" below and is the human-verification walk for this phase.

## Toolbar Row (RULES-01)

Top of the tab, pinned (does not scroll):

| Part | Contract |
|------|----------|
| Layout | left to right: `ff_text_field` (hint `Search {N} rules, classes, base types…`) + 8pt gap (`sm`) + `ff_button("+ Add rule", 124)` |
| Width arithmetic | `field_w = available_w - 124 - 8`; the field and button never touch (fixes 30-UI-REVIEW #2). Use explicit `item_spacing.x = 8` for this row and size the field from the remaining width; do not rely on default spacing |
| Heights | field 30 (`ff_text_field`), button 34 art; vertically centred on a shared 34pt row; 8pt below the row before the list |
| Clear | non-empty query keeps the small `Clear` inside the field's right edge (v0.5) |
| Button tooltip | `Adds a new rule at the top of the file.` (Claude's discretion; replaces the Phase 30 tooltip "Blocks you add are saved with the filter when you press Apply." which moves to the status line outcome, see Add rule) |
| Disabled | dimmed, `Sense::hover`, when `!actions.add_rule` (unchanged) |

## Collapsed Rule Row (RULES-01)

Fixed height so the virtual list can compute offsets without measuring: **collapsed row = 52pt** (two lines), no inter-row gap; separation is the alternating `pal::ROW_EVEN`/`ROW_ODD` ground, hover `pal::ROW_HOVER`, matching the prototype. `virtual_list` keeps its prefix-offset scheme: collapsed rows use this constant, the single expanded row (one at a time) uses its measured height cached by rule id. 500 blocks therefore paint ~12-14 rows per frame.

Row anatomy, left to right, inside the 535pt content width (`ROW_PAD` 10 each side):

| Slot | Contract |
|------|----------|
| Enable check | `ff_check` round ring art (22), vertically centred across both lines. Disabled-rule look: row text dims (see below). Tooltip: v0.5 toggle tooltips unchanged (`Can't enable: the commented lines are not valid filter grammar.` for blocked) |
| Index | `regular(15)`, `pal::MUTED`, right-aligned in a 28pt slot, 8pt gap after the check |
| Show / Hide | `small_caps(17)`, `pal::LABEL`, 44pt slot, 8pt gap before the name. Plain text, not gold (reduces gold use, fixes 30-UI-REVIEW accent finding; Claude's discretion vs prototype's gold-tinted word) |
| Name (line 1) | `small_caps(17)`, `pal::HEADING`; from `# ff:name` ONLY (foreign `$type->` text never shown); empty name shows nothing (header reads `N  Show`); single line, cut with "…" at the label rect; `LABEL_MIN_W` 140 kept |
| Summary (line 2) | `regular(15)`, `pal::MUTED`, indented to align under the Show/Hide slot start (x = index end + 8), single line cut with "…", full text as the row's hover tooltip only when cut. Hierarchy fix (30-UI-REVIEW): header line is small-caps 17 in bright colours, summary is regular 15 in muted, two clearly distinct levels; line 1 baseline at row top + 18, line 2 at row top + 38 |
| Right cluster | right-to-left: arrows (`ff_arrow` up/down, 16pt each, 4pt apart, then `ROW_PAD`), then 8pt, then flag icons / tags (below) |
| Disabled rule | whole row text uses `pal::DISABLED` for name and summary, check ring unfilled; row ground unchanged |
| Expanded rule | row ground gets a 1pt `pal::INPUT_BORDER_HOT` outline (as prototype row 3); the header block stays identical, the editor opens below it |

Click anywhere on the row (not check, arrows, flags) toggles expansion (one at a time, v0.5). Keyboard: row is focusable; Enter/Space toggles.

### Flag cluster (budget numbers for 535pt)

Order right to left from the arrows (kept from Phase 30): grammar error, grammar warning, unknown style, group broken, moved across Continue, Continue tag, styled chip. Icons are `skin::icons::flag_icon`, 18pt hit rect.

| Item | Contract |
|------|----------|
| Budget | `FLAG_BUDGET` stays 120pt for icons + tags combined (6 icons x 18 = 108 + gaps no longer fits all, hence the `+N` badge). Label min 140 is guaranteed: available = 535 - 2x10 (pad) - 22 (check) - 28 (index) - 44 (show/hide) - 3x8 (gaps) - 36 (arrows) - 8 = ~353 >= 140 + 120. Keep the arithmetic in one tested fn (`fit_flags`) fed measured widths |
| Gap between flag items | 4pt between icons |
| Continue tag | word `Continue`, `small_caps(17)`, `pal::GOLD`, tooltip `Matching goes on to the rules below`. Separated from the styled chip by **at least 8pt** and the styled chip is placed to the LEFT of Continue in the cluster, so the reading order is `styled-chip   CONTINUE` (fixes `◆ A CONTINUE` phrase reading). The tag is the only gold TEXT in a collapsed row |
| Styled chip | diamond (14pt `slider_thumb` texture) tinted `pal::LABEL` (NOT gold; reduces accent overuse), then 4pt, then style name truncated to 10 chars + "…" in `regular(15)` `pal::MUTED`; tooltip `Style "{tag}" sets this rule's actions on Apply`. Name text never touches the Continue word (8pt) |
| `+N` badge | `regular(15)`, `pal::MUTED`, at the far left of the cluster, tooltip joins hidden flags' tooltips with newlines; errors are never folded away (kept) |
| Icon fixes (30-UI-REVIEW #3) | all flag icons painted at 16pt glyph size inside the 18pt hit rect, 1.75pt stroke: (a) group-broken = two chain links with a visible gap and a diagonal slash through the gap (not two joined rings); (b) padlock = 16pt, body filled `pal::WARN` alpha 90 + 1.75pt outline, shackle arc clearly open-topped; tooltips as in Phase 30 B |
| Accent rule | gold in a collapsed row is limited to: the enabled check ring tick (art), and the Continue word. Nothing else in the row is gold |

## List Container

- `ff_scroll_area` (game scrollbar: 5pt track, 12pt gold thumb, `SCROLLBAR_WIDTH` 14 + 4 gap) replaces the thin egui scrollbar. It wraps the virtualised list; scroll offset is kept per tab and across hide/summon. Phase 30's thin-scrollbar note is superseded.
- Rows reserve the scrollbar's 18pt on the right, so the 535pt budget above is measured inside that (flag/label arithmetic uses 535 - 18 = 517; after the 120pt flag budget, arrows and the left slots the label keeps well over the 140pt minimum). Planner: use the content rect actually offered, not a constant.
- Focal point: the expanded row (its `INPUT_BORDER_HOT` outline) when one is open, otherwise the `+ Add rule` button; the shell keeps the selected tab and Apply as its own focal points.
- Empty states (heading only, centred, `small_caps(21)`, `pal::HEADING`): `No rules yet`, `No rules match "{query}"`, `The filter could not be loaded.` (unchanged).
- Pinned economy footer row (34pt) unchanged from Phase 30.

## Expanded Rule Editor (RULES-01, RULES-02)

Layout: two columns inside the expanded rule, directly under the header block, on `pal::ROW_EVEN` ground with 10pt left/right padding, `ff_row`-style 34pt lines:

| Column | Contract |
|--------|----------|
| Label (left) | `small_caps(17)`, `pal::LABEL`, fixed width 128pt, vertically centred on the line, left aligned. Source text mixed case |
| Control (right) | starts at x = label end + 16 (`md`), width up to `CONTROL_WIDTH` 252 for single controls; the content width is `available - 128 - 16`, wide controls (sliders, lists) use all of it. Never horizontal scroll |
| Line rhythm | 34pt min line height, 4pt between lines (`item_spacing.y`); sections separated by the existing alternating ground (`row_background` even/odd per line) |

Order top to bottom (v0.5 order kept): NAME, CONDITIONS (one line/card per condition), `+ condition`, STYLE, then (Custom only) Show/Hide and ACTION lines with `+ style`, then `Continue to later rules`, then the Duplicate / Delete row. No caption paragraphs; every standing explanation is a tooltip on its control or label (Phase 30 inventory continues to apply).

### Controls

| v0.5 control | Skinned form |
|--------------|--------------|
| NAME text box | `ff_text_field` (30pt, width = control column), hint `Name`; empty = no `# ff:name`; behaviour unchanged |
| Numeric condition (ItemLevel, AreaLevel, Quality, Sockets 0-6, StackSize...) | row: operator `ff_dropdown` (min 64 wide, plain-English labels in the list, existing operator never normalised) then `ff_slider` filling the remainder, then the exact number as a value field right-aligned at the slider end (`regular(15)`, `pal::VALUE`, 44pt wide, editable on click, validation hint `WHOLE_NUMBER` inline below in `pal::ERROR`, retained) as in the prototype's "Item Level  >=  slider  82" line |
| Between | one card: two stacked slider lines, labels `Min`/`Max` (`regular(15)`, `pal::MUTED`) at the left of each slider, clamped so min never exceeds max (v0.5), `MIN_GT_MAX_HINT` inline in `pal::ERROR` |
| Rarity / Class-like single enumerations | `ff_dropdown`, full control width |

Grouped-rule behaviour (n blocks, `# ff:group`) unchanged; `group broken` flag on the header. Both Defences pickers entries greyed when either card is present (unchanged) |

| Quoted lists (BaseType, mod names) | vertical list in a framed scroll area of ~7 rows (28pt rows = 196pt max height, `ff_scroll_area`), each entry `regular(15)` `pal::VALUE` with a right-aligned remove (`ff_icon_button` x). Below it: `ff_text_field` (hint `Type a name, press Enter`) + 8pt + `ff_button("+ Add", 84)`; Enter or button adds; a pasted quoted list is split (v0.5) |
| + condition / + style pickers | `ff_button("+ condition" / "+ style", 132)` opens a popup list on `skin.box_9slice` (dropdown art): top `ff_text_field` search, below grouped sections as collapsible headers (`small_caps(17)`, collapsed by default, a search opens matching sections), items `regular(15)`; items already on the rule are `pal::DISABLED` and clicking focuses the existing card (`ALREADY_ON_RULE`); Simple/Defences entries sit right after Rarity (v0.5). List height max 320pt then scrolls |
| Pending list condition | unwritten row shows its operator dropdown first, then the entry field (v0.5) |
| STYLE picker | `ff_dropdown` with `Custom` first then every `styles.json` preset in file order; unknown style flagged on the picker with `pal::WARN` text + tooltip. Presets hide Show/Hide and actions |
| Show / Hide (Custom only) | `ff_segmented` `Show | Hide` on its own line under the picker; foreign `Minimal` shown as text `Minimal` (muted) and untouched unless changed |
| Action lines | FONT SIZE: `ff_slider` + value; SOUND: `ff_dropdown` + volume `ff_slider`, custom file `ff_text_field`; MINIMAP ICON / BEAM: `ff_dropdown`s + `Temporary` as `ff_check` (as v0.5; the richer swatch/shape tiles of `skin::editor` are Phase 33 and are NOT required here); Text/Border/Background colour: current picker unchanged (Phase 33), each on a 34pt labelled line |
| Raw rows | `regular`/monospace(14) text field, full width, Enter commits; an edit adding a grammar Error shows an inline hint and changes nothing (v0.5) |
| Continue | line with single `ff_check` ring + label `Continue to later rules`, last in the body; tooltip `Matching goes on to the rules below` |

| Validation | grammar errors/warnings keep their flag icons; field-level hints stay inline in `pal::ERROR` / `pal::WARN`, `regular(15)` |

Colour usage inside the editor follows the 60/30/10 split of Phase 30: gold only on focus/hover borders, slider fill, ring tick, selected chips and section-style headings; destructive red only on `Delete` caption and error text.

## Add Rule (RULES-03)

| Aspect | Contract |
|--------|----------|
| Insertion | new empty `Show` block as the FIRST block of the file, above every other block and (in Phase 32) outside/before any section; was "before the economy section". The change lives in `src/filter` edit/structure code and is the single insertion point Phase 32 reuses |
| Result row | becomes rule index 1; all other indices shift by one; the list state, expanded id, search matches and stored scroll are re-keyed by rule identity, not index |
| After adding (Claude's discretion) | the new rule is expanded (the previous expansion collapses, one at a time) and the list scrolls to offset 0 so it is fully visible; the NAME field takes keyboard focus. If a query is active that would hide the new unnamed rule, the query is cleared first (same as the grammar-gate jump). Nothing is auto-applied |
| Status | event message (Ok): `Rule added at the top of the file. Press Apply to save it.` (replaces `Rule added at position N (hidden by the current search)`, which can no longer occur because the query is cleared) |
| Undo | Revert/Reload discard it like any other edit |
| Tooltip | on `+ Add rule`: `Adds a new rule at the top of the file.` |
| Interaction with grouped rules and economy | new rule never lands inside a `# ff:group` run; economy footer row untouched |

## Spacing Scale

Phase 30 tokens apply unchanged (multiples of 4):

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| xs | 4px | icon gaps, line gap in the editor, summary offset |
| sm | 8px | toolbar gap, chip gaps, flag-cluster gaps, Continue-to-chip minimum, button gaps |
| md | 16px | label-to-control gap |
| lg | 24px | not used |
| xl | 32px | not used |
| 2xl | 48px | not used |
| 3xl | 64px | not used |

Exceptions (all art- or prototype-fixed, intentional): collapsed row 52, editor line 34, label column 128, control width 252, number field 44, check 22, arrow 16, flag hit rect 18, chip height 28, list rows 28, button 34 / field 30, `ROW_PAD` 10. Row height 52 and the 4pt vertical gap are multiples of 4; the odd values (22, 18, 14, 10) are inherited from the skin.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `pal::GROUND` #0A0A09 / `pal::PANEL` #0F0E0D | window ground, Ferris bg showing through rows |
| Secondary (30%) | `pal::ROW_EVEN`/`ROW_ODD`/`ROW_HOVER`, `pal::INPUT_FILL` #070707, `pal::INPUT_BORDER` #3E3B34 | rows, editor lines, inputs, chips off-state, popups |
