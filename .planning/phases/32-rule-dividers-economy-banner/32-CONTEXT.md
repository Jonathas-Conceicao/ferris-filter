<decisions>
## Implementation Decisions

### File format
- Divider = three lines, 80 `#` on each rule line:
  ```
  ################################################################################
  # ff:section <name>
  ################################################################################
  ```
- Economy = the same banner with `# ff:economy-begin Economy (generated by FerrisFilter, do not edit)`.
  **No end markers at all** (author): a section begins at its banner and ends at the next section
  banner or end of file. Regenerating the economy section replaces the blocks between its banner and
  the next banner / end of file.
- The economy section is always appended at the **end of the file** (`ff-cli apply --add-economy`
  now, the ECONOMY tab in Phase 34); `--remove-economy` deletes the banner and its blocks.
- The old one-line `# ff:economy-begin ...` / `# ff:economy-end ...` markers are no longer recognised
  (no migration; the author converts their own dynamic.filter by hand). Update the tests that use
  them (`tests/dynamic_filter.rs`, `tests/filter_roundtrip.rs`, unit tests) deliberately; `generate`
  output and `tests/fixtures/seed-universal.filter` must stay byte-identical (they hold no economy
  markers).
- Foreign comment banners (NeverSink `#====`, etc.) are never sections: only a banner whose middle
  line is `# ff:section` / `# ff:economy-begin` counts.
- Lossless: load + save without edits stays byte-identical; edits touch only their lines.

### Overlay behaviour
- Rules above the first divider have no header.
- Header row: collapse arrow, name, rule **count** (not a range — author), inline rename, up/down
  arrows (move the divider line one rule at a time), remove (its rules stay and join the section
  above). Economy header: locked, collapse/expand only, read-only rows, collapsed by default; it
  replaces the `+ N locked rule blocks (economy)` footer row.
- Adding: toolbar `+ Add section` inserts a divider at the top of the list with its name field open;
  a `Section above` button in an expanded rule's bottom row (beside Duplicate / Delete) inserts one
  directly above that rule.
- `+ Add rule` still inserts at the very top of the file, outside every section, even when a divider
  is the first thing in the list (collapsed or not).
- Rules move freely across dividers with the arrows (moving past a divider puts the rule into the
  adjacent section — author: "rules can be moved into a new section"). A divider cannot split a
  `# ff:group` run; it steps over the whole group. Nothing user-editable moves into or below the
  economy section.
- Collapsed state saved per filter in `ff-settings.json`, keyed by section name (unknown keys
  preserved as today). New sections start expanded; Economy starts collapsed. Never written into the
  filter.
- Section names: any one-line text, trimmed; empty becomes "Section"; duplicates allowed.
- Search shows matches inside collapsed sections.
- All divider edits are in memory, written by Apply, undone by Revert; RELOAD re-reads.

### Claude's Discretion
- Internal representation (section as a structure item vs metadata), settings schema details,
  banner-reading tolerance (write exactly 80 `#`; reading may be lenient as long as the `ff:` tag is
  required).

</decisions>
