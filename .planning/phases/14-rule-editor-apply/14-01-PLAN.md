<objective>
Build the entire editable model of Phase 14 as library code, before a single widget exists.

This is where roadmap success criterion 8 is actually met — "rule mutation, validation and
compilation are library functions covered by unit tests" — and where D-18/D-19 stop being
aspirations. Every later plan in this phase is a thin caller of what lands here.

ordinal-identity hazard structurally impossible instead of a bug waiting for a reorder; the

`store::save` gives D-02's autosave a crash-safe write (D-04); and the end-to-end test file proves
the milestone's motivating example (criterion 2) against real compiled filter text rather than a
bool in memory.

Output: `src/overlay/edit.rs` (new, zero egui imports), `store::save`, `tests/rule_editor.rs`.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| overlay process → `dynamic.json` on disk | The only new *write* boundary this phase opens. Single-user, local, no network, no elevation. |
| hand-edited `dynamic.json` → overlay process | Pre-existing (Phase 13's `store::load`); this phase adds a second writer to the same file. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-14-01 | Denial of Service (local) | `store::save` — a crash or power loss mid-write leaving a truncated `dynamic.json` that then fails to load, destroying the player's accumulated tuning | mitigate | D-04's `NamedTempFile::new_in(store_dir)` + `persist()`; the target file is only ever replaced by one atomic rename. | T-14-02 | Denial of Service (local) | `WorkingRules` index arithmetic — a stale id or an out-of-range swap panicking the GUI process, taking the overlay down mid-session | mitigate | Every lookup goes through `position()`/`rule_mut()` returning `Option`; `move_up`/`move_down` return `false` at the boundaries rather than indexing. Enforced by the no-`unwrap`/`expect` grep and the boundary tests in Task 1. |
| T-14-03 | Tampering | The editor writing a `style` name the emitter rejects, producing a store that no longer compiles | mitigate | `available_styles` derives the offered names from the loaded `Styles` struct, so the picker cannot offer a name `emitter::resolve_style` would reject; the optional `exceptional`/`craftable` are included only when the config defines them. |
