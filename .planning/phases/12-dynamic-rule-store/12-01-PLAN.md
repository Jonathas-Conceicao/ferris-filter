<objective>
Teach the model and emitter what a dynamic rule set needs: an `enabled` flag whose `false` value
suppresses a rule without deleting it (DYN-01), ordinal block labels that survive disabling
(DYN-02), and a parameterized filter header — then clean `dynamic_base.json` so it uses them.

`When`'s all-`Option` shape already gives DYN-04 (an absent condition emits nothing) and
`dynamic_base.json` already has zero `areaLevel` conditions, giving DYN-05. Both are verified
here with tests rather than built.

**This plan changes no output on the universal path.** `generate(&Config, &PricedData)` keeps its
exact signature and behavior, `tests/fixtures/seed-universal.filter` and the insta snapshot must
not move a byte, and nothing under `tests/` may be edited.
</objective>

**`src/models/config.rs` — `Rule` (add `enabled` here).** Note `deny_unknown_fields`: without the
field, a `dynamic.json` carrying `"enabled": false` fails to parse.

```rust
#[derive(Debug, Clone, Deserialize, Serialize, PartialEq)]
#[serde(deny_unknown_fields, rename_all = "camelCase")]
pub struct Rule {
    #[serde(skip_serializing_if = "Option::is_none")]
    pub name: Option<String>,
    pub style: String,
    #[serde(skip_serializing_if = "Option::is_none")]
    pub when: Option<When>,
}
```

The precedent to copy is `When.corrupted` from v0.3: `#[serde(default, skip_serializing_if =
"Option::is_none")]` on an `Option`, so files that omit it round-trip byte-identically.

**`src/emitter.rs` — `emit_rules` (lines ~271-290).** The `idx` from `enumerate()` feeds both the
derived label and `GenerateError::UnknownStyle`'s `rule_index`:

```rust
fn emit_rules(out: &mut String, config: &Config) -> Result<(), GenerateError> {
    for (idx, rule) in config.rules.as_deref().unwrap_or(&[]).iter().enumerate() {
        let derived_label = format!("rule {}", idx);
        let label: &str = rule.name.as_deref().unwrap_or(&derived_label);
        let style = resolve_style(&config.styles, &rule.style, idx, label)?;
        ...
```

**Critical:** skip disabled rules with `continue` **inside** the loop, so `enumerate()` still walks
the whole array. Filtering the iterator first would renumber every later rule's label — disabling
rule 2 would silently turn rule 3's block into `Show # rule 2`, breaking the traceability from a
filter block back to its index in `dynamic.json`.

**`src/emitter.rs` — `emit_header` (line ~226) and its single caller `generate` (line ~42):**

```rust
pub fn generate(config: &Config, priced: &PricedData) -> Result<String, GenerateError> {
    let mut out = String::with_capacity(32_000);
    emit_header(&mut out);
    emit_rules(&mut out, config)?;
    emit_currency_sections(&mut out, config, &priced.category_blocks);
    emit_unique_sections(&mut out, config, &priced.unique_blocks);
    ...
}

fn emit_header(out: &mut String) {
    writeln!(out, "# universal.filter").unwrap();
    writeln!(out, "# GENERATED FROM config.json — edit the model, not this file (then regenerate).").unwrap();
    // ... 8 further lines of legend + philosophy, unchanged by this plan (12-CONTEXT D-11)
}
```

`generate` has **15 call sites in `src/emitter.rs`'s own unit tests** plus one in
`src/compile.rs`. Changing its signature would churn all 16. Do not: keep `generate` exactly as it
is and add a sibling that takes the identity (see task 2).

**`src/compile.rs` — the one production caller:**
```rust
pub fn compile(inputs: &CompileInputs) -> Result<String, CompileError> {
    Ok(emitter::generate(&inputs.config, &inputs.priced)?)
}
```

**`dynamic_base.json` (repo root)** — the author's base. 10 rules, zero `areaLevel`, full styles.
Rules 4, 5, 6, 7 and 9 carry `"name": ""` — key **present**, empty string — which is why the
`unwrap_or("rule {idx}")` fallback never fires and those blocks currently emit `Show # ` with
nothing after them. `config.json` has **zero** empty names, so fixing this cannot affect the oracle.

<task number="1" name="Rule.enabled and disabled-rule suppression">
<action>
Add `enabled` to `Rule` in `src/models/config.rs`:

- `#[serde(default, skip_serializing_if = "Option::is_none")] pub enabled: Option<bool>`
- Place it first, before `name`, so it reads as the rule's top-level state.
- Doc-comment it: absent or `true` means the rule is active; `false` means it stays in the file but
  emits nothing. Note that absence is the default so existing configs are unaffected.

In `src/emitter.rs` `emit_rules`, skip disabled rules — `if rule.enabled == Some(false) { continue; }`
placed at the top of the loop body, **before** `resolve_style`. Two properties this ordering buys,
both of which must hold:

1. `enumerate()` still walks the whole array, so labels stay tied to the array index.
2. A disabled rule with an unknown style name does not raise `UnknownStyle` — it is inert, and a
   rule the user switched off should not be able to fail the build.

Add unit tests in `src/emitter.rs`:
- a rule with `enabled: Some(false)` emits no block at all (assert its style's marker and its label
  are both absent from the output)
- a rule with `enabled: Some(true)` and one with `enabled: None` both emit normally
- disabling the middle rule of three leaves the third labelled `rule 2`, not `rule 1`
- a disabled rule referencing a nonexistent style does not error

Add config round-trip tests in `src/models/config.rs`:
- `"enabled": false` parses to `Some(false)`; `"enabled": true` to `Some(true)`; an absent key to
  `None`
- a `Rule` with `enabled: None` serializes without the key (so `config.json` round-trips unchanged)
</action>
