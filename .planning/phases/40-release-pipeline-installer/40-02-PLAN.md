<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| pull request author -> CI runner | untrusted code runs in ci.yml |
| tag name -> release scripts | the ref name is attacker-influenced input for anyone who can push tags |
| CI -> GitHub Releases | write token publishes public downloads |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-40-05 | Elevation of Privilege | ci.yml | mitigate | `on: pull_request` (never pull_request_target), `permissions: contents: read`, no secrets used. |
| T-40-06 | Tampering | release.yml run steps | mitigate | Tag validated by the strict regex before any build; step outputs passed via `env:`, no `${{ }}` in run text (acceptance grep). |
| T-40-07 | Tampering | third-party actions | mitigate | actions/checkout and Swatinem/rust-cache pinned by full commit SHA; publishing uses the preinstalled `gh`, no third-party release action. |
| T-40-08 | Tampering | published assets | mitigate | Assets built only in this workflow from the tagged commit, `--locked`, clean-tree and describe==tag gates, SHA256SUMS.txt verified with `sha256sum -c` before upload. |
| T-40-09 | Repudiation / Integrity | rerun over an existing release | mitigate | Publish step deletes only a *draft* of the same tag and refuses to touch a published release. |
| T-40-SC | Tampering | floating nightly toolchain | accept | Author accepted the floating nightly (CONTEXT); `rustc -vV` is logged in every run. |
</threat_model>
