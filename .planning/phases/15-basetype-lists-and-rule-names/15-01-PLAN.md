| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-15-01 | Denial of Service (in-game) | `remove_base_type` leaving `Some(vec![])`, which the emitter writes as a malformed empty `BaseType ==` line the game fails to parse | mitigate | The `None` collapse in `remove_base_type`, pinned by the named regression test `removing_the_last_base_type_yields_none_never_an_empty_vec` and the emitted-text test `an_emptied_base_type_list_emits_no_base_type_line` (RESEARCH Pitfall 2). |
| T-15-02 | Repudiation | `rule.name = Some("")` producing `Show # ` and silently destroying the derived `rule {idx}` label that makes a filter block traceable back to its position in the store | mitigate | `set_name` normalises empty-after-trim to `None`; asserted by `set_name_on_whitespace_only_yields_none_so_the_derived_label_still_wins` and by criterion 3's own test (RESEARCH Pitfall 3). |
| T-15-03 | Tampering | A name or base type carrying a newline, injecting a second line into the emitted block | accept (structurally foreclosed downstream) | `TextEdit::singleline` drops `\n` on typed input and replaces it with a space on paste (RESEARCH Pattern 3, confirmed in egui 0.36.1's own event handling), so no sanitizing code is written here — plan 15-02 carries the criterion that neither field is a `multiline`. |
