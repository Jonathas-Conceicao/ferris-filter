Contract this plan CREATES (plans 20-04 and 20-05 consume it; names are binding):

src/filter/lineedit.rs (re-exported from src/filter/mod.rs as `crate::filter::LinePatch`)
- `#[derive(Debug, Clone, PartialEq, Eq)] pub enum LinePatch { Operator(Option<Operator>), Values(String), Both(Option<Operator>, String), Whole(String) }` (must derive these: `overlay::rules::RowAction` embeds it and derives Debug, Clone, PartialEq, Eq)
  - `Operator(Some(op))`: replace the operator range, or insert `"<op> "` before the first value when the line has none.
  - `Operator(None)`: delete the operator range plus the following run of spaces/tabs; if that would glue the keyword to the first value (no whitespace left between them), leave exactly one space.
  - `Values(text)`: replace the byte span `values.first().start .. values.last().end`; when the line has no values insert `" " + text` after the operator (or keyword). `text` must be non-empty.
  - `Both(op, text)`: the operator change then the values change, applied to the same line in ONE validated commit (needed when switching `Rarity >= Magic` to the list form `Rarity Normal Magic Rare`).
  - `Whole(text)`: raw edit of the line's content after its indent (and after the `#` prefix of a disabled block): replaces everything from the end of the indent to the end of the line text, keeping the indent, the prefix and the line's Eol. `text` must be non-empty and contain no `\n`/`\r`. This is the raw-text path for unknown-keyword (opaque) lines and for values the overlay codec cannot structure (roadmap criterion 1: no condition is read-only). Validation for `Whole` refuses only NEW Error diagnostics (a new Warning, such as one unknown keyword renamed to another, is allowed and stays flagged); every other op refuses new Errors and new Warnings.
- `impl Document`:
  - `pub fn patch_line(&mut self, id: BlockId, line: usize, patch: LinePatch) -> Result<(), EditError>`
  - `pub fn insert_body_line(&mut self, id: BlockId, after: usize, text: &str) -> Result<usize, EditError>` — `after` is a doc line index inside the block's owned range (the header or a body line); `text` is the bare content (`"ItemLevel >= 65"`); the op prepends the indent of the block's first body line (or two spaces when the body is empty) and, for a disabled block, the same `#` prefix the other lines use (structure.rs `set_continue` recipe). Returns the new line's doc index. The new line takes the Eol of the line it follows (or `fresh_eol(header)` when that line is unterminated).
  - `pub fn remove_body_line(&mut self, id: BlockId, line: usize) -> Result<(), EditError>`
  - `pub fn splice_body(&mut self, id: BlockId, remove: &[usize], after: usize, texts: &[String]) -> Result<(), EditError>` — one validated commit that removes the given body lines and inserts `texts` (bare content, same indent/prefix rules) after doc line `after` (index in the pre-edit document; must not be one of `remove`). insert/remove are thin wrappers over it.
- New `EditError` variants (UI-ready one-sentence messages, shown as status text):
  - `NotABodyLine` — "that line is not part of this rule's body"
  - `EmptyValue` — "a condition needs at least one value"
  - `CannotEditInvalidDisabled` — "this commented-out rule is not valid grammar, so its lines cannot be edited; fix it by hand"

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| overlay control -> Document | User-typed value text becomes filter-file bytes |
| Document -> game filter file | Edited text is written by the existing guarded Apply writer (unchanged here) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-20-01 | Tampering | `patch_line`/`splice_body` value text | mitigate | Refuse `\n`/`\r` (`EmbeddedNewline`) and empty values before building the candidate; re-parse the candidate block with the loader's own `parse::build`; refuse any NEW Error/Warning (`InvalidBlock`) |
| T-20-02 | Tampering | neighbouring blocks | mitigate | Commit through existing `commit` + `check_neighbours`: any re-attribution of lines to other blocks is refused (`WouldReattributeLines`) and the document stays unchanged |
| T-20-03 | Tampering | disabled blocks | mitigate | Ops on an Invalid disabled block are refused (`CannotEditInvalidDisabled`); edits to valid disabled blocks must stay enableable (`Expect.enableable`) |
| T-20-04 | Denial of Service | relaxed Warning rule | accept | Pre-existing Warnings are tolerated only if unchanged; `set_enabled` keeps the strict D-11 rule, so the tool never enables a block the game refuses |
</threat_model>
