## Design decisions made by the planner (Claude's discretion, documented)

**JSON forms (chosen after reading the serde code; existing bytes unchanged):**
- New generic `pub enum Cancelable<T> { Set(T), Cancel }` in `models/config.rs`, used as
  `minimap: Option<Cancelable<Minimap>>`, `beam: Option<Cancelable<Beam>>`,
  `sound: Option<Cancelable<Sound>>`. `None` (JSON `null`, still always written) = off.
  `Set(T)` serialises exactly as `T` did (the object), `Cancel` as the JSON string `"None"`
  (mirrors the filter keyword). Hand-written `Serialize` (Set -> `T::serialize`, Cancel ->
  `serialize_str("None")`) and `Deserialize` via a visitor: `visit_str("None")` -> Cancel (any other
  string is an error naming the expected `"None"`), `visit_map` -> `T::deserialize(MapAccessDeserializer::new(map))`
  so `deny_unknown_fields` and unknown-colour errors keep naming the bad field (do NOT use
  `#[serde(untagged)]`, it loses the field-level message). Helpers: `value(&self) -> Option<&T>`,
  `is_cancel()`. Emits: minimap Cancel -> `MinimapIcon -1`, beam Cancel -> `PlayEffect None`,
  sound Cancel -> `PlayAlertSound None`.
- `Sound` gains `#[serde(default, skip_serializing_if = "std::ops::Not::not")] pub positional: bool`
  declared AFTER `vol` -> emits `PlayAlertSoundPositional <id> <vol>`. `validate` rejects
  `positional` with `custom` (reuse `StyleError::AmbiguousSound` with problem
  `"positional set for a custom file (there is no positional form for files)"`).
- `Style` gains `#[serde(default, skip_serializing_if = "std::ops::Not::not")] pub enable_drop_sound: bool`
  (JSON `enableDropSound`, declared after `disable_drop_sound` so it lands last and only when true).
  New `pub enum DropSound { Silent, Normal }` plus `Style::drop_sound() -> Option<DropSound>` and
  `Style::set_drop_sound(Option<DropSound>)` (Silent = disable, Normal = enable, None = neither).
  `validate` rejects both true with a new `StyleError::ConflictingDropSound { style }`
  ("style \"X\" sets both disableDropSound and enableDropSound; set at most one").
  Emitter step 8 emits `EnableDropSound` at the same canonical position.
- `check_ranges` reads minimap size / sound id / vol only for `Set` values.
- `ff-proto` has its own private `Style` and is NOT touched.

**Sound folder listing:** new `src/overlay/sound_files.rs`: `pub struct SoundFolder { pub dir: Option<PathBuf>, pub files: Vec<String> }`;
`pub fn list(dir: &Path) -> Vec<String>` = one non-recursive `read_dir`, regular files only, extension
`.mp3` or `.wav` (ASCII case-insensitive; no `.ogg`: nothing in the repo or the PoE docs evidence it),
names passing `style_lines::safe_file_name`, sorted case-insensitively; an unreadable/missing dir
yields an empty list (never an error, never a write). Cached in egui context data
(`ctx.data_mut(insert_temp(Id::new("ff-sound-folder"), Arc<SoundFolder>))`):
`set_dir(ctx, Option<PathBuf>)` (lists + stores), `refresh(ctx)` (re-lists the stored dir),
`get(ctx) -> Arc<SoundFolder>` (no I/O). The folder is the parent of the loaded filter's path
(`filter_target(game_dir, name)`), falling back to `game_dir` when no filter loaded. `App` calls
`set_dir` at startup after the first `load_filter`, after a filter switch (app.rs ~1330) and in
`reload` (~2010). The sound dropdown calls `refresh` once on its closed->open click. No per-frame disk I/O.

**`/` semantics while on:** the value row that shares the `/` line (Minimap colours, Beam colours,
the Sound dropdown) stays clickable, and picking a value there leaves Cancel (restoring the
remembered Set value with that pick); the subordinate pickers (Minimap shapes and Large/Medium/Small,
Beam Temp, Volume, Positional) are drawn greyed (`add_enabled_ui(false)`) with no selection lit.

**Tinted band:** each group draws all its lines with ONE zebra index (taken once per group), so the
band reads as one block; every line keeps its own `push_id(("ed-group", tag, k))` scope.
