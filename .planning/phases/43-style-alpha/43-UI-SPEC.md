# Phase 43 - UI Design Contract

> Visual and interaction contract. Generated by gsd-ui-researcher (autonomous run, no user questions), verified by gsd-ui-checker. The target is a Rust egui overlay with the PoE2 game skin, not a web UI. Web-template fields (px scales, font weights, hex palettes) are adapted: the "design system" is `src/skin/`, and this phase adds almost no new UI. It reuses what the RULES tab already has.

## Color

Unchanged palette (Dracula tiers, skin palette). Rules for translucent colours:

| Role | Value | Usage |
|------|-------|-------|
| Preview ground | the existing dark panel ground the label preview already sits on | translucent text, border and background paint over it |
| Alpha 255 | identical pixels to today | no visual regression for existing styles |
| Alpha < 255 | straight (unmultiplied) RGBA blended over the ground | label preview and style table preview |

Accent reserved for: nothing new. The Alpha slider uses the standard skin slider look. No checkerboard in the label preview or table preview (CONTEXT.md). The picker's own colour preview strip keeps its existing checkerboard (`paint_checker_preview`), as on the RULES path, because that is the picker's alpha read-out.

## Interaction Contract

1. **Picker mode.** The style colour cards (Text / Border / Background) open the picker with `PickerMode { alpha: true, allow_none: true }`. The None tile stays for all three slots. The RULES path is unchanged.
2. **Alpha slider.** Same control as the RULES picker: slider 0-255 paired with an exact number, live edits, Escape restores the opening colour (RGBA including alpha), click outside or **Use colour** keeps it.
3. **Edits.** The picker emits `PickerEdit::Set([r, g, b, a])`. The style stores all four. A quick pick keeps the current alpha (existing `a_quick_pick_keeps_the_current_alpha` behaviour). An empty slot opens with alpha 255 as the seed. The hex field stays 6-digit RGB; alpha is edited only through the slider.
4. **Unchanged open.** Opening the picker without a change edits nothing, including alpha. Idle emits nothing.
5. **Colour card swatch.** A card holding a translucent colour paints the swatch with that alpha over the card ground (same rule as previews). Its tooltip text gains alpha: `R G B A` when it is not 255; at 255 the tooltip is unchanged. No new captions.
6. **Label preview** (`skin::editor` item-label preview, style editor and RULES Custom): text, border and background are painted with their alpha over the panel ground. Border and text at alpha 0 vanish; this is correct.
7. **Style table Preview column:** same painting rule as the label preview.
8. **Equality.** Reset to defaults "greyed at the defaults", the strictness derivation, the dirty/unapplied indicator and the ` *` marker compare full RGBA. Loading a 3-value `styles.json` yields alpha 255, equal to the 4-value form, so it shows no edit (no ` *`, no unapplied indicator, no Quit popup).
9. **Strictness row.** The levels change visibility only. They touch no colours.

No new buttons, rows, popups, status messages or tooltips beyond the swatch tooltip in item 5.

## Judgement calls

Decided without asking, per the autonomous run.

1. **Alpha for all three slots, None tile kept.** CONTEXT.md says all three slots. None stays because it is the "game default" empty state, independent of alpha.
2. **Quick picks keep alpha.** Matches the existing RULES behaviour and tests.
3. **Hex field stays RGB-only.** Alpha has its own slider; avoids 8-digit hex ambiguity.
4. **Swatch tooltip shows `R G B A` only when alpha is not 255.** Keeps existing tooltips identical and adds no standing text.
5. **No checkerboard in previews** (author decision). The picker's own preview strip keeps its checkerboard, since it already exists and is the alpha read-out.
6. **Custom rule colour editing (RULES) needs no UI change.** It already has alpha. The only change is sharing the colour type. A rule colour with 3 tokens stays 3-token while alpha is 255 (existing rule, unchanged). Style writes always carry 4 values in `styles.json`, but the filter lines for a style always say `R G B A`, as the emitter does today.
7. **Rust type is left to the planner** (CONTEXT.md discretion). Contract only: four u8 channels, read 3 or 4, written 4, equality over all four.
8. **CLAUDE.md edits required** (the planner must include a task): the `styles.json` row (colour arrays read 3 or 4 values, written 4) and the Config colour picker note (remove "styles store RGB ... no alpha"; the style picker has Alpha).
9. **Screenshot mode.** `--picker text|border|background` already exists; the planner should verify with it that the Alpha row shows on style slots. No new flag.
