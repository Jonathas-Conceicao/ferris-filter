<objective>
Close the loop: an Apply action that compiles the edited store and lands `dynamic.filter` in the
game folder, tells the player how to make the game read it, says so out loud when it fails, and —
because D-02 lets the store and the filter move independently — never leaves the player guessing
whether what they just changed is actually in the game.

Then the phase's paperwork: `CLAUDE.md` describing the editor that now exists, and the manual
checklist for the handful of things only a human at a running game can judge.

Purpose: D-15 (reuse `compile_store` + `write_filter` unchanged — Phase 12 built them print-free
and fully parameterised for exactly this second caller), D-16 (the reload instruction), D-17
(failures in the stripe, since the release binary runs under the Windows GUI subsystem with no
console), D-03 (the unapplied-changes indicator, a required part of EDIT-09 and not decoration).

Output: `src/overlay/apply.rs` (pure), the Apply affordance in `app.rs`, an updated `CLAUDE.md`,
and `14-MANUAL-VERIFICATION.md`.
</objective>

    whatever the last session left.

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-14-12 | Denial of Service (in-game) | A half-written `dynamic.filter` that the game fails to parse on Refresh | mitigate | Reuse `dynamic::write_filter` unchanged: temp file created *in the destination directory* (cross-volume rename would fail on the OneDrive path) then `persist`. Enforced by the criterion that `src/dynamic.rs` shows no diff in this plan. |
| T-14-13 | Repudiation / usability failure | A silent Apply — the player believes the filter changed when it did not, or vice versa, and blames the tool | mitigate | D-03's `ApplyState` indicator plus D-16's explicit reload instruction, both unit-tested for content in `overlay::apply`. `PITFALLS.md` §1: the game never reloads on its own, so an unstated reload requirement reads as a broken tool. |

| T-14-SC | Tampering | npm/pip/cargo installs | mitigate | No package installs in this plan. Any new dependency would require a blocking human checkpoint before `cargo add`; `egui_kittest` remains explicitly unadopted. |
