Give `ff` a hidden `--quit` flag that asks the running instance to quit through the existing
single-instance channel, so the installer can close a tray-resident `ff` before it copies files
(CONTEXT, Installer: "Upgrading over a running `ff`"). The running instance treats the request
exactly like tray Quit: it quits at once when clean, or shows its normal Unapplied changes popup.

Purpose: INST-04 (installing over a running `ff` closes it first and keeps the settings).
Output: `-quit` event + `quit_running` in `src/overlay/instance.rs`, the poll in `app.rs`, the
early branch in `overlay::launch()`.

Decisions (author's place):
- Decision (author's place): `--quit` waits up to `QUIT_TIMEOUT_MS = 10_000` for the instance to
  exit after it is ready (plus up to `STARTUP_TIMEOUT_MS` for a still-starting instance). A user
  who takes longer with the Unapplied changes popup is covered by the installer's Retry box
  (plan 40-05).
- Decision (author's place): `--quit` asks whichever FerrisFilter instance holds the name, also a
  portable copy run from another folder (there is only ever one instance per user session; the
  newly installed `ff` launched afterwards would otherwise just reveal that copy). It waits on the
  process handles of the instance processes running the same exe path; when none matches (the
  instance runs from another path, so it does not lock the installed file) it waits until the
  mutex name is gone instead.
- Exit codes: 0 = not running / exited, 1 = still running at timeout, 2 = unreachable.
- Decision (author's place): one `--quit` run sends the request once (no re-assert, unlike `-show`).
  If the user picks Cancel in the Unapplied changes popup, ff stays open; the installer's Retry runs
  `--quit` again, which reopens the popup.
</context>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| other same-user process -> `Local\` instance events | any process in the session can set the `-quit` event |
| `ff --quit` -> running instance | the launcher only asks; the instance applies its own quit rules |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-40-01 | Spoofing | `-quit` event | accept | Objects live in `Local\` with the default same-user DACL; a same-user process can already kill `ff`. The request goes through quit_step, so unapplied edits still raise the Unapplied changes popup (no data loss without the user's choice). |
| T-40-02 | Denial of Service | quit_running wait loop | mitigate | Bounded by STARTUP_TIMEOUT_MS + QUIT_TIMEOUT_MS; on timeout the request is withdrawn with ResetEvent so a later frame does not quit unexpectedly. |
| T-40-03 | Elevation of Privilege | `--quit` becoming the instance | mitigate | quit path opens, never creates, the mutex/events (acceptance grep: no acquire_named / CreateMutexW in quit_running_named; test quit_on_a_free_name_reports_not_running). |
| T-40-04 | Tampering | process matching | mitigate | Only processes whose canonical image path equals current_exe are waited on; handles opened with SYNCHRONIZE / QUERY_LIMITED only, never terminated. |
</threat_model>
