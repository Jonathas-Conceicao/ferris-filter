Add a fallible style resolver that maps a rule's `style: &str` to the matching `&Style` in

```rust
fn resolve_style<'a>(styles: &'a Styles, style: &str, idx: usize, name: &str)
    -> Result<&'a Style, GenerateError> {
    Ok(match style {
        "S" => &styles.s, "A" => &styles.a, "B" => &styles.b, "C" => &styles.c,
        "D" => &styles.d, "E" => &styles.e, "F" => &styles.f,
        "Recycle" => &styles.recycle, "unchanged" => &styles.unchanged, "hidden" => &styles.hidden,
        other => return Err(GenerateError::UnknownStyle {
            rule_index: idx, rule_name: name.to_string(), style: other.to_string() }),
    })
}
```

Study the oracle: the es-hybrid block (lines 57-64) emits `AreaLevel >= 26`, `AreaLevel <= 45`,
`Class ...`, `BaseEnergyShield > 0`, `BaseEvasion 0`, `Rarity >= Magic`. Because parity in Plan 02
is order-INSENSITIVE within a block, a single fixed field order in `emit_rules` is acceptable as
long as the SET of condition lines matches. Pick ONE deterministic order and apply it uniformly:
emit in this sequence — areaLevel(max then min), class, baseArmour, baseEvasion, baseEnergyShield,
rarity, quality, sockets, baseType, unidentifiedTier. (This is the order the old generator roughly
used; reordering is allowed by the semantic comparator but keep it stable for clean diffs.)

NUMERIC MAPPING (`NumericCondition` -> filter line for attribute `Attr`):
- `eq: Some(v)`  -> `  {Attr} {v}`            (e.g. `BaseEvasion 0`, `BaseArmour 0`)
- `min: Some(1)` and Attr is a base-defence attr (`BaseArmour`/`BaseEvasion`/`BaseEnergyShield`)
  -> `  {Attr} > 0`  (the oracle writes `BaseEnergyShield > 0`, NOT `>= 1` — base-defence `min:1`
  is rendered as `> 0` to match. Verify against oracle line 62/70.)
- `min: Some(n)` and Attr is `Quality`/`Sockets`/anything else -> `  {Attr} >= {n}`
  (e.g. `Quality >= 1`, `Sockets >= 1`)
- `max: Some(n)` -> `  {Attr} <= {n}` (for symmetry; not used by the migrated config but implement it)

Implement the base-defence `min:1 -> "> 0"` rule by branching on the attribute name inside the
numeric helper. A small helper is cleanest:

```rust
fn emit_numeric(out: &mut String, attr: &str, nc: &NumericCondition) {
    if let Some(v) = nc.eq { writeln!(out, "  {attr} {v}").unwrap(); }
    if let Some(n) = nc.min {
        let is_defence = matches!(attr, "BaseArmour" | "BaseEvasion" | "BaseEnergyShield");
        if is_defence && n == 1 { writeln!(out, "  {attr} > 0").unwrap(); }
        else { writeln!(out, "  {attr} >= {n}").unwrap(); }
    }
    if let Some(n) = nc.max { writeln!(out, "  {attr} <= {n}").unwrap(); }
}
```
