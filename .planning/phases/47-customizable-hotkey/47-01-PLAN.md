<objective>
Build the pure core of the configurable show / hide hotkey: the chord type with FerrisFilter's own
text format and the egui-key table, the capture state machine, the registrar seam with the live
runtime (start-up fallback, register-new-before-unregister-old swap, release), and the `hotkey`
key in `ff-settings.json`. No UI and no app wiring here (Plans 03 and 04 wire it).

Purpose: the layer rule (pure logic in the library, egui a thin view) and the "never register a
real OS hotkey in tests" rule both require this logic to live behind a seam with unit tests.
Output: `src/overlay/chord.rs` (new), extended `hotkey.rs` and `settings.rs`. The legacy
`register_toggle` / `release_toggle` / `TOGGLE_*` stay compiling until Plan 03 removes them.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| ff-settings.json -> overlay | a hand-edited, untrusted file supplies the `hotkey` text |
| overlay -> OS hotkey table | registering a system-wide chord affects every app on the machine |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-47-01 | Tampering | `settings::load_parts` `hotkey` | mitigate | strict own token parser (`Chord::parse`): 64-byte cap, closed token set, no `HotKey::from_str`; invalid -> None + warning, default used |
| T-47-02 | Denial of service | `Chord::is_bindable` | mitigate | refuse chords with no Ctrl/Shift/Alt (F1-F24 excepted), refuse Windows key and Escape, so a bad value cannot swallow a plain typing key system-wide |
| T-47-03 | Denial of service | `HotkeyRuntime::begin_swap` | mitigate | register new before unregistering old; failure leaves the old binding registered (no window where another app can take it) |
| T-47-04 | Tampering (data loss) | `settings::render_hotkey` | mitigate | returns Err for non-object / unparsable bytes so a damaged hand-edited file is never rewritten; unknown and wrongly typed keys are preserved |
| T-47-SC | Tampering | dependency installs | accept | no new crates; everything uses crates already in Cargo.lock |
</threat_model>
