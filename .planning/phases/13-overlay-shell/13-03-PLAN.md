<objective>
Make the summon actually work: reveal the stripe without taking keyboard focus from the game, and
hide it when the user clicks away — without the stripe hiding itself the instant it appears.

This is the highest-risk code in the phase. RESEARCH read winit 0.30.13's Windows backend directly
and found that `ViewportBuilder::with_active(false)` suppresses activation only on the **first**
reveal: winit latches a `MARKER_ACTIVATE` flag, so every later `ViewportCommand::Visible(true)`
calls `SW_SHOW` and steals focus. D-05 is therefore not satisfiable through the native API alone.
The fix is a cached raw `HWND` driving both directions with `ShowWindow`.

The second-order hazard is Pitfall 2: a window shown without activation has never been focused, so
a naive "hide when `focused == false`" hides it on the very next frame. The state machine that
prevents that is a pure library function with plain `#[test]` coverage, per `PITFALLS.md` §8.

Purpose: SHELL-02's behavioral half — "toggles overlay visibility while the game holds focus, so it
can be summoned without alt-tabbing" — plus D-05, D-06, D-14's `✕`.
Output: `src/overlay/visibility.rs` (pure, tested), `src/overlay/win.rs` (the Win32 glue), both
wired into `update()`.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| process → OS windowing | `ShowWindow` is called on **our own** window handle only, obtained from our own eframe `Frame`. No window enumeration, no `FindWindow`, no handle belonging to another process is ever obtained or touched. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-13-09 | Tampering | Raw Win32 `unsafe` calls in `src/overlay/win.rs` | mitigate | All `unsafe` is confined to one module with two functions, each a single `ShowWindow` call on a handle obtained from our own `Frame`. Enforced by the grep criterion that no `windows_sys` symbol appears anywhere else in `src/`. |
| T-13-10 | Elevation of Privilege | Conduct boundary (D-21, D-22) | mitigate | The overlay obtains no other process's window handle, reads no memory, sends no input, and installs no hook. `SW_SHOWNOACTIVATE` deliberately avoids taking focus from the game rather than manipulating the game's state. |
| T-13-11 | Denial of Service | Stripe stuck hidden or stuck stealing focus | mitigate | The decision logic is a pure, unit-tested function (Task 1) rather than ad-hoc conditionals in the view; the tray remains a second, independent way to summon or quit if the hotkey path misbehaves. |
| T-13-12 | Information Disclosure | Focus/click observation | accept-by-design | D-07 cut click-outside-dismiss precisely because it would need a system-wide input hook. The overlay observes only its own focus state via egui's `ViewportInfo`. |
</threat_model>
