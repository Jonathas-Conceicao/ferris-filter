# Phase 49 — UI Design Contract

> Visual and interaction contract for Phase 49 (Drag-and-Drop Reorder). Generated by
> gsd-ui-researcher in an autonomous run (no questions asked); every CONTEXT.md decision is binding
> and reproduced here as contract. This is a Rust / egui overlay with the PoE2 skin, not a web UI:
> "px" in the template sense means **egui points (pt)**; "texel" means a pixel of a PNG.

## Handle art geometry (ART-04 applies)

Measured from the PNG alpha (all three states): **92x92 texels, opaque plate = `[0, 0, 84, 84)`**, i.e. an 8 texel transparent gutter to the right and below (the visible plate sits up-left in the file). This is identical to the game `fouriconbutton*` art, so the existing helper applies unchanged:

- `const DRAG_HANDLE_OPAQUE: [u32; 4] = [0, 0, 84, 84];` and paint with `slice::paint_visible(painter, &skin.drag_handle[state], DRAG_HANDLE_OPAQUE, rect, tint)` (as `ff_reload_button` does with `ICON_BUTTON_OPAQUE`). Never paint the full texture into the layout rect.
- The **visible plate fills the handle rect**; hence layout rect == visible rect.

## Spacing Scale

Existing tokens reused: `ROW_H = 52` (rule row, two lines), `ROW_PAD = 10`, `ROW_HEIGHT = 34` (skin control height), `SECTION_HEADER_HEIGHT = 36`, row `item_spacing.x = 4`. New values:

| Token | Value | Usage |
|-------|-------|-------|
| handle | 28x28pt | Visible plate of the drag handle (CONTEXT: about 28pt, ~control height), scaled from 84 texels visible (0.333 pt/texel; texture rect 30.67pt). Square, no distortion |
| handle hit | 32x32pt | Sensed rect centred on the plate (`Sense::drag()` on this rect only, never the row) |
| xs | 4pt | Gap between handle and the flag cluster (existing right-to-left spacing) |
| marker | 2pt | Thickness of the drop marker line |
| edge zone | 40pt | Auto-scroll band at the top and bottom of the list viewport |

Exceptions: the handle (28pt) is below the 34pt `ROW_HEIGHT` on purpose so it reads as a row control rather than a field; it is vertically centred in its row (rule row: centre of 52pt; style row: centre of the row cell). Everything is snapped through `snap_rect` at the current `pixels_per_point` (100-200% DPI).

## Color

Palette is `src/skin/palette.rs`; **no new constants** except none required (opacity is applied by `gamma_multiply` / `from_white_alpha`).

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `pal::GROUND` / `pal::PANEL` | window and row surfaces (unchanged) |
| Secondary (30%) | `pal::ROW_HOVER`, row stripe from `row_background` | row backgrounds |
| Accent (10%) | `pal::GOLD` | the drop marker line only (new use) |
| Destructive | `pal::ERROR` | not used |

Accent reserved for (this phase): the drop marker line (2pt, `pal::GOLD`). The handle art carries its own colours and is not accent.

Source row while dragging ("greyed in place"): the row stays at its place and size (offsets must not move), drawn with a `pal::GROUND` wash at ~55% alpha over its normal paint, text and flags dimmed to `pal::DISABLED`, handle shown in its **pressed** art, no hover. Shadow: the collapsed row painted with every colour multiplied by 0.6 (`gamma_multiply(0.6)`, "~60% opacity").

## Interaction contract

### Handle widget (shared by both lists) — `ff_drag_handle(ui, skin, enabled, dragging) -> Response` in `src/skin/widgets.rs`

- Sense: `Sense::drag()` on the 32pt hit rect only. Row click / expand remains the row's own `Sense::click()` behind it (the handle is registered after, so it wins its area, as the arrows did).
- Art state: **normal** at rest; **hover** while hovered (normal while another row is being dragged); **pressed** while the pointer button is down on it / while it is the dragged handle.
- Cursor: `CursorIcon::Grab` on hover, `Grabbing` during a drag.
- Tooltip (hover, not while dragging): `Drag to reorder`. Accessible name: `Reorder` (WidgetType::Button; no keyboard path, deliberately, per CONTEXT).
- Disabled (search active on RULES): drawn dimmed (`Color32::from_white_alpha(90)`, normal art), senses hover only, tooltip `Clear the search to reorder` (the existing arrow tooltip text, reused).

### Placement

| Where | Contract |
|-------|----------|
| Rule row (RULES) | Replaces both arrows at the **right edge**: `draw_row`'s right-to-left cluster starts with the handle at `inner.max.x`, then the flags as today. `arrows_w` (flag budget input) becomes the handle width + 4, so the flag/label budget (`flag_budget`) is recomputed from it and the label keeps its 140pt minimum. Economy rows: no handle and no reserved gap beyond what the muted rows have today. |
| Style table (CONFIG) | In the **Order column**, right-aligned at the table's right edge (where the arrows hugged it). **Custom** rows: live handle. **Built-in** rows: no handle drawn, the column width is kept (reserve the same 28pt cell) so the table lines up. The column header keeps the text `Order`. |
| Section headers | Unchanged: arrows stay, no handle. |

### Drag lifecycle

1. **Start**: primary press on a live handle and a drag threshold crossed (`drag_started`). If the dragged row is the expanded one, it **collapses at that moment** (`list.expanded = None`; offsets rebuilt next frame; the dragged row's collapsed height is used for slot maths). Dragging is impossible while searching (RULES: handle disabled as above) and for economy rows (no handle).
2. **While dragging**:
   - Source row greyed in place (see Color).
   - **Shadow**: the collapsed row at ~60% opacity, drawn on a `Order::Tooltip` layer, height = collapsed row height, **x aligned to the list's left edge** (width = list content width, never follows the cursor horizontally), **y follows the pointer** (shadow centre y = pointer y, clamped to the list viewport's top and bottom). Not interactive.
   - **Drop marker**: a 2pt `pal::GOLD` line spanning the list content width, drawn between rows at the slot nearest the shadow centre. Slot = boundary of the virtual list's offsets (`offsets[i]`); only valid slots are marked, an invalid position shows no marker and no move on release.
   - **Wheel**: the mouse wheel keeps scrolling the list during the drag (the drag does not capture scroll; spike early per CONTEXT).
   - **Auto-scroll**: within 40pt of the viewport's top or bottom the list scrolls toward that edge; speed grows linearly from 0 at 40pt to a maximum of 900pt/s at the edge (time-based: `dt * speed`, using `ui.input(|i| i.stable_dt)`), and the app requests a repaint every frame while a drag is active (`ctx.request_repaint()`).
   - Section collapsed headers are valid targets (drop on the header: the rule becomes the first rule of that section, header gets the marker highlight as a 2pt gold line below it); expanded headers: the slot just below the header is the section's first slot, the slot above it is the end of the previous section. Nothing lands in or below the economy section: slots at or after the economy header are invalid (no marker). Custom styles: slots above the end of the built-in block are invalid (no marker); the marker never appears above the first custom row.
3. **Drop**: pointer release over a valid slot emits **one** action (`RowAction::MoveTo` for rules; the style equivalent for styles) = **one pending edit** (Apply writes it, Revert undoes it, tab shows ` *`). A grouped rule (`# ff:group`) moves as one unit; a move across a Continue rule is flagged `moved across Continue` as with the arrows. The moved row is scrolled into view / kept (reuse `pending_scroll`). Status line: no new message (the edit just marks unapplied).
4. **Cancel**, with no change: release outside the list viewport, Escape, window hidden, window loses focus. Release on the source's own slot (no net move) is a no-op that emits nothing.

Escape while a drag is active is consumed by the drag (it must not also collapse a row or clear the search).

### Interaction summary

| Control | Press | Hover | Drag | Release |
|---------|-------|-------|------|---------|
| Handle (live) | start threshold | hover art, grab cursor, `Drag to reorder` | pressed art, grabbing cursor, shadow + marker | move (valid slot) or cancel |
| Handle (search active) | none | dimmed, `Clear the search to reorder` | none | none |
| Built-in style row / economy row | no handle | n/a | n/a | n/a |
| Section header arrows | unchanged | unchanged | unchanged | unchanged |

## Verification hooks (for planner and auditor)

- Pure `drag_reorder.rs` (shared by both lists), unit-testable without egui: slot from pointer y over `offsets` (nearest boundary), validity (economy boundary, built-in block, banner rules, collapsed-header target), shadow y clamp, auto-scroll speed `f(distance_to_edge, dt)` (0 beyond 40pt, linear, max 900pt/s), no-op detection.
- Geometry tests in house style: handle plate rect from a cell, 28pt visible size, UV equals `box_uv(size, [0,0,84,84])`, shadow rect left == list left.
- `--screenshot` is a one-shot render, so the drag state needs a debug-only injection flag (suggested: `--drag <row-index>:<slot>` painting the greyed source, shadow and marker); add it to the screenshot flag list in CLAUDE.md. Also confirm via screenshots: `--tab rules` (handles right edge, economy rows without), `--tab config --expand-style X` (Order column, built-in rows blank cells aligned).
- Existing tests asserting arrows on rule/style rows (`arrows_do_nothing_when_reorder_is_disabled_and_work_when_enabled`, `custom_arrows_reorder_and_builtin_arrows_are_disabled`, Order-cell arrow-position test in `config_view.rs`) are rewritten for the handle; section-header arrow tests stay.
- Moves go through a new `Document::move_run_to` (not `move_rule`'s per-step Continue toggling); the Continue flag is computed once from the crossed rules.

## Judgement calls (autonomous run; flag for the author's review)

1. **Plate bounds measured, not assumed**: all three PNGs have opaque box `[0,0,84,84)` of 92x92 (8 texel gutter right and below), the same as `fouriconbutton*`, so `slice::paint_visible` with the same opaque box is reused.
2. **28pt visible plate, 32pt hit target**: CONTEXT says ~28pt; the hit rect is larger for a forgiving press, as the arrows' padded target did.
3. **Source row greyed by wash plus dimmed text, handle in pressed art**: CONTEXT only says "greyed in place"; no new palette constant, reuse `pal::GROUND` and `pal::DISABLED`.
4. **Shadow clamped to the list viewport vertically**: avoids a shadow flying over the header/tab bar while auto-scrolling.
5. **Auto-scroll max 900pt/s**: ~17 rows per second at the edge; a chosen default for the "faster closer to the edge" requirement, tunable by the author.
6. **Drop on an expanded header**: treated as the section's first slot (slot below the header) rather than a special case; only collapsed headers are drop targets of their own, per CONTEXT.
7. **Marker is gold, 2pt, full content width**: `pal::GOLD` is the existing accent; 1pt would vanish at 100% DPI between stripes.
8. **Escape consumed by the drag**: so cancelling a drag does not also clear a search or collapse a row.
9. **Built-in style rows reserve an empty 28pt cell**: keeps the Order column aligned, as the greyed arrows did, without showing a dead control.
10. **Tooltip `Drag to reorder`**: the only new string; the author prefers tooltips over captions, and the handle art alone is not self-explanatory.
11. **Debug-only `--drag` screenshot flag suggested**: needed to verify the drag visuals; compiled out of release like the other screenshot flags.
