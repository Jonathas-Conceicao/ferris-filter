<objective>
Make the generate pipeline callable as a library API (CORE-01), take every input path from the
caller (CORE-02), and return expected failures as one typed error enum plus the price-source
decision as a value (CORE-04).

The crate already has a `[lib]` target and both binaries are already thin shims — that part of
the phase was already done before this milestone started (see 11-CONTEXT.md `<domain>`). The
actual blocker is that `run::cmd_generate` is private, hardcodes four CWD-relative paths, writes
its own output and prints its warnings, so no second front end can reuse it.

Output: a new `src/compile.rs` exposing a two-stage API — `load_inputs` (all IO, all expected
errors, reports which price source it used) and `compile` (pure) — with `run::cmd_generate`
rewired onto it and producing byte-identical CLI behavior.

**This plan changes no emitted filter text.** `tests/fixtures/seed-universal.filter` and the
insta snapshot must not move by a single byte, and `tests/cli_errors.rs` must pass unmodified.
</objective>

**`src/loader.rs` today** — three functions, all returning `miette::Result`, all called ONLY
from `src/run.rs` (verified: `grep -rn "loader::" src/ tests/` matches nothing else). This is
what makes retyping them safe and contained.

```rust
pub fn load_json<T: serde::de::DeserializeOwned>(path: &str) -> miette::Result<T>
pub fn load_prices_optional(path: &str) -> miette::Result<Option<PricesFile>>
pub fn load_tiers(path: &str) -> miette::Result<ValidatedTiers>
```

`load_json` produces exactly two failure shapes:
- unreadable file → `miette::miette!("Cannot read `{path}`: {e}")`
- malformed JSON → `JsonLoadError { file, field_path, cause, src, location }` (from
  `src/error.rs`, a `#[derive(Error, Debug, Diagnostic)]` struct carrying `#[source_code]` and
  `#[label]` so miette renders a source span)

`load_prices_optional` returns `Ok(None)` when the file does not exist — **absence is not an
error**, it is the fallback path. Preserve that distinction exactly.

`load_tiers` calls `ValidatedTiers::try_from`, surfacing `TierValidationError`.

**Existing typed error enums to wrap — all three already derive `Diagnostic`,** so
`#[diagnostic(transparent)]` forwards their rendering unchanged:

```rust

// src/emitter.rs:21

```

**`src/pricer.rs` — the two calls the load stage must make:**

**`src/run.rs` `cmd_generate` today** — the exact behavior to preserve. Read the file; these are
the observable strings, in this order:

| # | Stream | Exact text | When |

| 1 | stderr | `note: --early-game — using prices-fallback.json + tiers-fallback.json` | `--early-game`, printed BEFORE any loading |

<task number="2" name="Callable two-stage compile API">
<action>
Create `src/compile.rs` and register it in `src/lib.rs` with `pub mod compile;` (keep the
existing alphabetical-ish grouping).

Define, with doc comments explaining each:

- `pub struct InputPaths` with `PathBuf` fields `config`, `prices`, `tiers`, `prices_fallback`,
  `tiers_fallback`. Give it `pub fn relative_to(root: impl AsRef<Path>) -> Self` producing the
  conventional names (`config.json`, `prices.json`, `tiers.json`, `prices-fallback.json`,
  `tiers-fallback.json`) joined to `root`, and `pub fn with_config(self, p: impl Into<PathBuf>)
  -> Self` for `generate --config`. **These names appear here and nowhere else in the library** —
  this struct is the single place conventional filenames are spelled.
- `pub enum PriceSourcePolicy { Auto, ForceFallback }` — the caller's intent. `ForceFallback` is
  what `--early-game` maps to. Deliberately not a bare `bool`, so the GUI reads at the call site.
- `pub enum PriceSource { Live, Fallback(FallbackReason), Absent }` and
  `pub enum FallbackReason { Forced, LiveMissingOrEmpty }` — what actually happened. Derive
  `Debug, Clone, PartialEq, Eq`.
- `pub struct CompileInputs { pub config: Config, pub priced: PricedData, pub price_source: PriceSource }`
- `pub enum CompileError` deriving `#[derive(Debug, Error, Diagnostic)]`, with variants:
  `Load(LoadError)` (`#[error(transparent)]` + `#[diagnostic(transparent)]` + `#[from]`),
  `Rates(PriceRateError)` (same treatment), `Generate(GenerateError)` (same treatment), and
  `ForcedFallbackMissing { path: String }` whose message reproduces today's
  `--early-game requires prices-fallback.json, which is missing` (parameterized on the path).

- `pub fn load_inputs(paths: &InputPaths, policy: PriceSourcePolicy) -> Result<CompileInputs, CompileError>`
  — moves the whole selection ladder out of `run::cmd_generate` verbatim in behavior:
  * `ForceFallback` → load `paths.prices_fallback`; absent → `ForcedFallbackMissing`; then load
    `paths.tiers_fallback`; `price_source = Fallback(Forced)`.
  * `Auto` → load `paths.prices`; if `Some` and `!items.is_empty()` → load `paths.tiers`,
    `price_source = Live`. Otherwise try `paths.prices_fallback`: present → load
    `paths.tiers_fallback`, `price_source = Fallback(LiveMissingOrEmpty)`; absent → load
    `paths.tiers`, `price_source = Absent`.
  * Then: `Absent` → `PricedData::empty()`; otherwise `pricer::derive_rates` then
    `pricer::price_tiers`.
  * Config is loaded from `paths.config` first, exactly as `cmd_generate` does today.
  * **No `println!`/`eprintln!` anywhere in this function or this module.**
- `pub fn compile(inputs: &CompileInputs) -> Result<String, CompileError>` — thin wrapper over
  `emitter::generate(&inputs.config, &inputs.priced)`, mapping its error. No IO.

Add unit tests in `src/compile.rs` covering: `relative_to` joins the five conventional names to a
root; `with_config` overrides only the config path; `load_inputs` on a temp dir with live prices
reports `PriceSource::Live`; with prices absent but fallback present reports
`Fallback(LiveMissingOrEmpty)`; with both absent reports `Absent`; `ForceFallback` with the
fallback missing returns `ForcedFallbackMissing`. Use `tempfile` (already a dependency) and the
committed fixtures as inputs — never the repo-root `prices.json` (see PITFALLS §5).
</action>

<threat_model>
Pure internal refactor of a local CLI that reads local JSON and writes a local text file. No new
network, process, deserialization or authentication surface: `sync` (the only network path) is
untouched, and no new input format is introduced.

- **Path handling (low).** `InputPaths` widens where input paths come from — the caller rather
  than four literals. The CLI keeps passing `"."`-relative defaults plus the user's existing
  `--config` value, so its exposure is unchanged from today. The library performs no path
  canonicalization or traversal checks and should not start: callers supply paths they already
  control, exactly as `--config` and `--output` already work (T-02-03 in Phase 2 settled this for
  `--output`).
- **Error messages (low).** `CompileError` variants embed file paths in messages, as today's
  errors already do. No secrets or credentials pass through this code.
- No blocking or high-severity threats. Nothing here warrants a mitigation task.
</threat_model>
