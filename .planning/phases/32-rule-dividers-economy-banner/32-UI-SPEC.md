# Phase 32 — UI Design Contract

> Visual and interaction contract for section headers (dividers) and the locked Economy section in the RULES list. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> Rust egui/eframe overlay: "px" means egui logical points (pt); the design system is the in-repo `src/skin/`. This spec EXTENDS `31-UI-SPEC.md` (and through it `30-UI-SPEC.md`): palette, Fontin sizes 14/15/17/21, spacing tokens, `ROW_PAD` 10, 535pt content width (517 inside the scrollbar reserve). Where silent, Phase 31 applies. NO new colours, sizes, faces or art files. Sources: 32-CONTEXT.md (locked, incl. the approved mockup), REQUIREMENTS SECT-01..05, 31-REVIEW WR-02, memory note "Overlay UI not texty". Items marked "(Claude's decision)" were decided here without user input.

## Section Header Row (SECT-01, SECT-02, SECT-03)

Fixed-height row so `virtual_list` keeps its prefix offsets: **section header = 36pt** (Claude's decision; shorter than the 52pt rule row so sections read as dividers, not rules). No expansion editor; renaming is inline in the header.

Ground: `pal::PANEL` with a 1pt top rule and 1pt bottom rule in `pal::INPUT_BORDER`; hover `pal::ROW_HOVER`. The alternating ROW_EVEN/ROW_ODD ground of rule rows is unaffected: rule rows alternate by their position among visible rule rows and a header does not count. This makes headers visually distinct from rules without any new colour.

Anatomy, left to right inside the content width (`ROW_PAD` 10 each side):

| Slot | Contract |
|------|----------|
| Collapse chevron | painted `chevron` icon, 16pt glyph in an 18pt hit rect, `pal::LABEL`; right-pointing when collapsed, down-pointing when expanded; tooltip `Collapse` / `Expand` |
| Name | `small_caps(17)`, `pal::HEADING`, 8pt after the chevron; single line cut with "…". Shown in the source's case (the font small-caps it); empty name is never shown (stored as `Section`) |
| Rule line | a 1pt `pal::INPUT_BORDER` horizontal line vertically centred on the row, running from name end + 8pt to count start - 8pt (the mockup's `-----`). Omitted when it would be shorter than 16pt |
| Count | `regular(15)`, `pal::MUTED`, `{n} rules` (`1 rule` for one, `0 rules` for none), right-aligned before the cluster, 8pt gap. Counts rules (a `# ff:group` run is one rule), not blocks, not a range |
| Right cluster (user sections) | right-to-left: remove (`ff_icon_button` x), 4pt, down `ff_arrow`, 4pt, up `ff_arrow`, 4pt, rename (pencil `ff_icon_button`), then `ROW_PAD`. Icon-only; tooltips: `Remove section (its rules stay)`, `Move section down`, `Move section up`, `Rename section` |
| Right cluster (Economy) | a single padlock icon (existing amber-free variant: `pal::MUTED` outline, 16pt in 18pt hit rect), tooltip `Generated by FerrisFilter. Read-only; refreshed by Apply.` Count reads `{n} rules`. No rename, arrows or remove |

Interaction:

- Click anywhere on the header (not on the cluster) toggles collapse; Enter/Space on the focused header does the same. Chevron click is the same action.
- Collapsed hides every rule row up to the next header; the header and count stay. Count is always shown, collapsed or not.
- Up/down arrows move the divider line one rule at a time (a `# ff:group` run counts as one step); disabled (dimmed) when the divider cannot move further (already at top; last position directly above the Economy header or end of editable rules). Disabled while a search query is active, same as rule arrows (tooltip unchanged style: `Clear the search to reorder`).
- Remove deletes only the divider line; its rules join the section above (or become headerless at the top). No confirmation popup (nothing but a comment is lost and Revert undoes it). Status (Ok): `Section removed. Its rules joined the section above.` (Claude's decision)
- Rename: clicking the pencil, double-click on the name, or `+ Add section` swaps the name for an `ff_text_field` (30pt, width = name slot up to 220pt, hint `Section name`) with focus and text selected. Enter or focus loss commits (trimmed; empty becomes `Section`; one line only, newlines stripped; duplicates allowed); Escape cancels. Committing marks the filter unapplied like any edit; no inline validation messages are needed.
- Collapsed state is per filter in `ff-settings.json`, keyed by section name; it does not mark the filter unapplied and is saved on toggle. New sections start expanded; Economy starts collapsed. Renaming carries the collapsed flag to the new name (Claude's decision). Duplicate names share one collapsed state (accepted consequence of name keys).
- Keyboard: header is focusable (same focus ring as rule rows, `INPUT_BORDER_HOT` 1pt outline).
- Accessible names: `Section {name}, {n} rules, collapsed|expanded`.

Focal point of the tab stays the expanded rule's outline, otherwise `+ Add rule`; section headers are secondary landmarks, no gold fill.

| Aspect | Contract |
|--------|----------|

## Rule Rows Under Sections

- Rule rows are unchanged from Phase 31 (52pt, same anatomy). Rules above the first divider have no header and sit flush at the top. Rules in a section are NOT indented (the 535pt budget in Phase 31 stays valid); membership is shown by the header above and the alternating ground.
- Rule indices (`1`, `2`, ...) stay file-wide and continuous across sections; sections do not restart numbering.
- Reorder arrows move a rule across a divider (it lands in the adjacent section); the rule's `moved across Continue` flag logic is unchanged. A divider cannot split a group: the group steps as one.
- Rows below the last editable rule and above the Economy header need no spacer.

### Expanded rule bottom row (SECT-02)

Final line is `Section above` + `Duplicate` + `Delete`: three `ff_button`s, widths 128 / 112 / 112 with 8pt gaps (fits 360pt of the 535 control width); `Delete` stays the danger variant and rightmost.

| Aspect | Contract |
|--------|----------|
| `Section above` | `ff_button("Section above", 128)`; tooltip `Inserts a section divider directly above this rule.` |
| Behaviour | inserts a divider named `Section` directly above this rule (above the whole `# ff:group` run for grouped rules), opens its name field with focus, collapses the rule editor (one-at-a-time expansion keeps the rule expanded; list scrolls so the new header and the rule are visible). Status (Ok): `Section added above rule {index}. Press Apply to save it.` |
| Disabled | dimmed when the rule is in the Economy section (no editor there anyway) |

## Search (SECT-05)

- Matching rows inside a collapsed section are shown (the section temporarily renders as expanded for display only: chevron shows the expanded state and the header remains clickable; the saved collapsed state is untouched).
- While a query is active, a header is shown only if its section has at least one match; its count is the match count in the form `{m} of {n} rules` (`regular(15)`, `pal::MUTED`). Headers with zero matches are hidden. Rules above the first divider have no header. The Economy header follows the same rule.
- Empty state unchanged: `No rules match "{query}"`.
- Section names are not searched (Claude's decision; context lists only rule fields).
- Reorder arrows (rules and dividers) remain disabled while searching.

## WR-02 Hint (31-REVIEW, non-blocking)

Decision (Claude's decision, narrowed after the UI check): include a cheap, text-free mitigation, no behaviour change, no popup. A **presentation-only amber warning marker** (the existing warning-triangle glyph, `pal::WARN`) joins the collapsed row's flag cluster when ALL hold: the rule is enabled, has no conditions, is not `Continue`, and at least one enabled user rule follows it (economy rows excluded). Tooltip: `This rule has no conditions, so it matches every item and the rules below it never apply.` Accessible name `matches every item`. The neutral empty-summary text stays as it is. `flags_for` output is unchanged (the marker is computed separately), errors are never folded away by it, and Apply is never blocked. A condition-less catch-all at the end of the list or a condition-less Continue layer gets no marker.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | `+ Add section` (new), `+ Add rule` (existing); `Apply` remains the window primary |
| Default section name | `Section` |
| Empty state heading | `No rules yet` (unchanged; a file with only dividers also reads this when no rules exist in any section; headers are still listed) |
| Empty search | `No rules match "{query}"` (unchanged) |
| Count | `{n} rules` / `1 rule`; during search `{m} of {n} rules` |
| Add status | `Section added at the top. Press Apply to save it.` / `Section added above rule {index}. Press Apply to save it.` |
| Remove status | `Section removed. Its rules joined the section above.` |

| Tooltips | `Collapse` / `Expand`, `Rename section`, `Move section up`, `Move section down`, `Remove section (its rules stay)`, `Inserts a section divider directly above this rule.`, `Adds a section divider at the top of the list.`, `Generated by FerrisFilter.
