<objective>
Give the overlay its two summon inputs — a system tray icon with a menu, and a global `Shift+Z`
hotkey — and prove that both actually deliver events to the egui `update()` loop while another
application holds keyboard focus.

Deliberately **no visibility logic here**. Both inputs set a single `toggle_requested` flag and a
temporary on-window counter proves the events arrive. The real show/hide mechanism is plan 13-03,
and separating them is what makes a failure legible: if the counter does not increment, event
delivery is broken; if it increments but the window misbehaves, the focus mechanism is broken.

Purpose: SHELL-02's input half — the thread-affinity and event-delivery mechanics, isolated from
the harder focus-management problem.
Output: `src/overlay/tray.rs`, `src/overlay/hotkey.rs`, `assets/ferris.png`, tray + hotkey wired
into `OverlayApp::update`.
</objective>

      and `global_hotkey::hotkey::Code::KeyZ`, with a doc comment recording D-09's accepted trade:
      `Shift+Z` is captured in every application on the machine, including PoE2's chat box, and
      changing it is a one-constant edit.
    - `pub enum HotkeyStatus { Registered { id: u32 }, Failed(String) }` — a value, not a printed
      message, matching this crate's rule that the library reports and the caller presents.
    - `pub fn register_toggle() -> (Option<GlobalHotKeyManager>, HotkeyStatus)` constructing the
      manager, building `HotKey::new(Some(Modifiers::SHIFT), Code::KeyZ)`, registering it, and
      returning `HotkeyStatus::Failed` carrying the error text when either step fails. Never `unwrap`
      — another application already owning the combo is an expected outcome, not a crash.

    Call `register_toggle()` from the same app-creation closure that builds the tray (same
    thread-affinity constraint), and store the `GlobalHotKeyManager` in `OverlayApp` — dropping the
    manager unregisters the hotkey.

    Surface the status through the tray (D-10): when `HotkeyStatus::Failed`, set the tray tooltip to
    a message naming the combo and the reason (e.g. `FerrisFilter — Shift+Z unavailable: <error>`)
    and append a disabled menu item carrying the same text, so the failure is visible from the tray
    alone with no console. On success the tooltip states the working combo
    (`FerrisFilter — Shift+Z to toggle`). Extend `tray::build` to take the tooltip and an optional
    status line rather than hardcoding either.

    In `update()`, poll `global_hotkey::GlobalHotKeyEvent::receiver().try_recv()`; accept the event
    only when `event.id == registered_id` **and** `event.state == HotKeyState::Pressed` (otherwise
    every press fires twice, on press and release), then set `toggle_requested = true` — the same
    flag the tray's left click sets, so both inputs share one path.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| OS input → process | `RegisterHotKey` delivers `WM_HOTKEY` for one specific combo to our own hidden hook window. This is a targeted registration, **not** a keyboard hook: no other keystroke is observable to this process. |
| filesystem → binary | `assets/ferris.png` is compiled into the exe via `include_bytes!`, so no icon file is read from disk at runtime. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-13-05 | Information Disclosure | Global hotkey registration | mitigate | `RegisterHotKey` (via `global-hotkey`) receives only the registered combo. No `SetWindowsHookEx`, no `GetAsyncKeyState` polling, no keylogging surface — D-22's conduct boundary is held by choosing a registration API over a hook API. Enforced by the `grep` criteria that no input-hook API appears in `src/overlay/`. |
| T-13-06 | Denial of Service | Hotkey already owned by another app | mitigate | Registration failure returns `HotkeyStatus::Failed` and is surfaced in the tray tooltip and menu (D-10); the overlay stays usable via the tray. No panic, no silent no-op. |
| T-13-07 | Spoofing | Tray icon asset provenance | mitigate | `assets/ASSETS.md` records source URL and license per asset; an image whose license cannot be stated is not committed. |
| T-13-08 | Tampering | Game process | accept | Out of scope by construction: this plan calls no API that reads, writes or injects into another process (D-21, D-22). |
</threat_model>
