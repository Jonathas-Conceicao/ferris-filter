# Phase 33 — UI Design Contract

> Visual and interaction contract for the CONFIG tab's style table, the line-by-line style editor and the shared skinned colour picker. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> Rust egui/eframe overlay: "px" means egui logical points (pt); the design system is the in-repo `src/skin/`. This spec EXTENDS `32-UI-SPEC.md` / `31-UI-SPEC.md` / `30-UI-SPEC.md`: palette, Fontin sizes 14/15/17/21, `ROW_PAD` 10, `ROW_HEIGHT` 34, 535pt content width (517 inside the scrollbar reserve). Where silent, Phase 31/32 applies. NO new colours, sizes, faces or art files. Sources: 33-CONTEXT.md (locked), CLAUDE.md, memory note "Overlay UI not texty", and (reconciled against the code) `src/overlay/config_view.rs`, `body.rs`, `overlay/widgets.rs`, `skin/{editor,widgets,minimap,popup}.rs`, `bin/ff-proto.rs`, `assets/poe2/manifest.toml` and the prototype screenshots. Items marked "(Claude's decision)" were decided here without user input (non-interactive run).

## Scope and Boundaries

- IN: style table header and rows (Built-in and Custom), expanded style editor, the colour-picker popup, replacing the RULES colour swatches with it.
- OUT: TIERS (stays in CONFIG, still on its current widgets); sound preview (backlog 999.15); changing the style model (ids, in-memory edits, one all-or-none Apply, Revert, `StyleEdit` / `ConfigAction` stay as they are); the Filter section.
- Reconciliation: the CONFIG Styles area today uses the legacy `overlay::widgets` / `theme` look (`zebra_row`, `slide_switch`, `style_preview_chip`, `circular_toggle`, `egui::ComboBox`, `colour_swatch`). This phase moves the Styles table and editor onto the skin widgets named above; `slide_switch` (32x16) is kept for the Visibility column because no skin switch exists (it is not a panel or frame). `ConfigViewCtx.skin` is `Option<&Skin>` (None in headless tests): the new code takes `skin::of(ui.ctx())` like `body.rs` does, so tests keep working without the option.

## Style Table

Focal point: the first Built-in row (`S`) and its Preview label; the table has no other emphasis.

Built from `ui.available_width()` (517pt at the real window; never hard-code 517). Row inner width = available - 2 x `ROW_PAD` (497pt). Columns are separated by an 8pt gap (replaces today's `COL_VISIBILITY` 80 / `COL_NAME` 104 / `COL_PREVIEW` 120 / `COL_ORDER` 64 constants and `item_spacing.x` 4, which leave the table only ~400pt wide).

| Column | Width | x-start in the row (517pt) | Contract |
|--------|-------|----------------------------|----------|
| Visibility | 64 | 10 | `widgets::slide_switch` (on = Show), tooltip `SWITCH_TIP` ("On: shown. Off: hidden (Alt reveals)."); no Show/Hide caption anywhere |
| Name | flexible: 150 at 517 (`available - 64 - 32 - 160 - 56 - 4 x 8 - 20`, minimum 110) | 82 | built-in: `small_caps(17)` `pal::VALUE`, truncated with "…", tooltip is the full name, no hover affordance; custom: `ff_text_field` (30pt tall, width = column, hint `Style name`), commit on Enter/blur, Escape restores, red `INVALID_RED` outline + tooltip from `rename_hint` as today (rename keeps rules linked by id) |
| Icon | 32 | 240 | `paint_minimap_icon(.., minimap::icon_points(size, 24), tint WHITE)` centred in the cell, shape/colour indexed via `minimap::SHAPES` / `COLOURS` (`index_of`); nothing painted when the style has no minimap |
| Preview | 160 | 280 | `ff_item_label` (painter, 26pt tall rect) with `LabelLook` from the style (text/border/background; `font_size: None` so the preview does not grow the row; `hidden: true` for Hide styles), sample text `Item Name`. Replaces `style_preview_chip` |
| Order | 56 | 448 | `ff_arrow(up)` and `ff_arrow(down)`, 4pt gap, right-aligned in the cell |

Header row (one per group, directly under the group heading): 24pt, `regular(14)`, `pal::MUTED`, labels `Visibility`, `Name`, `Icon`, `Preview`, `Order` at the x-starts above (Order right-aligned over the arrows), 1pt `pal::INPUT_BORDER` rule under it. Replaces `styles_table_header` (which today omits Icon and, for Built-in, Order). Not clickable. The Custom header is shown only when there are custom styles or a draft row (as today, nothing for a header to label otherwise).

- Group headings **Built-in** / **Custom** keep the existing caption slot (`caption_text`, becomes `small_caps(15)` `pal::LABEL`); the Custom heading carries `ff_button("+ Add style", 124)` right-aligned (replaces the `+ ADD STYLE` small button), shown even with no custom styles. The `style_draft_row` (name field + `Add style` / `Discard new style`) keeps its behaviour, re-skinned with `ff_text_field` and two `ff_button`s (112 / 168).
- Built-in rows draw both arrows at the same position, disabled (`enabled = false`, dimmed, no click), tooltip `Built-in styles keep their order`. Custom rows: Up disabled on the first, Down on the last (existing `Some((can_up, can_down))`).
- Row height 34 (`ROW_HEIGHT`), ground `pal::ROW_EVEN`/`ROW_ODD` by index inside each table via `row_background` (replaces `zebra_row` and `theme::ROW_BASE`), `ROW_HOVER` on hover. Expanded row: 1pt `pal::GOLD` outline around the row plus its editor.
- Click target: the row except the switch, arrows and (custom) the Name field, as today. Enter/Space on the focused row toggles; focus ring `INPUT_BORDER_HOT` 1pt. One expanded at a time (`ConfigUi::set_expanded`).
- Accessible name: `Style {name}, {Show|Hide}, expanded|collapsed` (existing `CollapsingHeader` info).

## Style Editor (expanded, line by line)

Focal point: the Label preview line (line 2), the largest, most colourful element; everything else is quiet rows.

Rendered by `style_editor` directly under the expanded row (replaces the `egui::Frame` with `theme::ROW_BASE` and 8pt margin: no frame, no cards, no captions boxes). Each line is one `skin::widgets::ff_field_row(ui, index, label, tip, ..)`: label in the 128pt column (`small_caps(17)` `pal::LABEL`, `ROW_PAD` 10 left), control starting at 154pt and ending at 507pt, so the control width is **353pt** at the real window. Lines are 34pt (taller when a control wraps). This is the same line form as the RULES editor. No NAME line (the name is in the row; the `RENAME_TIP` moves onto the built-in Name cell tooltip: `Built-in names are fixed. Rename a custom style in its table row.`).

| # | Label | Controls (all within 353pt) |
|---|-------|-----------------------------|
| 1 | `Visibility` | `ff_segmented(.., &["Show","Hide"], 128)`; edits `StyleEdit::Action` |
| 2 | `Label` | the preview: `ff_item_label` in a 353 x 44pt rect, sample text `Item Name`, using the style's text/border/background, `font_size` from the Font size line (so it grows with the slider, clamped by the preview scale) and `hidden` for Hide |
| 3 | (empty label) | `ff_colour_card` x3, 110pt each with 8pt gaps (346pt): `Text`, `Border`, `Background`; a slot with no colour shows `Text (none)` on the dark ground (existing widget behaviour). Click opens the picker for that slot |
| 4 | `Font size` | `ff_check` (override on/off, seed 32 on, `None` off; tooltip `Font size override; off uses the game default`) then `ff_slider` 1-45 step 1 filling the rest; its right-hand value text replaces the number field; Left/Right keys step 1. Emits `StyleEdit::Font`. Hint `body::font_hint` stays a tooltip on the slider, not a line |
| 5 | `Minimap` | `ff_segmented(.., &["None","Large","Medium","Small"], 288)`; None = `style.minimap: None`, Large/Medium/Small = `size` 0/1/2 (`minimap::SIZES`); switching from None seeds `size 0, White, Circle` unless a session-remembered value exists |
| 6 | (empty label, only when size is not None) | 11 `ff_swatch(Some(minimap::SWATCHES[i]), selected, 24x24, name)` with 4pt gaps (11 x 24 + 10 x 4 = 304pt); the selected one shows the existing `pal::HEADING` ring (the widget's selected look) |
| 7 | (empty label, same condition) | 12 `ff_icon_button(ui, skin, shape, current_colour, selected, 24)` with 4pt gaps (12 x 24 + 11 x 4 = 332pt, one row); tooltips are the shape names (built in) |
| 8 | `Beam` | a `none` `ff_swatch(None, ..)` then the 11 colour `ff_swatch` tiles, all 24pt with 4pt gaps (12 x 24 + 11 x 4 = 332pt); then `ff_chip("Temp")` (disabled/dimmed while none is selected). Temp wraps to a second line inside `ff_field_row` (353pt cannot hold it): accepted |
| 9 | `Sound` | `ff_dropdown` 150pt over `None`, `Alert 1` ... `Alert 16`, `Custom file`; with Custom file selected an `ff_text_field` 150pt (hint `uwu.mp3`) follows (308pt total). Edits `StyleEdit::Sound` (new alert id defaults 1, volume 100; custom default `uwu.mp3`; existing value kept when switching within a mode) |
| 10 | `Volume` | `ff_slider` 0-300 step 1, hidden when Sound is None. No number field |
| 11 | `Drop sound` | `ff_check` toggling `disable_drop_sound` (existing `StyleEdit::DisableDropSound`); tooltip `Silence the default drop sound`; the model field stays editable (it was not in the prototype) |
| 12 | (Custom only, last) | `ff_button_ex("Delete style", .., danger)` 128pt, preceded by 12pt of space. Click sets `cfg.arm_delete(name)`, which opens the existing `Popup::DeleteStyle` |

Behaviour:

- Every control emits the same `ConfigAction::EditStyle` as today; edits are in memory, mark CONFIG unapplied, nothing is written until the shared Apply; Revert (existing `Discard config changes?` popup) undoes them.
- Built-in styles are editable except rename, move and delete (no line 12).
- Visibility Hide keeps all visuals (Alt-reveal).
- Switching Minimap to None / Beam to none / Sound to None clears the model value but keeps the last values in egui temp memory for that row so switching back restores them (Claude's decision).
- A load error (`state.styles_error()`) still shows one `pal::WARN` line at the bottom of the editor.
- Keyboard: Tab order top to bottom, left to right; inside a tile group the arrow keys move selection, Space/Enter select.

Delete confirm (reuses the existing machinery, unchanged copy): `Popup::DeleteStyle` in `app.rs` builds the prompt from `config_state::delete_confirm_text(name, users)` plus `config_state::config_warning(name)` when `config.json` references the style, shown through `ff_modal` [Delete style (danger) / Keep style (last = Escape/backdrop)]. This phase changes nothing there; the in-editor Delete button only moves into the bottom line above. (Escape/backdrop stays the safe choice.)

## Colour Picker (shared by CONFIG styles and RULES colour actions)

New module `src/skin/colour_picker.rs` exporting `ff_colour_picker(ui, skin, id, &mut Hsva, mode: PickerMode) -> PickerResult` where `PickerMode { alpha: bool, allow_none: bool }`. The two existing entry points in `overlay/widgets.rs` keep their names and `Option<..>` return contract so callers and tests barely change: `colour_swatch(ui, rgba) -> Option<[u8;4]>` (alpha on, no none) and `colour_swatch_rgb(ui, rgb) -> Option<[u8;3]>` (opaque); both now draw a swatch and open the new popup instead of `egui::color_picker::color_edit_button_hsva`. The CONFIG style slots use a third thin wrapper `colour_slot(ui, skin, current: Option<[u8;3]>, seed) -> SlotResult` (allow_none on) driven from the `ff_colour_card` click. The popup frame reuses the `paint_box_behind` logic from `body.rs` (move it to `skin::popup` as `pub fn paint_box_behind` so both can call it).

| Aspect | Contract |
|--------|----------|
| Frame | `box_9slice` art, 8pt margins (as `paint_box_behind`), inner padding 16, popup content width **268pt**, so the popup is 300pt wide (max 40% of the 660pt window; fits the 353pt control column). Painted behind an `egui::Popup` (anchored popup, same mechanism as `ff_dropdown` / `picker_popup`) |
| Placement (Claude's decision) | anchored to the clicked swatch/card: below it, left-aligned to it, flipped above when it would pass the bottom of the work area, clamped so it never leaves the window horizontally (swatches sit at x >= 154, so a 300pt popup always fits in 660). Click outside closes it; one picker open at a time (opening another closes the first via `egui::Popup::close_all`). No dim backdrop, so the preview line and the table stay visible while editing |
| Semantics (Claude's decision) | LIVE. Every change yields an edit immediately (preview and row update). Escape restores the value the picker opened with (one final edit of the opening value) and closes. Click outside, the swatch again, or `Use colour` keeps the current value. No Cancel button. A hex/RGB field edit applies on Enter or focus loss; an invalid entry reverts that field silently |
| No-op guard | unchanged from today: no action is emitted when the unmultiplied result equals the opening value, so merely opening the picker never rewrites a line (`colour_swatch` contract, and `rgba_edit` keeps a 3-token line 3-token while alpha stays 255) |
| Colour state | the picker edits unmultiplied HSVA (`hsva_of`, the WR-04 helper, made `pub(crate)`), kept in egui temp memory keyed by `id` while open so hue survives greys and a transparent colour keeps its RGB |
| Square | 268 x 150pt saturation (x) / brightness (y) at the current hue, 1pt `pal::INPUT_BORDER` border, 10pt ring cursor (white ring, black outline). Drag anywhere in it |
| Hue bar | 268 x 16pt rainbow, 8pt below the square, 4 x 22pt marker; drag |
| Fields | 12pt below the bar, one line (8pt gaps): `Hex` `ff_text_field` 80pt (`#RRGGBB`, accepts 3 or 6 digits with or without `#`), `R` `G` `B` `ff_text_field` 44pt each with 3-char hint-free numeric text (0-255). Labels `regular(14)` `pal::MUTED`. No CMYK, no HSV fields |
| Alpha | only when `mode.alpha` (rule colour actions): one more line 8pt below, `ff_slider` 0-255 step 1 (value text on the right), over a checkerboard strip behind the swatch preview. Styles never show it (opaque, alpha 255 is written by the emitter) |
| Quick picks | one row of 9 `ff_swatch` tiles 24pt, 4pt gaps (= 9 x 24 + 8 x 4 = 248pt; with the None tile 24 + 4 + 248 = 276 > 268, so the None tile sits at the end of the row only if the row has room, otherwise on its own line, left): the Dracula colours `(40,42,54)` bg, `(248,248,242)` fg, `(139,233,253)` cyan, `(80,250,123)` green, `(255,184,108)` orange, `(255,121,198)` pink, `(189,147,249)` purple, `(255,85,85)` red, `(241,250,140)` yellow. Click sets RGB and keeps the current alpha. Tooltip is the colour name; an exact match shows the selected ring |
| None | only when `mode.allow_none` (style Text/Border/Background): a `ff_swatch(None, ..)` 24pt tile, tooltip `No colour (game default)`; picks `value: None` and closes. Rule colour actions have no None: their colour line exists or not (removed with the card's existing remove button), so `mode.allow_none = false` there. Opening an unset slot shows the slot's seed (text/border 248 248 242, background 40 42 54) but emits nothing until the user changes something (Claude's decision; matches today's circular-toggle seeds) |
| Footer | `ff_button("Use colour", 112)` right-aligned, 12pt above it. It is the only button |
| Keyboard | Escape = revert and close; Enter in a field commits it; Tab: Hex, R, G, B, Alpha, quick picks, Use colour; arrows on the square nudge S/B 1% (Shift 10%), on the hue bar 1 deg (Shift 10 deg) |
| Trigger | CONFIG: the `ff_colour_card` (open state shows the 2pt `pal::HEADING` ring (the ring width of `ff_swatch`)). RULES: a 34 x 22pt chip in the colour line replacing the swatch + `R G B A` caption (`rgba_caption` text becomes the tooltip only; no caption, per "not texty") |
| Accessible names | `Text colour`, `Border colour`, `Background colour`, `Hex`, `Red`, `Green`, `Blue`, `Alpha`, `Hue`, `Saturation and brightness` |

RULES: the colour-action cards keep their `ff_field_row` layout and `Value::Rgba` path (`action_controls` -> `rgba_edit`); only `widgets::colour_swatch` is replaced, with alpha on and `had_alpha`/3-token form preserved by `rgba_edit`. Beam and minimap controls in RULES (`colour_combo`, `minimap_control`, `effect_control`) are NOT touched this phase (they are dropdown-based and out of the locked decisions); only reuse of `minimap::` tables is shared.

## Spacing Scale

Phase 30/31 tokens unchanged (multiples of 4): xs 4, sm 8, md 16; lg/xl/2xl/3xl unused except the 24pt `ff_modal` pad.

Exceptions (skin-fixed or art-fixed): table row 34 (`ROW_HEIGHT`), header row 24, preview label 26 (table) / 44 (editor), label column 128 and control column 353 (`LABEL_COL_W` / 517 - 154 - 10), tile 24 with 4pt gaps (332pt, one row of 12 in 353), quick-pick tile 24, swatch card 34 x 110, picker content 268 x 150 and padded width 300, hue bar 16, field widths 80 / 44, button widths 112 / 124 / 128. Off-grid values are skin- or art-fixed and justified: 1pt borders and the 1.5-2pt selection rings are the strokes of `ff_swatch`, `ff_icon_button` and `ff_chip`; 10pt picker cursor ring and the 4 x 22 hue marker are drawing details; 26 and 44pt preview heights fit inside the 34pt row / the editor line; 268 = 300 - 2 x 16. Inherited odd values: 10, 18, 22, 30.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `pal::GROUND` #0A0A09 / `pal::PANEL` #0F0E0D | window ground, picker interior |
| Secondary (30%) | `pal::ROW_EVEN`/`ROW_ODD`/`ROW_HOVER`, `pal::INPUT_FILL`, `pal::INPUT_BORDER` #3E3B34 | table and editor rows, fields, square/bar borders, header rule |
| Accent (10%) | `pal::GOLD` #C8A25A, `pal::HEADING` #E6D3A6 | see list |
| Destructive | `pal::ERROR` #E06252 | Delete style caption only (invalid custom-name outline keeps the existing `INVALID_RED`; unsafe sound file name outline too) |

Style data colours (the 11 `minimap::SWATCHES`, 9 Dracula quick picks, hue gradient, label preview) are content, not UI palette; they appear only in tiles, cards, previews and the picker.

Text: names `pal::VALUE`, editor labels `pal::LABEL`, table header/picker labels `pal::MUTED`, disabled arrows `pal::DISABLED`, editor error line `pal::WARN`.

Accent reserved for: group headings; the expanded-row gold outline; selected-tile rings (`pal::HEADING` via `ff_swatch`/`ff_icon_button` selected look) and the open swatch card ring; the checked state of `ff_check`/`ff_chip`; `INPUT_BORDER_HOT` focus rings. Gold fill is not used on rows or the picker.
