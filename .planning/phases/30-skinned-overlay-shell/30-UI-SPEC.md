# Phase 30 — UI Design Contract

> Visual and interaction contract for the skinned overlay shell. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> This is a Rust egui/eframe desktop overlay, not a web app. There is no shadcn, Tailwind or CSS. "px" below means egui logical points (pt); the design system is the in-repo `src/skin/` module built on extracted PoE2 art. The reference look is `src/bin/ff-proto.rs` (screenshots in `.planning/quick/261016-1de-poe2-prototype-tab-layout-style-editor-a/`). Sources: 30-CONTEXT.md (locked), CLAUDE.md overlay notes, REQUIREMENTS SHELL-01..08, and a grep of `src/overlay/` for captions, flags and confirms.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none (in-repo `src/skin/`, egui 0.3x `Ui`/`Painter` API) |
| Preset | not applicable |
| Component library | `skin::widgets` (`ff_frame`, `ff_header`, `ff_close`, `ff_tabs`, `tab_strip`, `ff_section`, `ff_row`, `ff_check`, `ff_slider`, `ff_dropdown`, `ff_button`, `ff_arrow`, `ff_text_field`, `ff_status`, `ff_scroll_area`, `ff_background`, `apply_style`) |
| Icon library | none shipped; flag icons are painted vector shapes in a new `skin::icons` module (painter primitives, 14pt, no new art files). Minimap icons stay `skin::minimap`. |
| Font | Fontin SmallCaps (`fonts::small_caps`, family `fontin-sc`: headings, labels, tabs, buttons, header title), Fontin Regular (`fonts::regular`, family `fontin`: body, values, status, tooltips). Cinzel stays registered, unused by the shell. Both Fontin faces are the proportional default chain with egui's default fonts as fallback for missing glyphs. |

Art in use (all via `Skin`): `title_bar` (header; slot swappable, see Header), `pages_frame` (nine-slice, `FRAME_MARGINS`), `tab` (3-slice), `button[0..3]` (normal/hover/pressed), `close[0..3]`, `box_9slice` (popups and dropdown lists), `scroll_track`/`scroll_thumb`, `title_underline`, `check_on/off`, `combo_arrow`, `slider_*`, `ferris_bg`.

## Window Geometry (SHELL-01)

| Property | Contract |
|----------|----------|
| Width | 660pt (`const WIDTH`, same as `ff-proto`), clamped to the target work-area width if narrower |
| Height | the full work area (screen minus taskbar) of the target monitor, top to bottom |
| Position | flush to the work area's left edge (honours a left-side taskbar: x = `rcWork.left`) |
| Chrome | borderless (`with_decorations(false)`), always on top, not resizable (`with_resizable(false)`), not movable (no title bar; no drag region anywhere) |
| Re-dock | on EVERY summon: hotkey reveal, tray click, second-launch show request. First open too. Never only once. |
| Target monitor | the monitor the PoE2 window is on (`win::find_game_window` HWND -> `MonitorFromWindow(MONITOR_DEFAULTTONEAREST)`); if the game is not running, the primary monitor (`MonitorFromPoint(0,0, MONITOR_DEFAULTTOPRIMARY)`) |
| Work area source | `GetMonitorInfoW(...).rcWork` of that monitor, in physical pixels. Replaces `SPI_GETWORKAREA` (primary-only bug) in `win::work_area` and `skin::window::primary_work_area_px` (the latter is renamed/generalised to take a monitor; `left_dock_rect` stays a pure, unit-tested function) |
| DPI | scale = `GetDpiForMonitor(MDT_EFFECTIVE_DPI) / 96` of the TARGET monitor (100%-200%+). Physical width = round(660 x scale), physical height = work-area height. Apply with `SetWindowPos` in physical pixels (not egui logical commands) so a move between monitors of different scale cannot mix units; egui then picks up the new `native_pixels_per_point`. Unit-test `left_dock_rect` with a second-monitor origin (non-zero, possibly negative x) and 100/150/200%. |
| Layers (paint order) | 1 `ff_background` (GROUND + Ferris, fixed to window, never scrolls) -> 2 `ff_frame` below the header (`frame_outer.min.y = win.min.y + header_h - 14`) -> 3 header art + title + close -> 4 tabs -> 5 content (clipped to `frame.content`, child `Ui` at `frame.content.shrink2(vec2(10, 8))`) -> 6 bottom bar in `frame.button_bar` -> 7 modal layer |
| Behaviours unchanged | hide when the game takes focus, `Ctrl+Shift+Z` only while PoE2 or ff is foreground, tray Quit as only exit, single instance, in-game `/reloaditemfilter` after Apply, hidden-window state survives (open popup, scroll, tab, edits all kept while hidden) |

Usable content width is about 535pt (660 x 0.504 frame scale -> 52pt stone each side, minus the 10pt content inset). Every legacy RULES/CONFIG row must lay out in 535pt with no horizontal scroll (the old stripe was wider/narrower; check wraps).

## Chrome (SHELL-02, SHELL-03)

Focal points: the selected tab (full-brightness stone, `pal::HEADING` caption) is the primary focal point of the chrome; the Apply button (rightmost in the bottom bar) is the primary action. Nothing else uses accent weight.

### Header

- `ff_header(ui, &skin, header_rect, art, "FerrisFilter")`, `header_rect = (win.min, 660 x header_height(skin, 660))`.
- Title slot: the gold plate at 71.7% of header height, centred. Title "FerrisFilter" in `small_caps(clamp(header_h x 0.215, 14, 30))`, colour `pal::ON_GOLD`, with the 1px light halo exactly as `ff_header` does.
- Custom-art slot: the `art: Option<&TextureHandle>` parameter is the only switch. The shell passes it through ONE constant/function (`shell::header_art(&skin) -> Option<&TextureHandle>`, today `Some(&skin.title_bar)`). When the author's own header PNG lands (deferred), only that function and an asset change. Do NOT bake the plate geometry anywhere else. `None` paints the placeholder plate (existing behaviour).
- Close: `ff_close` round red button, size `clamp(h x 0.3, 20, 34)`, right edge. Click HIDES the stripe (never quits). Tooltip: "Hide (Ctrl+Shift+Z)". Accessible label stays "Close".
- Hover tooltip on the title plate: the loaded filter's full path (replaces the old status-block path line), plus nothing else.

### Tab strip

- `ff_tabs(ui, &skin, tab_strip(&frame), labels, &mut tab)`; the fixed stone-tab layout of the prototype (stones overlap by `TAB_OVERLAP` 0.3, selected stone drawn last at full brightness, caption `pal::HEADING`; hover `pal::LABEL`; inactive `pal::MUTED`; caption shadow `from_black_alpha(220)`).
- Order and labels (source strings are mixed case; Fontin SmallCaps renders them as small caps): `Rules`, `Config`, `Economy`, `About`. Selected index 0 on launch (v0.5 default).
- ` *` marker: label is `apply::tab_label(name, marker)` (existing helper; trailing ` *`). The marker appears on a tab when the OTHER tab has unapplied edits (RULES shows it when CONFIG is dirty and vice versa). ECONOMY and ABOUT never show it and never cause it.
- Tooltip on a marked tab: `apply::OTHER_TAB_DIRTY_TIP` ("Unapplied changes on this tab" — kept verbatim). `ff_tabs` gains an optional `tips: &[Option<&str>]` parameter and attaches `on_hover_text` to each tab's hit response.
- Switching tabs never applies or discards (v0.5). Switching to CONFIG still disarms confirms and refreshes the filter list (existing `picked_tab` code path). Arrow Left/Right on a focused tab moves selection (kept).

### Content area

- Scrolling content sits over the static Ferris background (`ff_background` is painted first and never moves).
- CONFIG, ECONOMY, ABOUT: wrap content in `ff_scroll_area(ui, &skin, id, ...)` (game scrollbar: track 5pt line, 12pt gold thumb, `SCROLLBAR_WIDTH` 14 + 4 gap). Scroll ids are per tab so offsets are kept when switching.
- RULES: keeps its own virtualised list scroll (`virtual_list`/`rule_list`); its scrollbar uses the restyled thin egui scrollbar (`ScrollStyle::thin()`, bar_width 6, colours from the global style below). Swapping it to the game scrollbar is Phase 31.
- Pinned (not scrolling) rows inside RULES: the search row at top; the economy footer row at the bottom of the content rect.
- Rows on `pal::ROW_EVEN`/`ROW_ODD`/`ROW_HOVER` grounds, never an opaque panel, so Ferris shows faintly through.

### RULES tab layout (top to bottom)

1. Search row (as prototype): `ff_text_field` (hint `Search {N} rules, classes, base types…`, N = total rules; this replaces the old "N rules / shown of N" label and the "FILTER" section header) + `ff_button("+ Add rule", 124)`; field width = available - 132.
   - Disabled (dimmed, `Sense::hover`) when `!actions.add_rule`. Tooltip on the button: "Blocks you add are saved with the filter when you press Apply." (replaces the empty-state sentence).
   - A non-empty query shows the existing small "Clear" button inside the field's right edge (unchanged behaviour).
2. Rule list (legacy rows, restyled).
3. Economy footer row (pinned, 34pt, `pal::ROW_EVEN` ground): left label (`regular(15)`, `pal::MUTED`) = `economy_footer_text` string unchanged (`+ N locked rule blocks (economy)` / `No economy section`); right `ff_button` `Remove` (min 84) or `Add economy section` (min 160). Hover tooltip on the label (kept): "Generated from prices.json by SYNC ECONOMY and APPLY. Not editable here." Damaged: label in `pal::ERROR` with the damage message as tooltip. Remove opens the Remove-economy popup (below); Add stages immediately (as v0.5). Both disabled when the root is not ok or a changed-on-disk refusal is pending.
4. The old pinned footer (indicator line, + ADD RULE / RELOAD / OVERWRITE / SYNC / REVERT / APPLY button row, 96pt outcome area, status block with path/state/v0.4 notice) is DELETED from RULES; its content moves as specified in "Bottom bar" and "Status line".

### CONFIG tab layout

Same three sections as v0.5 (FILTER, STYLES, TIERS) inside `ff_scroll_area`, headed with `ff_section(ui, &skin, "Filter" | "Styles" | "Tiers")` (replaces `theme::section_header`). Content widgets stay legacy (restyled globally). The pinned CONFIG footer (revert prompt, indicator line, Apply/Revert/Discard/Cancel/RELOAD/OVERWRITE row) is DELETED; those actions are the shared bottom bar and popups.

### ECONOMY tab (placeholder, Phase 34 owns the real content)

Inside `ff_scroll_area`:
- `ff_section("Economy")`.
- Two `ff_row`s: `League` -> `sync::OVERLAY_LEAGUE` (value `regular(15)`, `pal::VALUE`); `Last sync` -> local `YYYY-MM-DD HH:MM` from `prices.json` modified time, or `Never` when absent.
- Centred `ff_button("Sync economy", 180)`. While running: label `Syncing…`, disabled. Enabled iff `footer_actions.sync` (root ok). This is the ONE home of SYNC ECONOMY (it is not on the bottom bar).
- Sync progress/outcome goes to the status line (`Fetching economy prices…` Info while running; outcome message Ok or Error on finish, naming the league as today).
- No other text. Ferris shows through below. No "Priced items" row (Phase 34).

### ABOUT tab (placeholder)

Inside `ff_scroll_area`, centred: "FerrisFilter" (`small_caps(21)`, `pal::HEADING`), `Version {CARGO_PKG_VERSION}` (`regular(15)`, `pal::MUTED`), one line `A loot-filter editor and overlay for Path of Exile 2` (`regular(15)`, `pal::LABEL`), then `ff_section("Credits")` with three `ff_row`s exactly as the prototype: `Game UI art and font files` -> `© Grinding Gear Games`; `Fontin typeface` -> `exljbris`; `Ferris the crab` -> `Karen Rustad Tölva, public domain`. Pinned at the bottom: the two-line not-affiliated disclaimer (`regular(15)`, `pal::MUTED`, centred, wrapped). No links, no buttons, no repo URL line (Phase 34 may add).

## Bottom Bar and Status Line (SHELL-04)

Placement: inside `frame.button_bar` (the recessed bar), inner = `bar.shrink2(vec2(10, 0))`, right-to-left layout, `item_spacing.x = 8`.

Buttons, visual left to right: **Revert**, **Reload**, **Apply** (each `ff_button`, min width 84, height 34; captions render in small caps). Apply is rightmost.

`ff_button` gains `enabled: bool` (disabled: tint `Color32::from_white_alpha(90)`, caption `pal::DISABLED`, `Sense::hover`, no pressed state) and a `danger: bool` variant (caption `pal::ERROR`) used only inside popups.

| Button | Enabled when (v0.5 `footer_actions`, unchanged logic) | Disabled tooltip / extra tooltip |
|--------|--------------------------------------------------------|----------------------------------|
| Revert | RULES tab: `actions.revert` (dirty rules, not needing reload, filter loaded). CONFIG tab: config state dirty. ECONOMY/ABOUT: disabled. | none. RULES Revert acts immediately (v0.5). CONFIG Revert opens the Discard-config popup (replaces the inline revert confirm). Revert acts on the CURRENT tab only (v0.5). |
| Reload | `actions.reload` (needs reload, no root, damaged markers, load failed, or changed-on-disk). Otherwise shown dimmed. | enabled: `apply::RELOAD_TOOLTIP` ("Discard your edits and load the file from disk."); disabled: "Nothing to reload." |
| Apply | `actions.apply` on RULES; on CONFIG `ctx.apply_enabled`; disabled with the existing reason chain as tooltip (`apply::APPLY_BLOCKED_TOOLTIP`, `config_state::APPLY_BLOCKED_TOOLTIP`, `APPLY_LOAD_ERROR_TIP`, `DAMAGED_MARKERS_MESSAGE`, "Nothing to apply."). One shared APPLY for both tabs (v0.5). Disabled on ECONOMY/ABOUT only if nothing is pending (same rule). | as listed |

Changed-on-disk state: while `needs_reload` (a file changed on disk), the Apply slot is relabelled **Overwrite** (tooltip `apply::OVERWRITE_TOOLTIP`, `danger` caption) and clicking it re-opens the Changed-on-disk popup. This keeps OVERWRITE reachable after the popup was cancelled without a fourth button.

APPLY / OVERWRITE both send `/reloaditemfilter` after a successful write, per the existing reload setting; the outcome (`Reloaded in game`, `Wrote <path>.`, or the reason) goes to the status line.

### Status line

- One row, left of the buttons: `status_rect = (inner.min, (buttons.min.x - 10, inner.max.y))`, drawn by `ff_status(ui, rect, text, kind)`: `regular(15)`, single line (newlines flattened to spaces), cut with "…" at the rect width, shown whole in a hover tooltip ONLY when it was cut (max width 420, same colour). Exists in `skin::widgets` already.
- Colours (`StatusKind::color`): Info `pal::MUTED`; Ok `pal::OK`; Warning `pal::WARN`; Error `pal::ERROR`.
- One message at a time. An event message (Apply/Revert/Reload/Overwrite/Sync outcome, list status such as "Rule added at position N (hidden by the current search)") replaces the previous one and is cleared by the next edit (v0.5 `apply_message = None` behaviour). When there is no event message, the highest-priority STANDING condition shows. Priority, highest first:

| # | Standing / event message | Kind |
|---|--------------------------|------|
| 1 | Missing app root error (`self.root` Err) | Error |
| 2 | Event: Apply/Overwrite/Reload outcome, `REVERTED_MESSAGE`, Sync outcome, list status | Ok (success), Warning (applied but needs a look, reload reason / unknown-style drops), Error (refused / failed) |
| 3 | Grammar gate: `apply::invalid_blocks_message` | Error; clicking the status line jumps to the first blocking rule (expands + scrolls it, clears the query if it hides it; `jump_to` as today). Pointing-hand cursor while a jump target exists. |
| 4 | Filter state: Damaged markers (`DAMAGED_MARKERS_MESSAGE`), `The filter could not be loaded: {msg}. Fix the file and press Reload.` | Error |
| 5 | Sync running: `Fetching economy prices…` | Info |
| 6 | `unknown_styles_message` | Warning; click jumps to the first such rule |
| 7 | v0.4 notice: `v0.4 filter: converted on the next Apply (a .ffbak backup is kept).` | Info |
| 8 | `Absent`: `The filter does not exist yet. Apply creates it once it has rules.` | Info |
| 9 | Default indicator (`apply::indicator`): Unapplied/NeverApplied -> `Filter out of date — press Apply, then reload in-game` (Warning); Applied -> `Filter matches saved rules` (Info) | as stated |

- Wording keeps the exact v0.5 strings wherever they exist (they are test-pinned); only the five new/shortened strings above are new. `NoSection`/`HasSection` state messages ("The filter has no economy section." / "Economy section found.") are no longer shown standing (the RULES economy footer row already says it).
- A multi-message backlog is NOT queued: the hover text is the full text of the one message. (Behaviour change vs the 96pt multi-line outcome area; listed in the verification inventory.)

## Modal Popups (SHELL-05)

One shared component `skin::popup::ff_modal(ctx, &skin, id, title, body, buttons) -> Option<usize>` (built on `egui::Modal` or an `Area` + `Order::Foreground` layer):

| Property | Contract |
|----------|----------|
| Dim | full-window rect `Color32::from_black_alpha(160)` over everything (header and bar included); swallows pointer input to the layers below |
| Box | `skin.box_9slice`, nine-sliced with `Margins::new(8, 8, 8, 8)`, scale 1.0 (same as the dropdown list), centred in the window (horizontally and vertically), fixed width 520pt (never wider than window - 80), height = content; inner padding 24 |
| Title | `small_caps(21)`, `pal::HEADING`, left aligned, then the `title_underline` rule (150 alpha, as `ff_section`) |
| Body | `regular(15)`, `pal::VALUE`, wrapped, left aligned, 12pt below the rule; at most 4 lines before it scrolls |
| Buttons | `ff_button` (game button art, small-caps caption), min width 120, one row, left to right, centred under the body, 8pt gaps, wrap to a second row if they do not fit. Destructive confirm uses `danger` caption `pal::ERROR`. |
| Keyboard | Escape = the Cancel/safe choice (same as clicking it). Click on the dim area = Cancel too (v0.5 quit-confirm behaviour). Tab cycles the buttons; Enter/Space activates the focused one. No button is focused initially. |
| Stacking | one modal at a time. If several are wanted: Quit confirm > Changed-on-disk > the rest. A modal does not close when the stripe is hidden/re-summoned. |
| Accessibility | modal gets a `WidgetInfo` label = title; each button labelled by caption |
| Tooltips | the v0.5 button tooltips are kept on the matching popup buttons |

Popup inventory (button order is left to right; the last button is always the safe dismiss (`Keep editing`, `Keep`, `Stay`; the Quit confirm keeps `Cancel`, locked by CONTEXT)):

| # | Trigger | Title | Body | Buttons |
|---|---------|-------|------|---------|
| 1 | Apply refused: file(s) changed on disk; also the bottom-bar Overwrite slot | File changed on disk | `{file name(s)} changed since ff loaded it.` / `Reload discards your edits. Overwrite replaces the file with them.` | `Reload` (tooltip `RELOAD_TOOLTIP`), `Overwrite` (danger; tooltip `OVERWRITE_TOOLTIP`), `Keep editing` |
| 2 | Pick another filter in CONFIG with unapplied rule edits | Switch filter? | `Unapplied rule changes will be discarded.` / `Switching to {target}.` | `Switch and discard` (danger), `Stay` |
| 3 | Tray Quit with anything unapplied | `apply::QUIT_CONFIRM_TITLE` ("Unapplied changes") | `Apply them before quitting?` | `Apply & quit` (`QUIT_APPLY_LABEL`), `Quit without applying` (danger; tooltip `QUIT_DISCARD_TIP`), `Cancel` |
| 4 | Delete on an expanded rule row | Delete this rule? | `Rule {index}: {name or "Show"/"Hide"}` and, for a Simple-Defences group, `Deletes all {n} blocks of this rule.` | `Delete` (danger), `Keep` |
| 5 | Delete style (CONFIG, custom styles) | Delete style? | `config_view::delete_prompt` text unchanged (rule count + the `config.json` warning line when referenced) | `Delete style` (danger), `Keep style` |
| 6 | Remove on the economy footer row | Remove economy section? | `Your own rules are kept. Add the section back any time.` | `Remove` (danger), `Keep` |
| 7 | Revert on CONFIG with edits | Discard config changes? | `revert_prompt(n)` text unchanged (`Discard N unapplied config changes?`) | `Discard` (danger), `Keep editing` |

The inline confirm frames they replace are deleted: rule row `Delete this rule? / Yes, delete / Keep`, economy `Remove the economy section? / Yes, remove / Keep`, CONFIG delete-style frame, CONFIG switch-filter frame, CONFIG `Discard / Cancel` footer, tray-Quit `egui::Modal` with plain buttons, and the RELOAD/OVERWRITE footer buttons. Their state fields (`confirm_delete`, `confirm_economy_remove`, `delete_armed`, `pending_switch`, `revert_armed`, `quit_confirm`, `changed_on_disk`) are reused as the "popup is open" flags; behaviour on each choice is identical to v0.5 (same `ConfigAction`/`RowAction`/`QuitChoice` dispatch).

## Global Restyle of Legacy Widgets (SHELL-06)

Goal: existing RULES/CONFIG code (egui `Button`, `ComboBox`, `TextEdit`, `Slider`, frames, `widgets::*` wrappers) looks close to the skin with no per-widget rewrites. Mixed look is accepted until Phases 31/33.

1. Install at startup: `skin::install(ctx)` (fonts + `widgets::apply_style` + `Skin::load`) replaces `theme::install`. Keep the returned `Skin` in the app.
2. Extend `skin::widgets::apply_style` (shared with ff-proto) with:
   - Text styles: `Heading` = `small_caps(21)`; `Body` = `regular(15)`; `Button` = `small_caps(17)`; `Small` = `regular(15)` (no smaller text in the shell); `Monospace` = 14 (raw filter lines only). The size set is exactly 14, 15, 17, 21; the skin widgets' hard-coded `regular(16)` (slider value, dropdown, text field) change to `regular(15)` in the same change.
   - `Visuals`: `panel_fill` `pal::GROUND`; `window_fill`/`extreme_bg_color`/`faint_bg_color` `pal::INPUT_FILL`; `widgets.noninteractive/inactive.fg` `pal::LABEL`; `hovered/active.fg` `pal::HEADING`; `inactive.bg_fill` `pal::INPUT_FILL`, stroke 1 `pal::INPUT_BORDER`; `hovered.bg_stroke` `pal::INPUT_BORDER_HOT`; `selection` fill gold alpha 70, stroke `pal::GOLD`; `hyperlink_color` `pal::GOLD`; `warn_fg_color` `pal::WARN`; `error_fg_color` `pal::ERROR`; widget `corner_radius` 1; no widget shadow; popup/tooltip frames use `pal::INPUT_FILL` + `pal::INPUT_BORDER_HOT` stroke.
   - Tooltips: `regular(15)`, `pal::VALUE`, max width 420.
   - Spacing: `item_spacing` (8, 4), `button_padding` (8, 4), `interact_size.y` 28, `scroll = ScrollStyle::thin()` bar_width 6.
3. `overlay::theme` constants are RE-POINTED (values only; no call-site churn; the module itself is deleted in Phase 35):

| `theme::` constant (legacy) | New value |
|-----------------------------|-----------|
| `LABEL_TAN` | `pal::LABEL` |
| `VALUE_TEXT` | `pal::VALUE` |
| `DISABLED_TEXT` | `pal::DISABLED` |
| `TAB_ACTIVE`, `SECTION_CREAM` (text uses) | `pal::HEADING` |
| `WARM_ACCENT_TEXT` | `pal::WARN` (grammar-error icons/text use `pal::ERROR` explicitly) |
| `WARM_ACCENT` (button fill) | `pal::INPUT_FILL` with `pal::INPUT_BORDER_HOT` stroke (no loud fill; danger lives in popups) |
| `ROW_BASE` | `pal::ROW_EVEN` |
| `ROW_ALT` | `pal::ROW_ODD` |
| `HEADER_PLATE` | `pal::PANEL` |
| `ROW_SUMMARY_SIZE` | 15 |
| `section_header(..)` | no longer used by CONFIG (replaced by `ff_section`); remove call sites in the shell, keep fn for Phase 35 deletion |

4. `widgets::circular_toggle`, `slide_switch`, `toggle_chip`, `themed_slider`: recolour via the table above only (track `pal::INPUT_FILL`, on `pal::GOLD`, thumb `pal::HEADING`). `circular_toggle` MAY delegate to `ff_check` (it is the single funnel for ~11 call sites and the game ring art is a drop-in); optional, not required.
5. The old `theme::` stripe window fill, header text, tab drawing, custom title bar and 96pt outcome area are no longer drawn. No Cinzel in the shell.

## Typography

Fontin ships only a Regular and a SmallCaps face (no bold). The two "weights" are therefore Regular (400, `fontin`) and SmallCaps (400, `fontin-sc`, used where the game uses heavier headings).

| Role | Size | Face | Line height |
|------|------|------|-------------|
| Body / status / tooltip / value / secondary / badge / flags (control text, dropdown, slider value, popup body, ABOUT lines; legacy `Body`, `Small`) | 15 | Regular | 1.4 (egui row default) |
| Monospace (raw filter lines only) | 14 | egui monospace | 1.4 |
| Label / button (`ff_row` label, `ff_button`, `Button` text style, "Continue" flag) | 17 | SmallCaps | 1.2 |
| Heading (section, popup title, ABOUT title) | 21 | SmallCaps | 1.2 |

The table is the complete size set (14, 15, 17, 21). Art-derived exceptions, explicitly OUTSIDE the 4-size limit because they scale with the header/tab art (computed, not tokens): header title `clamp(header_h x 0.215, 14, 30)`; tab caption `clamp(tab_h x 0.58, 12, 22)`.
