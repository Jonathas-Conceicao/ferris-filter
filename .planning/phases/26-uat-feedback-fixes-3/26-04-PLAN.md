## Facts found while planning (hypotheses to confirm, not conclusions)

- rule_list.rs ~L304: each rule body is drawn inside `ui.push_id(("rule", row.id, list.epoch), ..)`.
  `ListUi::forget_card_state()` (~L94) bumps `epoch`; app.rs `apply_row_actions` calls it for every
  `AddLine` and `RemoveLine` (WR-07: shifted ordinals must not carry temp state to a neighbour). The
  first Class click on a pending row emits `AddLine`, so the epoch bumps and every egui id under the
  rule changes in the next frame -- the open class group (`CollapsingHeader` in `class_picker`, body.rs
  ~L1188, `default_open(false)`) is then closed.
- Independently, the pending card salts the class picker with `(block, kw, usize::MAX, "pending")`
  inside `push_id((block, kw, "pending"))` (body.rs ~L604/L627), while the real card uses
  `card.salt("class")` = `(id, kw, ordinal, "class")` inside `push_id((id, kw, ordinal))` (~L703) --
  a second reason the open group cannot survive the pending -> real transition.
- Also check: `list.expanded` reset paths in rule_list.rs (~L249-265: expanded row not visible under
  the current query; `last_expanded` change), the row header `row_click`/summary `ui.interact` hit
  areas (~L471, ~L505-519) in case a click falls through to the header, and `BlockId` stability after
  `insert_body_line`.
- body.rs test helpers: `headless_ctx()`, `input(..)`, `frame_of(&ctx, input, &wf, &mut list, classes)`,
  `entries_of(src)`, `first_click_y(..)`; rule_list.rs has its own list harness (~L812-830,
  `show_list`). Class catalogue for tests: see existing Class picker tests in body.rs.
- `PendingRow { block, keyword, op, kind }` (rule_list.rs ~L53, `PartialEq`; `list.pending.retain(|q|
  q != p)` compares the whole struct, so mutating `op` must match by (block, keyword)).
  `pick_condition` (~L497) sets `op` to `Some(EqEq)` for BaseType, None otherwise.
  `pending_card` (~L590) shows the operator only as a label when `p.op.is_some()`.
  `operator_combo(ui, card, list_form)` (~L844) needs a `Card` (real entry); a pending variant must
  build its choices from `grammar::operator_choices(p.keyword, p.op, false)`.
  `pending_first_entry` (~L551) already writes `p.op` (dropping an ordering op on multi-rarity).
- Picker: body.rs ~L445-454: `.default_open(gi == 0)`; `if searching { header = header.open(Some(true)) }`.
