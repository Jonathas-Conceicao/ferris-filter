# Phase 18: Filter as Store & Economy Section - Context

**Gathered:** 2026-10-12
**Status:** Ready for planning
**Mode:** Smart discuss (autonomous, all v0.5 phases discussed upfront)

<domain>
## Phase Boundary

The game-folder `.filter` file becomes the only store for the dynamic filter. `dynamic.json`,
`dynamic_base.json`, the overlay's JSON store and the obsolete CLI flags are removed.

Economy-priced blocks live in one fenced, regenerable section after the general rules. Apply is a
safe in-place write: backup, changed-on-disk guard, and atomic replace. Repo files are found
without relying on the working directory.

Requirements: STORE-01, 03, 04, 05; ECON-01, 03, 04; EDIT-09, 10. This phase is headless: the
library and CLI `apply`. The overlay's new rule list is Phase 19. Between the two phases the
overlay may be temporarily limited, which is acceptable on the milestone branch.

</domain>

<decisions>
## Implementation Decisions

### Economy section
- **Placement:** at the **end of the file**, after all general rules. This is the author's
  design: economy blocks come after the general filter rules.
- **Markers:** FerrisFilter's header-style comment family from Phase 16. A begin and an end
  line, e.g. `#ff:economy-begin` and `#ff:economy-end`, each followed by human-readable text such
  as "generated by FerrisFilter, do not edit". The planner settles the exact text.
- **Refresh:** Apply regenerates everything between the markers from `prices.json`, `tiers.json`
  and `styles.json`, and changes **no byte outside** the markers. Applying again with unchanged
  inputs produces identical bytes.
- **Damaged markers** (missing end, duplicated begin, …) are a hard stop with a clear message.
  Never guess.
- **Add and remove (ECON-04):** headless operations to add a section to a filter that has none
  (a new empty filter or a foreign filter), or remove it. Adding only ever happens on an
  explicit user action, never automatically.

### Migrating the existing dynamic.filter (one time)
- The author's current game-folder `dynamic.filter` was written by v0.4. It has a
  `# GENERATED FROM dynamic.json` header, and its economy section starts at the
  `# alwaysShow.currency` `#====` banner and runs to the end of the file.
- On first load, detect that v0.4 shape and convert it in memory:
  - Wrap the old economy section in the new markers.
  - Turn v0.4's `Show # <name>` rule names into `#ff:name` metadata lines (Phase 16's
    convention), so names survive the change in naming scheme.
  - The general rules otherwise carry over untouched.
- The conversion is written out by the next Apply. It is not a silent rewrite on open.
- `dynamic.json` and `dynamic_base.json` are then dropped. No import is needed, because the
  filter already holds the rules.

### Safe writes
- **Backup:** on the first FerrisFilter write to any given filter, copy it once to
  `<name>.filter.ffbak` beside it. The game lists only `*.filter`, so it ignores this. The backup
  is never overwritten.
- **Changed-on-disk guard (EDIT-09):** remember a content hash at load. Before writing, re-read
  the file. If it changed, refuse and report "changed on disk since it was loaded", with a Reload
  path that discards in-memory edits. Never overwrite.
- **Atomic write:** create the temp file in the destination directory and rename it over the
  target (the game folder is under OneDrive). Retry briefly on sharing violations.
- **No rewrite on open.** A no-op Apply on a foreign file writes nothing, or writes identical
  bytes.

### Locations and paths
- **Default filter:** the game-folder `dynamic.filter`
  (`%USERPROFILE%\OneDrive\Documentos\My Games\Path of Exile 2`, the existing `install`
  default). If it doesn't exist, it starts empty (STORE-03), with an economy section only if the
  user adds one.
- **App root (STORE-05):** one resolver used everywhere, replacing every `current_dir()`-relative
  repo path. Order:
  1. the `FERRISFILTER_HOME` environment variable;
  2. walk up from the exe's directory until `styles.json` (or `config.json`) is found;
  3. the working directory;
  4. otherwise a visible error.

  It must cover `overlay::store`'s default paths, Apply's `relative_to(store_dir)`, and
  `sync_economy_blocking`'s `prices.json` location. This also fixes the v0.4 double-click launch
  blocker.

### CLI (STORE-04)
- `ff-cli apply [--filter <path>]` refreshes the economy section of the given filter (default
  `dynamic.filter`), using the same headless function the overlay will call.
- `--reset`, `--base` and `--store` are **removed**, not deprecated: the project is unreleased.
- `generate`, `install` and `sync` are unchanged.
- Remove `dynamic.json` from `.gitignore` notes, remove `dynamic_base.json` from the repo, and
  update `CLAUDE.md`'s layout table and `CHANGELOG.md` `[Unreleased]`, recording the breaking
  change.

### Claude's Discretion
- Function and module names (`apply_text`/`refresh_economy` suggested), the split of
  `compile::load_inputs` into config/economy parts, the hash choice, the retry policy, and the
  exact marker text.

</decisions>

<code_context>
## Existing Code Insights

### Reusable Assets
- `dynamic::write_filter` (atomic `tempfile::NamedTempFile::new_in` + `persist`) and
  `dynamic::default_destination`.
- The pricer's economy emitters already produce the currency/uniques/gems blocks. They need
  `&StyleSet` (Phase 17) and must stop requiring a whole `Config`.
- `compile::` library API (Phase 11) returns `price_source` as a value.

### Established Patterns
- v0.4 D-02: edits are held in memory, Apply is the single writer, and Revert discards.
- Apply ordering lesson (Phase 14, `3375ad4`): never compile from stale disk state. With the
  filter as the store, Apply becomes one render plus an atomic write, which removes that hazard.

### Integration Points
- `src/dynamic.rs` (seed/reset/base/store code goes away), `src/overlay/store.rs`,
  `src/overlay/apply.rs`, `src/overlay/economy.rs`, `src/cli.rs`/`src/run.rs` (`apply`
  subcommand), and the integration tests that seed `dynamic.json`.

</code_context>
