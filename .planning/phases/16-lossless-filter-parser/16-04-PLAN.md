    - set_enabled(id, false) leaves the block's leading comment / `#ff:` lines untouched

    - replace_block_lines with `"Show"` + `"\tRarity =< Rare"` -> Err(EditError::InvalidBlock { diagnostics }) and document unchanged
    - replace_block_lines with lines forming two blocks, zero blocks, or containing `\n`/`\r` -> Err, document unchanged
    - replace_block_lines on the last block of `Show\n\tRarity Rare` (no final newline) -> new last line has Eol::None; when the new block has more lines, every earlier new line gets the header's Eol
    - set_meta(id, "name", "Exceptional 3 socks") with no metadata -> inserts `#ff:name Exceptional 3 socks` directly above the header with the header's Eol; with an existing `#ff:name old` line -> rewrites only that line, keeping its Eol; meta_get returns the new value
    - set_meta with key `bad key` or a value containing a newline -> Err(EditError::InvalidMeta)
    - after any edit, every other block's id still resolves via document.block(id) to the block with the same header text
    - unknown id -> Err(EditError::UnknownBlock)
  </behavior>
  <action>
    Create `src/filter/edit.rs` (declare `mod edit;` in mod.rs and re-export `EditError`). `pub enum
    EditError` deriving `thiserror::Error` + Debug with variants `UnknownBlock`, `CannotEnable {
    reasons: Vec<FilterDiagnostic> }`, `InvalidBlock { diagnostics: Vec<FilterDiagnostic> }`
    (diagnostic line numbers relative to the replacement, 1-based), `NotOneBlock`, `EmbeddedNewline`,
    `InvalidMeta(String)`. All methods are `impl Document` in edit.rs, return `Result<(), EditError>`,
    and on Err leave the Document exactly as before (validate first, mutate after).

    `pub fn set_enabled(&mut self, id: BlockId, enabled: bool)`: per D-08, disabling inserts `#` at
    byte 0 of every line in `block.owned()` (header through last body line, including interior
    blank/comment lines); enabling requires `can_enable()` (else CannotEnable with the Invalid reasons,
    D-09) and removes exactly the first `#` char of each owned line (`uncomment_once` from
    disabled.rs gives the slice). Line terminators are never touched.

    `pub fn replace_block_lines(&mut self, id: BlockId, new_lines: Vec<String>)`: reject any string
    containing `\n` or `\r` (EmbeddedNewline). Build candidate `Line`s: each gets the header line's
    Eol, except when the block's old last owned line was the document's final line with Eol::None —
    then the new last line gets Eol::None. Classify the candidate lines in isolation with the plan 03
    builder: must yield exactly one Block and nothing else (NotOneBlock otherwise); if it is enabled
    and any Error diagnostic exists, InvalidBlock (D-10). A disabled candidate is accepted (its reasons
    become Info diagnostics). Only then splice the candidate into `lines` replacing `owned()`, keeping
    the leading comment lines untouched, and keep the same BlockId.

    `pub fn set_meta(&mut self, id: BlockId, key: &str, value: &str)`: key must match
    `[A-Za-z0-9_-]+`, value must not contain `\n`/`\r` (InvalidMeta). If the leading run has a line
    whose `parse_ff_line` key equals `key`, replace that line's text with `#ff:{key} {value}` keeping
    its Eol; otherwise insert a new line `#ff:{key} {value}` immediately above the header with the
    header's Eol (it becomes the last line of the leading run). This is the exact writer form
    Phases 18-20 use (D-05).

    Re-derivation after a successful edit: re-classify only the edited block's span (leading run +
    owned) with the plan 03 builder, reuse the existing BlockId, replace that block's diagnostics in
    the Document (drop old ones whose line falls in the old span, add new ones), and shift the line
    ranges / indices of all later items and diagnostics by the line-count delta. No other item is
    rebuilt. If a partial re-derive is impractical, an acceptable alternative is a full rebuild that
    maps old BlockIds to new blocks by position-of-header (every block other than the edited one keeps
    its id); record the choice in the SUMMARY. Either way, unit tests must show other ids survive.

    Unit tests in edit.rs implementing every behavior bullet above.

|----------|-------------|
| caller (future overlay editor) -> edit API | Edit requests with arbitrary strings for lines and metadata |
| user filter file -> parser | Truncated / garbage / hostile files |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-16-12 | Tampering | `replace_block_lines` injecting extra blocks or lines via `\n`/`\r` | mitigate | Reject embedded newlines (EmbeddedNewline); candidate must classify as exactly one block (NotOneBlock) |
| T-16-13 | Tampering | edit producing an invalid enabled block that the game rejects | mitigate | Validate candidate before mutation; Error diagnostics -> InvalidBlock; enabling Invalid disabled blocks -> CannotEnable (D-09, D-10) |
| T-16-14 | Tampering | `set_meta` key/value injecting lines | mitigate | Key restricted to `[A-Za-z0-9_-]+`, value newline-free (InvalidMeta) |
| T-16-15 | Denial of Service | panic on truncated/garbage input | mitigate | `parse_never_panics_on_prefixes` deterministic sweep over the 258 KB fixture and garbage inputs |
| T-16-16 | Repudiation | edits silently altering other blocks | mitigate | Byte prefix/suffix equality tests on the real fixture; BlockId stability test |
| T-16-SC | Tampering | cargo installs | accept | No dependencies added |
</threat_model>
