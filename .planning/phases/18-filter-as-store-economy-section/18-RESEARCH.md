### Locked Decisions
- **Placement:** economy section at the **end of the file**, after all general rules.
- **Markers:** FerrisFilter's `#ff:` comment family from Phase 16. A begin and an end line, e.g. `#ff:economy-begin` and `#ff:economy-end`, each followed by human-readable text such as "generated by FerrisFilter, do not edit". Planner settles exact text.

- **Damaged markers** (missing end, duplicated begin, ...) are a hard stop with a clear message. Never guess.
- **Add and remove (ECON-04):** headless operations to add a section to a filter that has none (new empty filter or foreign filter), or remove it. Adding only on an explicit user action, never automatically.

## Summary

The work is mostly **deletion plus three small, well-isolated pure components**. The v0.4 dynamic pipeline is `dynamic.json` (a full `Config`) -> `compile_store` -> `emitter::generate_as` -> `write_filter`. In v0.5 the filter text itself is the store, so Apply collapses to: read file bytes -> (migrate v0.4 in memory) -> splice a regenerated economy body between two marker lines -> guarded atomic write. The economy emitters (`emit_currency_sections`, `emit_unique_sections`, src/emitter.rs:429, :501) already need only a `&StyleSet` (they read `config.styles` and nothing else), so extracting them is a signature change, not a redesign. `generate_as` must keep calling the same code in the same order into the same buffer so `seed-universal.filter` stays byte-identical.

Three decisions shape the plan. (1) **Do all text surgery on text, not through the Phase 16 edit API.** `Document::{set_enabled, replace_block_lines, set_meta}` are strictly block-scoped (src/filter/edit.rs) and refuse any edit that changes the block count; there is no "replace a line range" operation. Use `filter::parse` only to read lines/`ff_marker()` and to resolve blocks for `#ff:name` insertion during migration; do the marker splice with a small pure function over the line list. (2) **Compare full bytes instead of hashing.** Files are 50-260 KB; keeping the loaded `Vec<u8>` and comparing equal to a fresh read is simpler, has no collision or version-stability concern, and needs no new dependency. (3) **The overlay must keep compiling but loses its rule list.** `overlay/app.rs` is wired to `store::load/save` and `dynamic::compile_store`; `store.rs` is deleted, Apply is re-pointed at the new headless function, and the rule list area shows a "rule list returns in Phase 19" notice. `overlay/edit.rs`, `rule_editor.rs`, `view_model.rs` (Config-rule based, 1439/1326/652 lines) stay untouched for Phase 19 to delete or reuse.

**Primary recommendation:** Add `src/paths.rs` (AppRoot), `src/section.rs` (markers + v0.4 migration, pure text), `src/safe_write.rs` (guard + backup + atomic retry), split `compile::load_inputs` and `emitter::generate_as` at the economy boundary, rewrite `dynamic.rs` as `apply_text` / `LoadedFilter` / `apply_file`, then delete the JSON store and rewrite the CLI `apply`. Verify against a committed copy of the author's real v0.4 `dynamic.filter`.

### Pattern 1: Economy split without changing `generate`
**What:** Extract the two economy emitters behind one entry that takes `&StyleSet` and the priced data. `generate_as` keeps its order: header, rules, then the same helper writing into the same `out` buffer.
**Key facts (verified):** `emit_currency_sections(out, config, blocks)` uses `config` only for `style_for_tier(&config.styles, ...)` (src/emitter.rs:429-498); `emit_unique_sections` likewise (:501-557). Both do a trailing-blank trim on the shared buffer (`if out.ends_with("\n\n") { out.pop(); }`); the unique section assumes the currency section already trimmed. Keep them together in one function so that coupling stays internal.

    emit_unique_sections(&mut out, styles, &priced.unique_blocks)?;

### Pattern 3: Marker section as a pure text operation
**Marker layout (recommended exact text).** Key-only `#ff:` lines recognised by `meta::parse_ff_line` (src/filter/meta.rs:14; tests already assert `#ff:economy-begin` / `#ff:economy-end` parse as key-only, :42-47):
```
#ff:economy-begin
# FerrisFilter economy section: generated from prices.json, tiers.json and styles.json.
# Do not edit between the markers; Apply regenerates everything in here.
<blank>
#============================================================
# alwaysShow.currency ... (exact current output of generate_economy)
...
<last block's final action line>
<blank>
#ff:economy-end
```
- The blank line after the begin descriptor and before the end marker is **load-bearing**: the parser attaches a contiguous comment run directly above a header to that block's `leading()` (src/filter/parse.rs:70-76, "maximal run of comment lines directly above `header`"), and a comment directly after a body may be absorbed into the block. Blanks keep both markers in `Item::Trivia`. Test it: parse the produced text and assert both marker lines fall in trivia and that block count equals the pre-section block count plus the economy block count.
- Define the **managed body** as the lines strictly between the begin-marker line and the end-marker line. Markers themselves and their descriptors are never rewritten by Refresh (satisfies "no byte outside the markers" literally and makes the section's wording stable). `add` writes markers + descriptors + body; `remove` deletes begin..end inclusive plus the single blank line `add` put before the begin marker (so add-then-remove returns the original bytes -- make that a property test).
- **EOL:** new lines use the begin-marker line's `Eol` for refresh; for `add`, use the eol of the last terminated line of the file (LF if the file is empty). If the last line has no terminator, add one (using that same eol) -- the only byte "outside" touched, and only on an explicit add. Lines handed to the splice must contain no `\r`/`\n`.
- **BOM:** serialize via `Document` (`has_bom` preserved) or splice on the `Vec<Line>` and re-emit with the same BOM logic; do not use string search on raw text.
- **Validation before any change (`section::find`)** returns `Result<Option<SectionSpan{begin_line, end_line}>, SectionError>` with typed errors, each naming 1-based line numbers: `EndWithoutBegin`, `BeginWithoutEnd`, `EndBeforeBegin`, `DuplicateBegin{lines}`, `DuplicateEnd{lines}`, `MarkerInsideBlock{line}` (a marker line that the parser placed inside a block's owned range, i.e. between header and last body line -- refreshing would corrupt the block). Count markers by `line.ff_marker().map(|(k,_)| k)`; ignore the value part, so `#ff:economy-begin extra text` is still a marker.
- `refresh` on a text with **no** section returns `SectionError::NoSection` (not a silent add) -- the CLI turns it into "no economy section; use --add-economy".

### Pattern 5: Safe write
```rust
// safe_write.rs (shape)
pub enum WriteOutcome { Unchanged, Written { backup_created: bool } }
pub enum WriteError { ChangedOnDisk{path}, DestinationMissing{path}, Backup{..}, Io{path, source}, ... }

pub fn write_guarded(path: &Path, loaded_disk: Option<&[u8]>, new_bytes: &[u8])
    -> Result<WriteOutcome, WriteError>
```
Order of operations (each step's failure leaves the target untouched):
1. `dest_dir = path.parent()`; must `is_dir()` (do not create; matches today's `DestinationMissing` guard and the install guard).
2. Re-read current disk state: `Ok(bytes)` / `NotFound` -> `None`. Compare to `loaded_disk`: `Some(a)` vs `Some(b)` equal bytes, or both `None`. Any difference (including file appeared / vanished) -> `ChangedOnDisk`. Message: "`<path>` changed on disk since it was loaded; nothing was written. Reload to pick up the new version (this discards your unsaved changes)."
3. `if loaded_disk == Some(new_bytes)` -> `Unchanged` (no temp, no backup, no touching mtime). Do this *after* the guard so a changed-on-disk file is still reported.
4. Backup: if the file existed (`loaded_disk.is_some()`), `OpenOptions::new().write(true).create_new(true).open("<name>.filter.ffbak")` (`path.with_file_name(format!("{}.ffbak", file_name))`) and write `loaded_disk` bytes. `AlreadyExists` => backup already taken, fine, never overwrite. Writing the guarded in-memory bytes (not `fs::copy`) avoids a copy of bytes the guard has not seen. Any other backup error => abort before writing the filter (a failed backup must stop the write). Do not create a backup for a file that did not exist.
5. Temp in `dest_dir` (`NamedTempFile::new_in`), write all, `flush`, then `persist` with retry: on `Err(PersistError{error, file})`, if `error.raw_os_error()` is `Some(32)` (ERROR_SHARING_VIOLATION) or `Some(5)` (ERROR_ACCESS_DENIED) retry with the returned `file` after short sleeps (recommended ~5 attempts: 50, 100, 200, 400, 800 ms, about 1.5 s total); any other error or exhaustion -> `Io` error that names the path and tells the user the file may be open (game/OneDrive). Do not retry `ChangedOnDisk`.
6. Residual TOCTOU window between step 2 and the rename cannot be closed without OS locking; document it as accepted (the guard exists to catch edits made by other tools/sessions, minutes later, not races within milliseconds).
- Windows semantics: `MoveFileExW(.., MOVEFILE_REPLACE_EXISTING)` replaces the destination unless it is open without `FILE_SHARE_DELETE` (fails with 5 or 32) -- standard behaviour [CITED: learn.microsoft.com MoveFileExW]; whether PoE2 or the OneDrive sync client hold such a handle on `dynamic.filter` is not testable here [ASSUMED: transient at most]. Retrying a read-only target wastes ~1.5 s before failing; acceptable.
- Temp file lands in the OneDrive folder briefly with a `.tmp*` name (the game lists only `*.filter` [per CONTEXT, not independently verified]); the existing `write_filter` already does this.
- Unit-testable without Windows specifics: inject the persist step behind a closure/trait (`fn persist(&mut self, NamedTempFile, &Path)`) to simulate N sharing violations then success, and permanent failure.

### Pattern 6: App root
```rust
// paths.rs -- pure core + thin wrapper
pub fn resolve_from(env: Option<&OsStr>, exe_dir: Option<&Path>, cwd: Option<&Path>)
    -> Result<PathBuf, RootError>;
pub fn app_root() -> Result<PathBuf, RootError> { resolve_from(var_os("FERRISFILTER_HOME"), current_exe().parent(), current_dir().ok()) }
```
- Order exactly as CONTEXT. Step 1: if set (and non-empty) it **must** be an existing directory, else `RootError::HomeNotADirectory` (an explicit override that does not exist should not silently fall through). Step 2: starting at exe dir, check each ancestor for `styles.json` or `config.json`; first hit wins. Step 3: cwd only if it contains one of the two files (otherwise step 4 is unreachable). Step 4: error listing what was tried.
- **Test-isolation hazard (important):** integration tests spawn `ferrisfilter` with `.current_dir(tempdir)`. The exe lives under the Cargo target dir; with the default in-repo `target/`, walk-up (step 2) finds the repo root's `styles.json` *before* the temp cwd (step 3), so a hermetic test would silently compile against repo-root files. Every CLI test that runs `apply` must set `.env("FERRISFILTER_HOME", dir)`. With `CARGO_TARGET_DIR` under `%TEMP%` walk-up fails and cwd would be used, so the bug would only show on a default checkout -- exactly the kind of latent failure to guard: add one test that spawns the binary with a *different* cwd and `FERRISFILTER_HOME` and asserts the home wins.
- Scope: `current_dir()` appears once in `src/` (`overlay/store.rs:94`, `default_paths`). Other cwd-relative uses are bare relative names, not `current_dir()` calls: `InputPaths::conventional()` (run.rs `cmd_generate`/`cmd_apply`), `sync::cmd_sync` passes `Path::new(".")` (src/sync/mod.rs:23), `install` uses a bare `universal.filter` default, `app.rs:~474` derives the sync dir from `store_path.parent()`. Recommended scope: resolver used by `apply` (CLI), the overlay (store dir replacement, sync dir, Apply inputs), and `ff`'s startup; **`generate`, `install`, `sync` stay cwd-relative** (CONTEXT: unchanged). Flag the asymmetry in CLAUDE.md: `sync` run from another directory writes `prices.json` there, while `apply` reads it from the app root.
- Both `overlay::launch` and `run::cmd_apply` call `app_root()` once and pass `InputPaths::relative_to(&root)`; `launch` should surface a root error visibly (the GUI-subsystem release build has no console) -- show it in the stripe status line, never `expect`/panic (existing `tray::build(...).expect` is a precedent to avoid, not copy).

### Anti-Patterns to Avoid
- **Writing through `Document::replace_block_lines` for a multi-block section.** It requires exactly one resulting block and refuses otherwise (`NotOneBlock`); using it for the section would fail by design.
- **Searching raw text for `#ff:economy-begin`** with `str::find`: matches inside a block body, a disabled (`# `-prefixed) line, or a value. Use `Line::ff_marker()` per line and check trivia/leading placement.
- **Guessing on damaged markers** (e.g. treating a missing end as EOF). Hard stop, message with line numbers.
- **Auto-adding a section on Apply.** Only `Op::Add` (explicit) may create one; `Op::Refresh` on a section-less file reports `NoSection` and writes nothing.
- **Letting `PriceSource::Absent` wipe the section.** `load_inputs` returns `Absent` when neither `prices.json` nor `prices-fallback.json` exists; `generate_economy` would then emit only the banner. Refresh must refuse (`EconomyUnavailable`) rather than replace real blocks with an empty body.
- **Calling `canonicalize()` on the root/paths:** on Windows it yields `\\?\` verbatim paths that change rendered error messages and can confuse string-based `loader` APIs (`path_str`).

## Common Pitfalls

### Pitfall 1: `generate` bytes drift
**What goes wrong:** Refactoring the economy emitters changes whitespace (the trim-last-blank logic is order-sensitive), breaking `artifact_guard`/`generate_snapshot`.
**How to avoid:** change signatures only (`config: &Config` -> `styles: &StyleSet`), do not restructure buffers; run `cargo test --test cli_generate` after each step; `git diff --stat tests/fixtures/seed-universal.filter tests/snapshots` must stay empty.
**Warning signs:** snapshot diff, `artifact_guard` failure.

### Pitfall 2: Markers swallowed by the parser
**What goes wrong:** A marker adjacent to a block becomes that block's `leading()` comment, or the end marker is absorbed into the last block's body, so Phase 19 shows marker lines as part of a rule and Phase 16 edits could rewrite them.
**How to avoid:** blank line before the end marker and after the begin descriptors (Pattern 3); a unit test parsing the emitted section and asserting marker lines are in `Item::Trivia`.

### Pitfall 3: Hermetic CLI tests silently using repo files
**What goes wrong:** exe walk-up (resolver step 2) finds the repo `styles.json` ahead of the test's temp cwd. Tests pass for the wrong reason.
**How to avoid:** `FERRISFILTER_HOME` in every spawned-binary test; a dedicated precedence test; keep `[VERIFIED]` assertion that fixtures differ from repo root (mutate a style in the temp copy and assert the output changed -- the pattern Phase 17 used).

### Pitfall 4: Non-idempotent refresh
**What goes wrong:** Apply twice yields different bytes (trailing newline growth, eol change, blank-line accumulation).
**How to avoid:** body always ends with exactly one `\n` (before conversion to the section's eol); lines spliced by index, never by string search; property test `refresh(refresh(x)) == refresh(x)` on LF, CRLF, no-final-newline, BOM, and on a section with hand-edited garbage between markers.

### Pitfall 5: Migration turns derived labels into names
**What goes wrong:** `Show # rule 4` becomes `#ff:name rule 4`; the unnamed rule now appears named, and a later reorder renumbers nothing but the stale label lies.
**How to avoid:** skip `^rule \d+$`. Residual risk: a rule the user literally named "rule N" loses its name; accepted and documented (v0.4 could not distinguish them either).

### Pitfall 6: Name conversion touches the economy range
**What goes wrong:** economy headers (`Show # Currency S`) get `#ff:name` lines, inflating the "locked" section and making refresh non-idempotent against the old body.
**How to avoid:** convert only blocks whose header line < banner line.

### Pitfall 7: Windows sharing violations and OneDrive
**What goes wrong:** the replace fails with os error 5/32 while OneDrive or the game briefly holds the file, leaving an orphan `.tmp*` file in the game folder.
**How to avoid:** retry with the returned temp file; if finally failing, `NamedTempFile` is dropped and deletes itself (verify in the retry test that the temp file is gone). Error text mentions OneDrive/game as likely holders.

### Pitfall 8: Guard comparing against a migrated/edited buffer
**What goes wrong:** recording `disk` after migration makes the guard compare the wrong baseline, so a no-op Apply on a v0.4 file looks unchanged and nothing is written (migration never lands), or the backup stores migrated bytes.
**How to avoid:** `disk` is always the exact bytes read from the file; migration and refresh only change the *working* text.

### Pitfall 9: Absent file + plain Apply
**What goes wrong:** a typo'd `--filter` path creates a new file.
**How to avoid:** `Op::Refresh` on an absent file reports "not found; nothing written (use --add-economy to create it)". Creating a file only via `Op::Add` and only when the destination directory exists.

### Pitfall 10: Non-UTF-8 foreign filters
`filter::parse` returns `LoadError::InvalidUtf8` (src/filter/mod.rs:36). Apply must refuse with a clear message (never lossy-convert), consistent with Phase 16's contract.

### Pitfall 11: Windows `std::env::current_exe()` quirks
Can return a path through a symlink/junction or a `\\?\` prefix. Walk-up uses `Path::parent()` only (no canonicalize); `exists()` checks on `styles.json` are enough.

### Applicable ASVS Categories

| ASVS Category | Applies | Standard Control |

### Known Threat Patterns

| Pattern | STRIDE | Standard Mitigation |
|---------|--------|---------------------|
| Data loss by overwriting an externally edited filter | Tampering | Changed-on-disk guard + first-write backup |
| Partial write observed by the game | Tampering | Temp file in destination dir + `persist` |
| Marker injection through block/category names into the generated body (e.g. a name containing `#ff:economy-end`) | Tampering | Generated body comes from `prices.json`/`mapping.json` names emitted inside quoted strings and `# --- X ---` comments; add a test that the generated body contains no line whose `ff_marker()` is `economy-*`, and make `refresh` re-run `section::find` on the result and assert exactly one span |
| Malicious `FERRISFILTER_HOME` | Spoofing | Local env var controlled by the same user; only used to find JSON inputs |
| Orphaned temp files in OneDrive on failure | Info/DoS | `NamedTempFile` drop-cleanup; tested |
