  <action>
Extend `tests/cli_generate.rs` (Approach A from interfaces) with THREE tests. All three MUST
normalize `\r\n` → `\n` on every string read from disk before comparing/snapshotting, because the
working-tree `universal.filter` is CRLF on Windows while the generator emits LF (RESEARCH Pitfall 1
— this is critical or tests spuriously fail on Windows).

Helper:
```rust
fn normalize(s: &str) -> String { s.replace("\r\n", "\n") }
```

1. **`generate_snapshot`**: run the binary `generate --output <tmp.filter>` in a temp working dir
   that contains copies of config.json, currency.json, tiers.json (copy them from CARGO_MANIFEST_DIR,
   or run in a temp dir with those files present). Read the produced file, `normalize`, then
   `insta::assert_snapshot!("generate_snapshot", normalized);`. (Alternatively run with the default
   output into a temp cwd. Do NOT write into the repo-root universal.filter from the test — keep the
   committed artifact untouched so the .snap and the artifact stay independent, D-06.)

2. **`artifact_guard`**: generate the filter (same mechanism → a temp file), read BOTH the generated
   temp file AND the committed repo-root `universal.filter` (via
   `concat!(env!("CARGO_MANIFEST_DIR"), "/universal.filter")`), `normalize` both, and
   `assert_eq!(gen_lf, committed_lf, "committed universal.filter drifted from generator — run `ferrisfilter generate` and commit")`.

3. **`generate_is_deterministic`**: run generate twice (two temp outputs), normalize both, assert
   they are byte-identical.

Generate the snapshot oracle: `INSTA_UPDATE=new cargo test --test cli_generate` then accept via
`cargo insta accept` (or `cargo insta test --accept`). If cargo-insta CLI is unavailable, use
`INSTA_UPDATE=always cargo test --test cli_generate` to write the .snap directly. COMMIT
`tests/snapshots/cli_generate__generate_snapshot.snap`. Verify the .snap body is LF (insta
normalizes snap files to LF). Re-run `cargo test` with no INSTA_UPDATE to confirm all three pass
against the committed snapshot.
  </action>
