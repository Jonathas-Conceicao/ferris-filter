Key existing contracts (from src/filter, verified in research):
- `Document { bom, lines: Vec<Line>, diagnostics, items: Vec<Item>, next_id: u64 }`; `parse::build(&[Line], &mut u64) -> (Vec<Item>, Vec<FilterDiagnostic>)` assigns fresh ids from the counter.
- `Block::{id, keyword, is_enabled, can_enable, disabled_state, leading, header_line, owned, span, body, has_continue}`; `span()` = leading comments + owned lines, 0-based half-open. Diagnostics are 1-based lines.
- `BodyLine { line, keyword: Option<&'static Keyword>, tokens: Option<TokenizedLine> }`; for a disabled block token ranges are relative to the text after the line's first `#`.
- `TokenizedLine { indent, keyword, operator, values, comment }` (byte ranges).
- `Document::commit` (edit.rs) remaps ids BY POSITION and refuses block-count changes, so it must NOT be reused for structural ops (research Pitfall 1).
- `replace_block_lines(id, Vec<String>)` validates the candidate in isolation (exactly one block; enabled candidates reject Error AND Warning diagnostics, D-11), allows a different line count, then commits. It is the right primitive for keyword/Continue edits.
- `fresh_eol(header)` gives the terminator for created lines. `Line::new(text, eol)` is `pub(crate)`.
- `section::find(&Document) -> Result<Option<SectionSpan{begin,end}>, SectionError>`; economy blocks are those with `begin < header_line() < end`. `lead_start` never attaches a marker line to a block.

    run `parse::build` with a scratch counter; require the number of blocks == `ids.len()`; require that
    each rebuilt block's owned-line texts equal `expected[i]` (the owned texts the caller predicts,
    in new order), else `EditError::WouldReattributeLines`; assign `Some(id)` verbatim and allocate

    - `append_rule(&mut self, lines: Vec<String>) -> Result<BlockId, EditError>`: rejects embedded
      CR/LF (`EmbeddedNewline`); validates `lines` in isolation like `replace_block_lines` (exactly one
      enabled block covering every line, no Error/Warning; else `NotOneBlock`/`InvalidBlock`).
      Insertion point: with an economy section, the first line of the blank run directly above the
      begin marker (or the begin marker line when there is none); otherwise end of file. Ensure a blank
      line separates the new header from any preceding non-blank line, and (economy case) a blank line
      separates it from the begin marker. An unterminated final line gets the document EOL first.
      Created lines use `fresh_eol` of the nearest terminated line (LF for an empty document). New id
      from `next_id`.

    - `duplicate_block(&mut self, id) -> Result<BlockId, EditError>`: inserts a verbatim copy of the
      source `span()` lines directly after the source unit, preceded by one blank line when the source
      unit has no trailing blank line, and followed by the source's own trailing blank run shape
      (one blank line) when more content follows. Fresh id for the copy. Does NOT rename (`(copy)` is
      overlay policy, plan 19-04).
    - `move_neighbour(&self, id, up: bool) -> Result<Option<BlockId>, EditError>`: the adjacent block
      in that direction, or `None` when there is none, when it is an economy block, or when an economy
      marker line lies between the two units.
    - `move_block(&mut self, id, up: bool) -> Result<(), EditError>`: `NoNeighbour` when
      `move_neighbour` is `None`; otherwise swap the two units in place, leaving any lines between them
      (stray comments, imports, opaque lines) where they are, so the op is its own inverse. If one
      unit's last line is the file's unterminated last line, the line that becomes last after the swap
      gets `Eol::None` and the line that stops being last gets the document EOL.
