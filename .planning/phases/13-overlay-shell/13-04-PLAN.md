<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| filesystem → process | `dynamic.json` is read at startup. It is locally authored (by Phase 12's seed from the committed template, or by the user's own hand edits), but it can be malformed. |
| process → filesystem | This phase performs exactly one write: `ensure_store` seeding `dynamic.json` from the committed template when it is absent. No filter is compiled or written (D-20). |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-13-13 | Denial of Service (local) | Malformed or hand-edited `dynamic.json` read at startup | mitigate | `store::load` returns `Result<_, String>` built on Phase 12's `serde_path_to_error` load path; the stripe renders the field-path message instead of panicking. Enforced by the `unwrap`/`expect` grep criterion and a malformed-store unit test. |
| T-13-14 | Tampering | User's existing rule store | mitigate | Only `ensure_store` is called, which never overwrites an existing store (proven by its Phase 12 test `ensure_store_never_overwrites_an_existing_store`). `reset_store`, `compile_store` and `write_filter` are grep-forbidden in `src/overlay/`. |
| T-13-15 | Tampering | The `universal.filter` oracle | mitigate | This plan touches no emitter, pricer or config path; every task re-asserts `cargo test` green with an empty `git status` over `tests/fixtures` and `tests/snapshots`. |
| T-13-16 | Information Disclosure | Overlay content rendered on a streamed/screenshotted screen | accept | The stripe shows only the user's own filter policy — no credentials, no paths (D-19 bans path chrome), no personal data. |
| T-13-17 | Spoofing | Bundled font asset provenance | mitigate | `assets/Cinzel-OFL.txt` ships with the font and `assets/ASSETS.md` records source and license; the OFL text is read before commit (RESEARCH A3). |
</threat_model>
