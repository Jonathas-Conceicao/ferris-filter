<objective>
Wire named styles into the working model and the single Apply path: rows know whether their
`#ff:style` names a known, unknown or unchecked style; `ApplyStyle`/`RemoveStyle` RowActions; the
Apply path rewrites styled rules from a freshly read `styles.json` on a clone of the document and
reports what it did; a changed `styles.json` counts as unapplied changes. Also loads the class
catalogue from `config.json` for the class picker (20-07).

Purpose: EDIT-06 (apply a named style, sets the rule's style actions) and STYLE-03 (rule remembers
its style via a comment tag; actions update on the next Apply after the style changes). CONTEXT
"Styles on rules" decisions are implemented exactly: tag in the metadata comment run, style's
Show/Hide overrides, rewrite on Apply when the name is known, hand edits overwritten, removing the
tag leaves the style, unknown names reported and untouched.

Decisions recorded here (from 20-RESEARCH open questions / assumptions, autonomous run):
- D-A1: disabled styled rules are not rewritten; the first Apply after enabling rewrites them.
- D-Q5: `styles.json` is read at overlay start, on RELOAD, at every Apply, and whenever its
  modification time changes (polled at most every 2 s while the stripe runs).
- D-Q6: style names failing `styled::style_name_ok` are refused at ApplyStyle.
- D-STYLES-UNAVAILABLE (Pitfall 7): when `styles.json` cannot be read, rows with a tag are
  `StyleState::Unchecked` (no unknown flag, no lock), and Apply is refused with the load error
  only if at least one enabled rule carries a `#ff:style` tag; otherwise Apply proceeds unchanged.
  (Research recommended always refusing; narrowed so an unrelated styles.json typo never blocks
  saving an unstyled filter. styles.json is the root marker, so it normally exists.)
- `config.json` failing to load degrades the class picker to the generic chip list (20-07) and is
  shown once in the list status; it never blocks editing.
Output: changes to `rules.rs`, `apply.rs`, `app.rs`, and the minimal `rule_list.rs` switch from
`style_tag` to `style`.
</objective>
